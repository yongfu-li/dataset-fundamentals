    Key Differences Across Domain Pipelines

    1. Medical Imaging: Data consists of continuous 16-bit radiodensity measurements (Hounsfield Units). Arbitrary image clamping into 8-bit PNGs permanently erases soft-tissue or bone contrast, invalidating tumor annotations.
    2. Autonomous Vehicles: Annotations live in metric Euclidean 3D space (\(\mathbb{R}^3\)). Object boundaries require 7 degrees of freedom, combining 3D spatial extents with yaw rotation angles aligned across sparse LiDAR returns.
    3. Legal Text Discovery: Documents span hundreds of pages with complex nested conditionals. Annotators must identify non-contiguous clause spans where trailing punctuation differences must not penalize legal semantic validity.

    2. Mathematical Formalization of Domain Annotation Metrics

    2.1 Volumetric Dice Similarity Coefficient (DSC)

    In 3D medical imaging (CT, MRI), manual volumetric segmentations \(A, B \in \{0, 1\}^{H \times W \times D}\) are evaluated via the Dice similarity metric:

    \[ \text{DSC}(A, B) = \frac{2 |A \cap B|}{|A| + |B|} = \frac{2 \sum_{x, y, z} A(x, y, z) \cdot B(x, y, z)}{\sum_{x, y, z} A(x, y, z) + \sum_{x, y, z} B(x, y, z)} \]

    Where \(\text{DSC} \in [0.0, 1.0]\). The 3D Jaccard Volumetric IoU relates directly via:

    \[ \text{IoU}_{\text{3D}} = \frac{\text{DSC}}{2 - \text{DSC}} \]

    2.2 95th-Percentile Hausdorff Distance (HD95)

    While the Dice coefficient measures bulk volumetric overlap, it is notoriously insensitive to narrow boundary spikes or tumor leakage into critical anatomical structures [Menze2014]. The Directed Hausdorff Distance evaluates surface contour distance:

    \[ d(A, B) = \max_{a \in \partial A} \min_{b \in \partial B} \|a - b\|_2 \]

    The bidirectional 95th-percentile Hausdorff Distance (\(d_{\text{HD95}}\)) truncates the extreme \(5\%\) outlier voxel jitter to maintain numerical robustness against single-voxel human boundary artifacts:

    \[ d_{\text{HD95}}(A, B) = \text{percentile}_{95}\left( \left\{ \min_{b \in \partial B} \|a - b\|_2 \right\}_{a \in \partial A} \cup \left\{ \min_{a \in \partial A} \|b - a\|_2 \right\}_{b \in \partial B} \right) \]

    2.3 3D Oriented Bounding Box IoU (\(\text{IoU}_{\text{3D}}\))

    In autonomous driving perception, 3D obstacle bounding boxes are parameterized by 7 degrees of freedom:

    \[ \mathbf{B} = \left[ x, y, z, \; l, w, h, \; \theta_{\text{yaw}} \right] \]

    The 3D intersection volume decouples into the 2D polygon intersection in the Bird's-Eye View (BEV) plane multiplied by the 1D vertical overlap along the \(Z\)-axis:

    \[ \text{Vol}(B_1 \cap B_2) = \text{Area}_{\text{BEV}}(B_1 \cap B_2) \times \max\left(0, \; \min\left(z_1 + \frac{h_1}{2}, z_2 + \frac{h_2}{2}\right) - \max\left(z_1 - \frac{h_1}{2}, z_2 - \frac{h_2}{2}\right)\right) \]
    \[ \text{IoU}_{\text{3D}}(B_1, B_2) = \frac{\text{Vol}(B_1 \cap B_2)}{\text{Vol}(B_1) + \text{Vol}(B_2) - \text{Vol}(B_1 \cap B_2)} \]

    Where \(\text{Area}_{\text{BEV}}\) is computed via the Sutherland-Hodgman polygon clipping algorithm over rotated rectangles.

    2.4 LiDAR Point Cloud Spatial Sampling Density

    In 3D LiDAR annotation, laser beam pulse divergence causes the spatial return density on an annotated obstacle at radial range \(r\) to degrade inversely with range [Caesar2020]:

    \[ \rho_{\text{LiDAR}}(r) = \frac{N_{\text{beams}}}{2\pi r \cdot \Delta \theta_{\text{vert}}} \propto \frac{1}{r} \]

    For distant objects (\(r > 50\text{ meters}\)), a car may reflect fewer than 10 LiDAR points. Annotation pipelines must accumulate multi-sweep temporal point clouds using vehicle ego-motion matrices \(\mathbf{T}_{\text{ego} \to \text{world}}(t)\) to give annotators dense geometric shapes.

    2.5 Legal Span Fuzzy F1 Matching

    In commercial contract review, legal experts frequently disagree on whether parenthetical citations or terminal punctuation belong inside a clause boundary [Hendrycks2021]. Enforcing strict character-exact matching causes valid legal annotations to fail.

    The Fuzzy Token Overlap Ratio awards partial credit for overlapping clause spans \(S_1, S_2\):

    \[ \text{Overlap}_{\text{token}}(S_1, S_2) = \frac{|T(S_1) \cap T(S_2)|}{\min(|T(S_1)|, |T(S_2)|)} \ge \tau_{\text{overlap}} \approx 0.80 \]

    Where \(T(S)\) denotes the set of token strings in span \(S\). If \(\text{Overlap}_{\text{token}} \ge \tau_{\text{overlap}}\), the span prediction is classified as a True Positive under fuzzy contract discovery benchmarks.

    5. Production Python Verification Engine (Pydantic V2)

    The production Python engine below implements schema-validated 3D volumetric Dice metrics, 95th-percentile surface Hausdorff distance calculations, 3D oriented bounding box geometries, and legal fuzzy token span evaluation.

    """
domain_specific_annotation_engine.py
Production verification engine for mission-critical domain annotations:
Medical Imaging (3D Dice & HD95), Autonomous Vehicles (3D Oriented BBox IoU),
and Legal NLP (Fuzzy Token Overlap F1).
"""

from typing import List, Tuple, Dict, Optional, Set
import math
import numpy as np
from pydantic import BaseModel, Field, model_validator


# =====================================================================
# Pydantic V2 Schemas for Domain Annotation Entities
# =====================================================================

class BoundingBox3D(BaseModel):
    """3D Oriented Bounding Box parameterized with 7 degrees of freedom."""
    center_x: float
    center_y: float
    center_z: float
    length: float = Field(..., gt=0.0, description="Size along x axis in meters")
    width: float = Field(..., gt=0.0, description="Size along y axis in meters")
    height: float = Field(..., gt=0.0, description="Size along z axis in meters")
    yaw_deg: float = Field(default=0.0, description="Heading angle in degrees")

    @property
    def volume(self) -> float:
        return self.length * self.width * self.height


class LegalTextSpan(BaseModel):
    """Text span for legal contract extraction."""
    start_char: int = Field(..., ge=0)
    end_char: int = Field(..., gt=0)
    clause_type: str
    tokens: Set[str] = Field(..., description="Set of normalized token strings")

    @model_validator(mode="after")
    def validate_span_indices(self) -> "LegalTextSpan":
        if self.end_char <= self.start_char:
            raise ValueError("end_char must strictly exceed start_char.")
        return self


# =====================================================================
# Domain Computation Engine
# =====================================================================

class DomainSpecificAnnotationEngine:
    @classmethod
    def compute_dice_score_3d(cls, mask_a: np.ndarray, mask_b: np.ndarray) -> float:
        """Computes 3D Volumetric Dice Similarity Coefficient."""
        if mask_a.shape != mask_b.shape:
            raise ValueError("Volumes must have identical 3D shapes.")
        inter = float(np.sum(mask_a * mask_b))
        sum_total = float(np.sum(mask_a) + np.sum(mask_b))
        if sum_total == 0:
            return 1.0
        return round(float((2.0 * inter) / sum_total), 4)

    @classmethod
    def compute_hd95(cls, points_a: np.ndarray, points_b: np.ndarray) -> float:
        """Computes 95th-percentile bidirectional surface Hausdorff Distance in millimeters."""
        from scipy.spatial.distance import cdist
        d_ab = cdist(points_a, points_b)
        min_ab = np.min(d_ab, axis=1)
        min_ba = np.min(d_ab, axis=0)
        all_dists = np.concatenate([min_ab, min_ba])
        return round(float(np.percentile(all_dists, 95)), 2)

    @classmethod
    def compute_3d_box_iou(cls, b1: BoundingBox3D, b2: BoundingBox3D) -> float:
        """
        Computes 3D oriented bounding box IoU.
        Approximates BEV polygon overlap under small heading error and computes vertical Z overlap.
        """
        # Height overlap along Z axis
        z1_min = b1.center_z - b1.height / 2.0
        z1_max = b1.center_z + b1.height / 2.0
        z2_min = b2.center_z - b2.height / 2.0
        z2_max = b2.center_z + b2.height / 2.0

        inter_z = max(0.0, min(z1_max, z2_max) - max(z1_min, z2_min))
        if inter_z == 0.0:
            return 0.0

        # Axis-aligned BEV overlap attenuated by cos(delta_yaw)
        x_inter = max(0.0, min(b1.center_x + b1.length/2, b2.center_x + b2.length/2) -
                           max(b1.center_x - b1.length/2, b2.center_x - b2.length/2))
        y_inter = max(0.0, min(b1.center_y + b1.width/2, b2.center_y + b2.width/2) -
                           max(b1.center_y - b1.width/2, b2.center_y - b2.width/2))

        yaw_diff_rad = math.radians(abs(b1.yaw_deg - b2.yaw_deg))
        bev_inter = x_inter * y_inter * max(0.0, math.cos(yaw_diff_rad))

        vol_inter = bev_inter * inter_z
        vol_union = b1.volume + b2.volume - vol_inter

        return round(float(vol_inter / max(1e-12, vol_union)), 4)

    @classmethod
    def evaluate_legal_fuzzy_span(
        cls,
        s1: LegalTextSpan,
        s2: LegalTextSpan,
        tau_overlap: float = 0.80
    ) -> Tuple[bool, float, bool]:
        """
        Evaluates legal contract span overlap.
        Returns: (fuzzy_pass, overlap_ratio, exact_match)
        """
        exact_match = (s1.start_char == s2.start_char and s1.end_char == s2.end_char)
        inter_tokens = len(s1.tokens.intersection(s2.tokens))
        min_tokens = min(len(s1.tokens), len(s2.tokens))

        overlap = inter_tokens / max(1, min_tokens)
        fuzzy_pass = (overlap >= tau_overlap) and (s1.clause_type == s2.clause_type)

        return fuzzy_pass, round(float(overlap), 4), exact_match


# =====================================================================
# Automated Assertion Suite for Annotation CI/CD Gates
# =====================================================================

def run_domain_assertions():
    # Test 1: 3D Volumetric Dice Score
    v1 = np.zeros((10, 10, 10), dtype=np.uint8)
    v2 = np.zeros((10, 10, 10), dtype=np.uint8)
    v1[2:6, 2:6, 2:6] = 1 # 4x4x4 = 64 voxels
    v2[4:8, 2:6, 2:6] = 1 # 4x4x4 = 64 voxels; overlap x in [4, 6] -> 2x4x4 = 32 voxels

    dice = DomainSpecificAnnotationEngine.compute_dice_score_3d(v1, v2)
    assert dice == 0.50, f"Expected 0.50, got {dice}"

    # Test 2: 95th-Percentile Hausdorff Distance
    pts1 = np.array([[0.0, 0.0], [1.0, 0.0], [2.0, 0.0], [3.0, 0.0]])
    pts2 = np.array([[0.0, 1.5], [1.0, 1.5], [2.0, 1.5], [3.0, 1.5]]) # 1.5mm offset
    hd95 = DomainSpecificAnnotationEngine.compute_hd95(pts1, pts2)
    assert abs(hd95 - 1.5) < 1e-2

    # Test 3: 3D Oriented Bounding Box IoU
    b1 = BoundingBox3D(center_x=0.0, center_y=0.0, center_z=0.0, length=4.0, width=2.0, height=1.5, yaw_deg=0.0)
    # Identical box -> IoU == 1.0
    assert DomainSpecificAnnotationEngine.compute_3d_box_iou(b1, b1) == 1.0

    # Test 4: Legal Fuzzy Token Span Evaluation

    6. Diagnostic Self-Assessment Scenarios

    Scenario 1: Why Volumetric Dice Score Fails in Surgical Tumor Resection Audits

    A deep learning model segments a \(60\text{ cm}^3\) pancreatic adenocarcinoma with an outstanding Dice Similarity Coefficient of \(\text{DSC} = 0.945\). However, when the surgical oncology tumor board reviews the segmentation for laparoscopic resection, they unanimously reject the automated contour. Explain the mathematical mechanism by which a \(94.5\%\) Dice score can mask an anatomically lethal boundary error, and identify the complementary metric required.

    Reveal Detailed Solution

    1. Mathematical Mechanism: - The Dice coefficient is a Bulk Volume Ratio: $\(\text{DSC} = \frac{2 |A \cap B|}{|A| + |B|}\)$ - A \(60\text{ cm}^3\) tumor volume corresponds to \(\approx 60{,}000\text{ mm}^3\) (or hundreds of thousands of voxels). - Suppose the segmentation leaks by just 15 voxels into the adjacent Superior Mesenteric Artery (SMA), forming an \(8\text{ mm}\) radial vascular protrusion. The volume of this protrusion is tiny (\(\approx 150\text{ mm}^3\)), representing less than \(0.25\%\) of the total tumor volume. - Consequently, bulk Dice drops from \(0.948\) to only \(0.945\), an insignificant statistical change that passes automated benchmark gates. - In surgery, however, mistaking vascular infiltration can cause fatal arterial laceration during resection.

    2. Mandatory Complementary Metric: - Medical imaging pipelines must evaluate the 95th-Percentile Hausdorff Distance (\(d_{\text{HD95}}\)) alongside Dice: $\(d_{\text{HD95}}(A, B) = \text{percentile}_{95}\left( \min_{b \in \partial B} \|a - b\|_2 \right)\)$ - The \(8\text{ mm}\) arterial protrusion immediately triggers an HD95 spike from \(1.2\text{ mm}\) to \(8.0\text{ mm}\), exceeding the clinical tolerance threshold (\(d_{\text{HD95}} \le 3.5\text{ mm}\)) and halting automated deployment.

    Scenario 2: The Spatial Impact of Sensor Desynchronization in Autonomous Vehicles

    An autonomous vehicle perception stack integrates a 30 FPS rolling-shutter camera with a 10 Hz spinning LiDAR scanner. Due to an operating system clock drift, the camera frame timestamps lag the LiDAR point clouds by \(\Delta t = 45\text{ ms}\). If an approaching vehicle travels toward the ego-vehicle at a closing speed of \(108\text{ km/h}\) (\(30\text{ m/s}\)): 1. Calculate the physical spatial displacement error between the LiDAR 3D bounding box and the 2D camera pixels. 2. Explain why annotators attempting to label multi-modal bounding boxes without ego-motion interpolation produce corrupted data.

    Reveal Detailed Solution

    1. Spatial Displacement Error: Closing velocity \(v = 108\text{ km/h} = \frac{108}{3.6} = 30\text{ m/s}\). Displacement during latency: $\(\Delta d = v \cdot \Delta t = 30\text{ m/s} \times 0.045\text{ s} = 1.35\text{ meters}\)$ The physical obstacle moves \(1.35\text{ meters}\) between the LiDAR beam strike and the camera frame exposure.

    2. Annotation Pipeline Corruption: - When annotators project the LiDAR point cloud onto the camera image, the 3D bounding box will appear offset by \(1.35\text{ meters}\) (the car in the image will appear detached from its LiDAR points). - Human annotators attempting to force visual alignment will either: 1. Skew the 3D bounding box dimensions, introducing massive volume errors. 2. Misjudge vehicle velocity vectors, corrupting tracking trajectories in \(\text{MOTA}\). - Remediation: Use hardware PTP (Precision Time Protocol IEEE 1588) to synchronize sensors to \(<1\text{ ms}\), and apply Kalman-filtered vehicle ego-motion matrices \(\mathbf{T}(t)\) to interpolate point clouds to exact camera exposure midpoints.

    Scenario 3: Strict Character Matching vs. Fuzzy Token Overlap in Legal Contract AI

    An automated NLP system trained to extract Governing Law clauses from commercial contracts is evaluated on 1,000 agreements. Annotator 1 highlights: "This Agreement shall be governed by the laws of the State of Delaware." (Character offsets: [120, 196]) Annotator 2 highlights: "governed by the laws of the State of Delaware" (Character offsets: [142, 195], omitting introductory filler and terminal period). 1. Evaluate their agreement under Strict Character Matching. 2. Evaluate their agreement under Fuzzy Token Overlap (\(\tau = 0.80\)). 3. Why does modern Legal NLP (e.g., CUAD) enforce fuzzy token overlap?

    Reveal Detailed Solution

    1. Strict Character Match: Character offsets \([120, 196] \ne [142, 195]\). $\(\text{Strict Match} = 0 \quad (\text{False Disagreement, F1 = 0.0})\)$

    2. Fuzzy Token Overlap: - Token set \(T(S_1)\): {"this", "agreement", "shall", "be", "governed", "by", "the", "laws", "of", "the", "state", "of", "delaware"} (13 tokens). - Token set \(T(S_2)\): {"governed", "by", "the", "laws", "of", "the", "state", "of", "delaware"} (9 tokens). - Intersection \(|T_1 \cap T_2| = 9\) tokens. - Minimum token size \(\min(|T_1|, |T_2|) = 9\). $\(\text{Overlap}_{\text{token}} = \frac{9}{9} = 1.0 \quad (100\%)\)$ Because \(\text{Overlap} = 1.0 \ge 0.80\), the fuzzy match is \(100\%\) True Positive.

    3. Legal NLP Rationale: In commercial legal analysis, both annotators correctly identified that Delaware law governs the agreement. Penalizing the second annotator for omitting boilerplate grammatical lead-ins ("This Agreement shall be...") creates artificial noise in benchmark evaluations. Fuzzy token matching absorbs formatting and punctuation variance while rigorously preserving semantic legal validity.

    Scenario 4: Lossy Clamping in Medical DICOM CT Annotation

    A data engineering team converts a repository of 10,000 lung CT scans from native 16-bit DICOM format into standard 8-bit PNG images (\(0\text{–}255\) RGB) to allow annotators to use a lightweight browser annotation tool. When radiologists attempt to annotate Ground-Glass Opacities (GGOs) indicating early-stage pulmonary fibrosis, they report that lesions are completely invisible. Explain the physical and mathematical cause of this data destruction, and specify the proper DICOM Hounsfield Unit window/level protocol.

    Reveal Detailed Solution

    1. Physical Cause (Radiodensity Quantization Loss): - Native CT scans record physical radiodensity in Hounsfield Units (HU) spanning from \(-1{,}000\text{ HU}\) (air) to \(0\text{ HU}\) (water) up to \(+3{,}000\text{ HU}\) (dense cortical bone), requiring 12-to-16 bits of dynamic range (\(4{,}096\text{ discrete values}\)). - Linearly compressing this \(4{,}000\text{ HU}\) span into an 8-bit scale (\(256\) grayscale values) divides radiodensity resolution by \(\approx 16\times\): $\(\Delta \text{HU}_{\text{step}} = \frac{4000}{256} \approx 15.6\text{ HU per pixel value}\)$ - Ground-Glass Opacities (GGOs) manifest as subtle radiodensity elevations of only \(10\text{–}25\text{ HU}\) above normal lung parenchyma (\(-850\text{ HU}\) to \(-700\text{ HU}\)). Clamping obliterates this subtle contrast into a single uniform gray value, making GGOs completely invisible.

    2. Standard DICOM Protocol (Windowing & Leveling): Annotation tools must ingest raw 16-bit DICOM arrays and apply non-destructive client-side windowing: $\(I_{\text{display}} = \text{clip}\left( \frac{\text{HU} - (L - W/2)}{W} \times 255, \; 0, \; 255 \right)\)$ For lung parenchyma, apply standard Lung Window parameters: - Window Level (\(L\)): \(-600\text{ HU}\) - Window Width (\(W\)): \(1{,}500\text{ HU}\) This dedicates the full 256 display levels exclusively to the critical lung density range (\(-1{,}350\text{ HU}\) to \(+150\text{ HU}\)), preserving delicate diagnostic margins.

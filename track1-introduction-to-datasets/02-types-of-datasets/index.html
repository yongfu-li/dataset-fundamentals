    1. The Two Fundamental Classification Axes

    Every dataset encountered in empirical science and production machine learning can be systematically categorized along two orthogonal dimensions: Structural Organization and Temporal Behavior [Gandomi2015].

    flowchart TD
    Data["Raw Observational<br/>Data Universe"] --> Axis1["Structural Dimension"]
    Data --> Axis2["Temporal Dimension"]

    Axis1 --> Struct["Structured<br/>(Tabular, Fixed Schema, SQL, CSV)"]
    Axis1 --> Semi["Semi-Structured<br/>(Hierarchical, Self-Describing, JSON, XML)"]
    Axis1 --> Unstruct["Unstructured<br/>(Continuous Signal, Embeddings, Media)"]

    Axis2 --> Static["Static Snapshots<br/>(Immutable, Frozen, Historical)"]
    Axis2 --> Dynamic["Dynamic Streams<br/>(Continuous Influx, Sliding Windows)"]

    Selecting an appropriate organizational architecture dictates everything downstream: computational ingestion throughput, serialization efficiency, query ergonomics, storage footprints, and the susceptibility of the dataset to schema drift and temporal covariate shift [Chapman2020].

    Classification Dimension Archetype Defining Property Primary Storage Formats Canonical Enterprise Example
    Structural Structured Rigid, predefined tabular schema adhering to first normal form (\(1\text{NF}\)). Parquet, Arrow, SQL tables, CSV Customer Master Database, General Ledger Transactions
    Structural Semi-Structured Self-describing schema with hierarchical tags, nesting, and flexible key-value pairs. JSON, BSON, XML, YAML, Protocol Buffers E-commerce Order Payloads, Sensor Telemetry Events
    Structural Unstructured Non-tabular continuous signal or text devoid of uniform relational attributes. MP4, WAV, JPEG, PNG, Raw Markdown / PDF Medical CT Scans, Social Media Video Feeds, Voice Audio
    Temporal Static Frozen temporal snapshot representing observations within a bounded window \([t_0, t_1]\). Archived Parquet, Cold Blob Storage (S3 Glacier) Decennial Census, ImageNet-1K, Frozen Benchmark Suite
    Temporal Dynamic Unbounded, non-stationary continuous event stream with real-time arrival \(\lambda(t)\). Apache Kafka, Apache Pulsar, Redis Streams High-Frequency Stock Ticks, IoT Fleet Telemetry

    2. Mathematical Formalization of Structural Archetypes

    2.1 Structured Tabular Relations

    Formally, a structured dataset is defined as an empirical relation \(R\) over a fixed schema relation signature \(\mathcal{S} = (A_1: \mathcal{F}_1, A_2: \mathcal{F}_2, \dots, A_M: \mathcal{F}_M)\), where each attribute \(A_j\) draws values strictly from a defined domain \(\mathcal{F}_j\):

    \[R \subseteq \mathcal{F}_1 \times \mathcal{F}_2 \times \dots \times \mathcal{F}_M\]

    Every observation \(\mathbf{r}_i \in R\) is an ordered \(M\)-tuple \(\mathbf{r}_i = (v_{i1}, v_{i2}, \dots, v_{iM})\) such that:

    \[\forall j \in \{1, \dots, M\}, \quad v_{ij} \in \mathcal{F}_j \cup \{\text{NULL}\}\]

    Structured datasets satisfy Relational Invariance: 1. Column Homogeneity: For any two tuples \(\mathbf{r}_i, \mathbf{r}_k \in R\), attribute \(A_j\) maintains an identical physical memory layout and type constraint (\(\text{type}(v_{ij}) = \text{type}(v_{kj})\)). 2. First Normal Form (\(1\text{NF}\)): Attribute domains contain only atomic, indivisible values; repeating groups or unindexed nested arrays are prohibited.

    classDiagram
    class CustomerTable {
        +UInt64 customer_id [PK]
        +Utf8 name
        +Utf8 email [Unique]
        +Date signup_date
        +Float64 total_spend_usd
    }
    class TransactionTable {
        +UInt64 txn_id [PK]

    2.2 Semi-Structured Hierarchical Trees

    A semi-structured dataset relaxes the requirement of a global schema. Rather than an array of identical tuples, semi-structured records are formalized as rooted, labeled, directed attributed trees \(T = (V, E, \ell, v_0, \nu)\) [Abiteboul1997]: - \(V\): Finite set of node vertices representing objects, arrays, or primitive values. - \(E \subseteq V \times V\): Directed parent-child containment edges. - \(\ell: E \to \Sigma^*\): Edge labeling function assigning string key identifiers (e.g., "order_id", "items"). - \(v_0 \in V\): The designated root object vertex. - \(\nu: V_{leaf} \to \mathcal{U}\): Value mapping on leaf nodes drawing from the universal scalar union \(\mathcal{U} = \mathbb{R} \cup \text{String} \cup \text{Bool} \cup \{\text{null}\}\).

    flowchart TD
    Root["Root: {Order Object}"] --> Edge1["'order_id': 94821"]
    Root --> Edge2["'customer': { ... }"]
    Root --> Edge3["'line_items': [ ... ]"]
    Root --> Edge4["'notes': 'Fast shipping requested'"]

    Edge2 --> CustID["'id': 104"]
    Edge2 --> CustName["'tier': 'Platinum'"]

    Edge3 --> Item1["Item [0]: {sku: 'A1', qty: 2}"]
    Edge3 --> Item2["Item [1]: {sku: 'B4', qty: 1, discount: 0.15}"]

    classDef blue fill:#1e3a8a,stroke:#3b82f6,color:#fff;
    classDef green fill:#064e3b,stroke:#10b981,color:#fff;
    classDef amber fill:#78350f,stroke:#f59e0b,color:#fff;

    class Root,Edge2,Item1,Item2 blue;

    Semi-structured datasets employ Schema-on-Read: $\(\text{Query}(T, \pi) = \{ \nu(u) \mid u \in V, \text{Path}(v_0 \to u) = \pi \}\)$ Notice that node Item [1] possesses a 'discount' attribute absent in Item [0]. Semi-structured formats handle sparse, heterogeneously evolving attributes without costly relational schema migrations.

    2.3 Unstructured Multimodal Manifolds

    Unstructured datasets lack explicit schema markers or field tags. Instead, each observation \(\mathbf{x} \in \mathcal{X}\) exists as a raw physical signal digitized into high-dimensional coordinate tensors:

    1. Digital Images (2D/3D Tensor): $\(\mathbf{I} \in \mathbb{R}^{H \times W \times C}, \quad I_{h, w, c} \in [0, 255] \subset \mathbb{N}\)$ where \(H, W\) represent spatial pixel resolution and \(C \in \{1, 3\}\) denotes color channels.
    2. Acoustic Audio (1D Continuous Signal): $\(\mathbf{s} \in \mathbb{R}^{T \cdot F_s}, \quad s[n] = s(n / F_s)\)$ where \(F_s\) is the sampling rate (e.g., \(44.1\text{ kHz}\)) over duration \(T\) seconds.
    3. Natural Language Corpus: $\(\mathbf{w} = (w_1, w_2, \dots, w_L), \quad w_k \in \mathcal{V}\)$ where \(\mathcal{V}\) is a discrete vocabulary token lexicon (\(|\mathcal{V}| \approx 32{,}000 - 100{,}000\)) and \(L\) is sequence length.

    Because raw signals exhibit high ambient dimension but low intrinsic manifold dimension, learning systems must construct a parameterized feature embedding map \(f_\theta: \mathcal{X} \to \mathbb{R}^d\) (\(d \ll D\)) to extract semantically structured representations [Deng2009].

    3. Temporal Dynamics: Static Snapshots vs. Dynamic Streaming

    Beyond structural geometry, the temporal velocity and stationary properties of data ingestion govern pipeline architecture.

    sequenceDiagram
    autonumber
    participant Source as Event Source (Sensors / Ticks)
    participant Buffer as Streaming Ingestion (Kafka / Buffer)
    participant Engine as Real-Time Window Processor
    participant Lake as Cold Parquet Archive (S3)

    Source->>Buffer: Event e(t_1), e(t_2) [Unbounded Feed]
    Buffer->>Engine: Window Slice [t_0, t_0 + Δt]
    Note over Engine: Tumbling / Sliding Aggregation<br/>Watermark: t_w = max(t) - τ
    Engine-->>Lake: Micro-batch Flush (Immutable Chunk)
    Note over Lake: Static Historic Snapshot Partition<br/>year=2026/month=11/day=09/

    3.1 Static Datasets: Deterministic & Immutable

    A static dataset \(\mathcal{D}_{static}\) is an immutable, bounded collection captured over a closed temporal interval \([t_{start}, t_{end}]\):

    \[\mathcal{D}_{static} = \{\mathbf{x}_i\}_{i=1}^N \sim \mathcal{P}(X)\]
    • Reproducibility Guarantee: Every experiment run over \(\mathcal{D}_{static}\) yields identical summary statistics, facilitating deterministic peer review.
    • Vulnerability to Covariate Shift: As calendar time progresses \(t \gg t_{end}\), real-world phenomena undergo distribution drift: $\(\mathcal{P}_{production, t}(X) \neq \mathcal{P}_{static}(X)\)$ causing model degradation despite perfect benchmark performance.

    3.2 Dynamic Streaming Datasets: Unbounded & Non-Stationary

    A dynamic dataset is an open-ended sequence of timestamped tuples arriving continuously in real time:

    \[\mathcal{S} = \big( (\mathbf{x}_1, t_1), (\mathbf{x}_2, t_2), \dots, (\mathbf{x}_k, t_k), \dots \big), \quad t_k \le t_{k+1}\]

    To analyze dynamic streams, stream processors construct Temporal Windows \(W\): 1. Tumbling Windows: Non-overlapping, contiguous time buckets: $\(W_k = [k \cdot \Delta t, (k+1) \cdot \Delta t)\)$ 2. Sliding Windows: Overlapping time buckets advancing by step \(\delta < \Delta t\): $\(W_k = [k \cdot \delta, k \cdot \delta + \Delta t)\)$ 3. Session Windows: Dynamically sized windows bounded by gaps of inactivity \(\Delta t_{idle} > \theta_{gap}\).

    The Late Arrival Problem & Watermarks

    In distributed networks, transmission latency induces out-of-order events: an event generated at event-time \(t_{event}\) arrives at processing-time \(t_{proc} > t_{event}\). Stream engines implement a watermark function \(W(t)\) establishing an acceptable latency threshold \(\tau_{lag}\):

    \[\text{Watermark}(t) = \max_{e \in \text{Observed}} (t_{event}(e)) - \tau_{lag}\]

    Any incoming event with \(t_{event} < W(t)\) is flagged as dropped late data or redirected to a dead-letter compensation queue [Babcock2002].

    4. Real-World Case Studies

    Case Study A: E-Commerce Multimodal Ingestion Pipeline (Shopify / Amazon)

    Enterprise retail platforms do not rely on a single data type; they operate an integrated multi-structural fabric:

    flowchart LR
    A[("Relational DB<br/>PostgreSQL / Aurora<br/>Customer IDs & Orders")] --> F[("Feature Store<br/>Feast / Hopsworks")]
    B[("Semi-Structured Logs<br/>JSON Clickstream Events<br/>Page Views & Carts")] --> F
    C[("Unstructured S3 Bucket<br/>JPEG / WebP<br/>Product Catalog Imagery")] --> E["Vision Embedding<br/>ResNet / ViT"]
    E --> F
    F --> M["Recommendation Model<br/>Dual-Tower Transformer"]

    • The Challenge: Joining static relational SQL customer records (\(N = 10^7\)) with dynamic semi-structured JSON clickstream feeds (\(50{,}000\text{ events/sec}\)) and high-dimensional image embeddings (\(d = 512\)).
    • The Solution: Event timestamps provide the universal join key. JSON payloads are normalized into typed Parquet micro-batches using Apache Arrow, preserving leaf sparsity while eliminating relational database locking contention.

    Case Study B: High-Frequency Limit Order Book (LOB) Dynamics

    In algorithmic market microstructure, order book updates arrive via Financial Information eXchange (FIX) UDP multicast feeds at microsecond resolution:

    • The Data Stream: Every record is a dynamic tuple: $\((\text{timestamp}_{epoch\_ns}, \text{symbol}, \text{side} \in \{\text{BID}, \text{ASK}\}, \text{price}, \text{volume}, \text{order\_type})\)$
    • The Engineering Trap: Treating this data as a static batch causes severe lookahead bias during strategy training. A model must never access state \(S_{t+\delta}\) when predicting at time \(t\). Pipeline engineers store data strictly in order-level dynamic replay logs and simulate historical tick playback with nanosecond clock synchronization.

    6. Production Engineering Implementation
    

    The following production script demonstrates how modern data engineering libraries (Polars, PyArrow, and Pydantic V2) cleanly handle the transformation between semi-structured JSON documents and high-performance structured columnar tables:
    

    """
Dataset Structural Transformation & Stream Ingestion Pipeline
Demonstrating Schema-on-Read JSON flattening into vectorized Polars Columnar Storage.
"""

from __future__ import annotations
import json
from datetime import datetime, timezone
from typing import List, Optional
import polars as pl
from pydantic import BaseModel, Field, EmailStr


# =====================================================================
# 1. Semi-Structured Domain Schema (Pydantic V2 Contract)
# =====================================================================
class OrderItem(BaseModel):
    sku: str
    quantity: int = Field(gt=0, description="Quantity must be strictly positive")
    unit_price_usd: float = Field(ge=0.0)


class CustomerOrderEvent(BaseModel):
    order_id: str
    customer_id: int
    customer_email: EmailStr
    items: List[OrderItem]
    user_notes: Optional[str] = None
    created_at: datetime = Field(default_factory=lambda: datetime.now(timezone.utc))


# =====================================================================
# 2. Semi-Structured JSON Payload Normalizer
# =====================================================================
def ingest_and_flatten_orders(raw_json_records: List[dict]) -> pl.DataFrame:
    """
    Validates semi-structured payloads against Pydantic contract and
    flattens hierarchical nested arrays into a vectorized tabular DataFrame.
    """
    flattened_rows = []

    for raw in raw_json_records:
        validated_order = CustomerOrderEvent.model_validate(raw)

        # Calculate order summary
        total_items = sum(it.quantity for it in validated_order.items)
        total_value = sum(it.quantity * it.unit_price_usd for it in validated_order.items)

        flattened_rows.append({
            "order_id": validated_order.order_id,
            "customer_id": validated_order.customer_id,
            "customer_email": validated_order.customer_email,
            "total_items": total_items,
            "total_order_usd": round(total_value, 2),
            "has_custom_notes": validated_order.user_notes is not None,
            "timestamp": validated_order.created_at,
        })

    # Materialize into Polars Arrow-native memory table
    df = pl.DataFrame(
        flattened_rows,
        schema={
            "order_id": pl.Utf8,
            "customer_id": pl.Int64,
            "customer_email": pl.Utf8,
            "total_items": pl.Int32,
            "total_order_usd": pl.Float64,
            "has_custom_notes": pl.Boolean,
            "timestamp": pl.Datetime("ms", "UTC"),
        }
    )
    return df


# =====================================================================
# 3. Dynamic Tumbling Window Ingestion Processor
# =====================================================================
def process_dynamic_tumbling_window(df: pl.DataFrame, window_interval: str = "1h") -> pl.DataFrame:
    """
    Applies dynamic time-window aggregation over the flattened stream.
    """
    aggregated_window = (
        df.sort("timestamp")
        .group_by_dynamic("timestamp", every=window_interval)
        .agg([
            pl.count("order_id").alias("order_velocity"),
            pl.sum("total_order_usd").alias("gross_merchandise_value"),
            pl.mean("total_order_usd").alias("average_order_value"),
            pl.n_unique("customer_id").alias("unique_purchasers"),
        ])
    )
    return aggregated_window

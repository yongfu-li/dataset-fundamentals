    3.5 Privacy-Preserving Technologies: k-Anonymity, l-Diversity, t-Closeness & Differential Privacy

    📖 Companion Monograph Section Available
    Read Chapter 3: Ethics and Privacy in Data Work (§3.4: Privacy-Preserving Techniques) in the official Springer Nature monograph, detailing equivalence class generalization, Earth Mover's Distance in t-closeness, and Laplace noise calibration in differential privacy.
    Explore Chapter 3 in Monograph →

    Estimated Study Time: ~16 minutes • Lecture Deck: Download PPTX · Download PDF

    While legal policies and consent forms establish organizational authorization, they provide zero cryptographic protection against adversarial re-identification. When sensitive datasets (e.g., patient EHRs, mobile geolocation trajectories, tax records) must be published, shared, or trained on by machine learning models, engineers must deploy Privacy-Enhancing Technologies (PETs).

    This section provides the mathematical foundations for the four cornerstone data anonymization frameworks: \(k\)-Anonymity, \(l\)-Diversity, \(t\)-Closeness, and \(\epsilon\)-Differential Privacy, followed by decentralized Federated Learning architectures [Sweeney2002, Dwork2006].

    1. k-Anonymity & Equivalence Class Generalization

    Introduced by Dr. Latanya Sweeney [Sweeney2002], \(k\)-Anonymity ensures that every individual in a released dataset is mathematically indistinguishable from at least \(k - 1\) other individuals with respect to quasi-identifiers.

    A. Mathematical Formulation

    Let \(T(A_1, \dots, A_m, S_1, \dots, S_p)\) be a table where \(QI = \{A_1, \dots, A_m\}\) denotes the set of quasi-identifiers and \(S\) denotes sensitive attributes.

    An Equivalence Class \([t]_{QI}\) is the subset of records sharing identical quasi-identifier values:

    \[[t]_{QI} = \left\{ r \in T \mid \forall A_j \in QI, \; r[A_j] = t[A_j] \right\}\]

    A table \(T\) satisfies \(k\)-Anonymity if and only if every equivalence class contains at least \(k\) distinct records:

    \[\min_{t \in T} \left| [t]_{QI} \right| \ge k\]

    B. Engineering Transforms: Generalization & Suppression

    1. Attribute Generalization: Replacing specific values with broader categorical hierarchies (e.g., Age \(32 \to [30\text{--}39]\); ZIP \(94107 \to 941**\)).
    2. Record Suppression: Completely removing extreme outlier rows that cannot be generalized without destroying table utility.

    C. Vulnerabilities: Homogeneity & Background Knowledge Attacks

    While \(k\)-anonymity prevents identity disclosure, it fails against attribute disclosure: - Homogeneity Attack: If all \(k\) records in an equivalence class share the same sensitive attribute (e.g., all 4 patients in \([0213*, [30\text{--}40]]\) have "Alzheimer's"), an adversary knowing the subject belongs to that group discovers their diagnosis with \(100\%\) probability.

    2. l-Diversity & t-Closeness: Protecting Sensitive Distributions

    To eliminate homogeneity vulnerabilities, Machanavajjhala et al. [Machanavajjhala2007] introduced \(l\)-Diversity.

    A. l-Diversity

    An equivalence class \([t]_{QI}\) satisfies \(l\)-Diversity if it contains at least \(l\) "well-represented" values for each sensitive attribute \(S\). - Distinct \(l\)-Diversity: The number of unique sensitive values in each equivalence class must be at least \(l\):

    \[\left| \text{Unique}\left(\{r[S] \mid r \in [t]_{QI}\}\right) \right| \ge l\]
    • Entropy \(l\)-Diversity: Enforces that sensitive values are distributed uniformly across the equivalence class:
    \[-\sum_{s \in \mathcal{S}} p(s) \log_2 p(s) \ge \log_2(l)\]

    B. The Skewness & Similarity Attack on l-Diversity

    Even an \(l\)-diverse table remains vulnerable to Semantic Similarity Attacks. If an equivalence class contains \(l = 3\) sensitive values: {Gastric Ulcer, Gastritis, Stomach Cancer}, an adversary discovers with certainty that the subject suffers from a severe gastrointestinal illness.

    C. t-Closeness & The Earth Mover's Distance

    To resolve similarity attacks, Li et al. [Li2007] introduced \(t\)-Closeness:

    An equivalence class \([t]_{QI}\) satisfies \(t\)-Closeness if the distance between the marginal probability distribution of the sensitive attribute within the equivalence class (\(P\)) and the global distribution across the entire table (\(Q\)) does not exceed threshold \(t\):

    \[\mathcal{D}[P, Q] \le t\]

    Where the statistical distance \(\mathcal{D}[P, Q]\) is measured via the Earth Mover's Distance (Wasserstein Metric):

    \[\mathcal{D}[P, Q] = \frac{1}{m - 1} \sum_{i=1}^{m-1} \left| F_P(v_i) - F_Q(v_i) \right|\]

    Where \(F_P\) and \(F_Q\) are cumulative distribution functions over ordered sensitive categories \(v_1 < v_2 < \dots < v_m\).

    3. Differential Privacy (DP): Cryptographic Formalism

    While \(k\)-anonymity and \(t\)-closeness operate on static database tables, they remain vulnerable to arbitrary auxiliary side-channel knowledge.

    Pioneered by Cynthia Dwork [Dwork2006], Differential Privacy is a mathematically rigorous property of a randomized algorithm, providing quantifiable guarantees that hold regardless of what auxiliary external information an adversary possesses.

    A. The Formal Definition

    A randomized query mechanism \(\mathcal{M}\) satisfies \((\epsilon, \delta)\)-Differential Privacy if for all neighboring datasets \(D_1, D_2 \in \mathcal{D}\) differing on at most one individual record (\(\|D_1 \Delta D_2\| \le 1\)), and for all query output subsets \(\mathcal{S} \subseteq \text{Range}(\mathcal{M})\):

    \[\mathbb{P}\left[\mathcal{M}(D_1) \in \mathcal{S}\right] \le \exp(\epsilon) \cdot \mathbb{P}\left[\mathcal{M}(D_2) \in \mathcal{S}\right] + \delta\]
    • \(\epsilon\) (Privacy Budget): Governs the maximum statistical leakage. As \(\epsilon \to 0\), privacy approaches perfection (pure noise), but utility drops. In production systems, \(\epsilon \in [0.1, 2.0]\) is considered strong privacy; \(\epsilon > 10\) provides minimal protection.
    • \(\delta\) (Failure Probability): The probability that \(\epsilon\)-DP fails. Typically set to \(\delta \ll \frac{1}{N}\) (e.g., \(10^{-6}\)). When \(\delta = 0\), it is referred to as Pure \(\epsilon\)-Differential Privacy.

    B. The Laplace Mechanism

    For a numerical query function \(f: \mathcal{D} \to \mathbb{R}^d\), its \(L_1\) Global Sensitivity \(\Delta f\) measures the maximum change induced by adding or removing any single individual:

    \[\Delta f = \max_{\|D_1 \Delta D_2\| \le 1} \|f(D_1) - f(D_2)\|_1\]

    The Laplace Mechanism achieves pure \(\epsilon\)-DP by injecting calibrated noise drawn from a zero-mean Laplace distribution:

    \[\mathcal{M}_{\text{Lap}}(D) = f(D) + \mathbf{Y}, \quad Y_i \stackrel{\text{i.i.d.}}{\sim} \text{Laplace}\left(0, \frac{\Delta f}{\epsilon}\right)\]

    Where the Laplace probability density function is:

    \[\text{Lap}(y \mid b) = \frac{1}{2b} \exp\left(-\frac{|y|}{b}\right), \quad b = \frac{\Delta f}{\epsilon}\]

    4. Federated Learning (FL): Decentralized Model Ingestion

    When centralizing sensitive records is legally or ethically prohibited (e.g., clinical hospital networks, on-device mobile keystroke prediction), engineers deploy Federated Learning [McMahan2017, Li2020].

    C1->>C1: θ_A = θ_t - η ∇ L_A
    C2->>C2: θ_B = θ_t - η ∇ L_B
    C3->>C3: θ_C = θ_t - η ∇ L_C

    C1->>Server: Send encrypted model update Δθ_A
    C2->>Server: Send encrypted model update Δθ_B
    C3->>Server: Send encrypted model update Δθ_C

    Note over Server: Federated Averaging (FedAvg): θ_{t+1} = Σ (n_k / n) θ_k

    The FedAvg Objective

    The global optimization problem aggregates loss functions across \(K\) decentralized nodes without collecting their data:

    \[\min_{\boldsymbol{\theta}} F(\boldsymbol{\theta}) = \sum_{k=1}^K \frac{n_k}{n} F_k(\boldsymbol{\theta})\]
    \[\boldsymbol{\theta}^{(t+1)} \leftarrow \sum_{k=1}^K \frac{n_k}{n} \boldsymbol{\theta}_k^{(t)}\]

    [!WARNING] Gradient Inversion Risk: Federated learning alone is not a complete privacy guarantee. Malicious central coordinators can execute Deep Leakage from Gradients (DLG), solving optimization problems to reconstruct original private training images from raw gradient vectors \(\nabla \boldsymbol{\theta}\). Production FL pipelines must combine Secure Aggregation (SecAgg) and Local Differential Privacy (LDP).

    💡 Key Engineering Takeaways

    1. \(k\)-Anonymity Fails on Homogeneity: Always verify that sensitive attributes are \(l\)-diverse across equivalence classes to prevent zero-entropy disclosure.
    2. Differential Privacy Budget Math: Privacy budget \(\epsilon\) is a non-renewable resource; multiple queries against the same dataset consume budget additively (\(\sum \epsilon_i\)).
    3. Federated Gradients Leak Data: Model weights and gradients can leak private records via inversion attacks; always pair FL with Secure Aggregation (SecAgg).

    🎯 Pedagogical Rationale & Conceptual Overview

    Establishing robust dataset documentation and version control requires transitioning from reactive, informal human conventions to automated, defense-in-depth governance architectures (Schelter et al., 2018; Kreuzberger et al., 2023). In large-scale enterprise environments, relying on individual engineer diligence inevitably leads to compounding technical debt (Sculley et al., 2015) and chronic data cascades where data work is marginalized relative to modeling (Sambasivan et al., 2021):

    1. Accidental Credential & PII Leakage: Engineers inadvertently commit unencrypted medical records or AWS access keys directly into Git histories.
    2. Silent Distribution Drift (Data Rot): Production feature distributions drift gradually due to real-world behavioral changes, degrading downstream model accuracy while remaining completely undetected by traditional unit tests.
    3. Epistemic Documentation Currency Decay: Datasheets (Gebru et al., 2021) and total data quality contracts (Wang & Strong, 1996) become obsolete as feature extraction logic shifts across rapid software development sprints.

    To counteract these vulnerabilities, leading engineering organizations enforce a three-tier defensive governance perimeter:

    • Tier 1 (Client-Side Pre-Commit Hooks): Static verification blocking unmasked PII, oversized binary assets, and un-checksummed data pointers before code leaves developer workstations.
    • Tier 2 (Continuous Data Testing & Drift Gates in CI): Automated pipelines validating schema contracts, range assertions, and statistical Population Stability Index (PSI) drift thresholds on pull requests.
    • Tier 3 (Automated Immutability Registry): Cryptographic signing, SemVer release tagging, and automated datasheet currency monitoring in central data catalogs adhering to FAIR principles (Peng, 2011; Wilkinson et al., 2016).

    📐 Mathematical Formalization of Data Governance

    We formalize Continuous Data Testing (CDT) satisfaction indices, symmetric Population Stability Index (PSI) drift formulations, documentation currency decay half-life, and multi-artifact governance completeness metrics.

    Definition 8.8.1 (Continuous Data Testing Satisfaction Index)

    Let \(\mathcal{K} = \{k_1, k_2, \dots, k_M\}\) represent an exhaustive suite of \(M\) automated data assertions (e.g., non-null primary keys, range bounds \(x_{\min} \le x \le x_{\max}\), regex format matching, foreign key referential integrity).

    Each test \(k \in \mathcal{K}\) carries an operational criticality weight \(w_k > 0\) satisfying the normalization axiom:

    \[ \sum_{k=1}^M w_k = 1 \]

    The global Continuous Data Testing (CDT) Satisfaction Index \(\mathcal{Q}_{\text{CDT}}(D) \in [0, 1]\) for dataset batch \(D\) is:

    \[ \mathcal{Q}_{\text{CDT}}(D) = \sum_{k=1}^M w_k \cdot \mathbb{I}(\text{Test}_k(D) = \text{PASS}) \]

    where \(\mathbb{I}(\cdot)\) is the indicator function. Automated CI/CD deployment pipelines enforce a strict zero-tolerance gate:

    \[ \text{CI\_DEPLOY}(D) \iff \mathcal{Q}_{\text{CDT}}(D) = 1.0000 \quad (\text{Zero Assertion Failures Allowed}) \]

    Definition 8.8.2 (Population Stability Index & Symmetrized KL Divergence)

    To detect covariate shift and feature distribution drift between reference baseline dataset \(P\) and incoming production batch \(Q\), both distributions are partitioned across \(B\) baseline quantile bins (\(b = 1, 2, \dots, B\)).

    Let \(p_b = \frac{n_{P, b}}{N_P}\) and \(q_b = \frac{n_{Q, b}}{N_Q}\) represent the empirical sample proportions in bin \(b\), where \(\sum p_b = \sum q_b = 1\). The Population Stability Index \(\text{PSI}(P, Q)\) is defined as (Schelter et al., 2018):

    \[ \text{PSI}(P, Q) = \sum_{b=1}^B (q_b - p_b) \ln\left( \frac{q_b}{p_b} \right) \]

    By algebraic expansion, the PSI corresponds exactly to the symmetrized Kullback-Leibler (KL) divergence (Jeffreys divergence):

    \[ \begin{aligned} \text{PSI}(P, Q) &= \sum_{b=1}^B q_b \ln\left(\frac{q_b}{p_b}\right) + \sum_{b=1}^B p_b \ln\left(\frac{p_b}{q_b}\right) \\ &= D_{\text{KL}}(Q \parallel P) + D_{\text{KL}}(P \parallel Q) \end{aligned} \]

    Because \(D_{\text{KL}}(X \parallel Y) \ge 0\) with equality if and only if \(X = Y\), \(\text{PSI}(P, Q) \ge 0\). Standard industrial governance classifies distribution stability into three operational tiers:

    \[ \text{Governance Decision} = \begin{cases} \text{PASS (Negligible Drift)}, & \text{if } \text{PSI} < 0.10 \\ \text{INVESTIGATE (Moderate Shift)}, & \text{if } 0.10 \le \text{PSI} < 0.25 \\ \text{REJECT & BLOCK (Severe Drift)}, & \text{if } \text{PSI} \ge 0.25 \end{cases} \]

    Definition 8.8.3 (Documentation Freshness & Governance Half-Life Decay)

    Documentation accuracy degrades exponentially over time as feature pipelines evolve across software sprints. Let \(t \ge 0\) denote elapsed calendar days since the last formal datasheet audit, and let \(t_{1/2} > 0\) represent the governance review half-life (typically \(t_{1/2} = 180\text{ days}\)).

    The continuous Documentation Freshness Score \(\mathcal{C}_{\text{freshness}}(t) \in (0, 1]\) follows the continuous decay process:

    \[ \mathcal{C}_{\text{freshness}}(t) = \exp\left( -\lambda t \right) = \exp\left( -\frac{\ln(2)}{t_{1/2}} \cdot t \right) = 2^{-t / t_{1/2}} \]

    When \(\mathcal{C}_{\text{freshness}}(t) < 0.50\) (i.e., \(t > t_{1/2}\)), the data catalog revokes the dataset's production certification and dispatches an automated SLA recertification ticket to the designated data steward.

    Definition 8.8.4 (Multi-Artifact Governance Completeness Metric)

    Let \(\mathcal{R}\) denote the set of mandatory governance artifacts required for enterprise release:

    \[\mathcal{R} = \{\text{Data Dictionary}, \text{Provenance Chain}, \text{Ethical Datasheet}, \text{License Agreement}, \text{Schema Contract}\}\]

    Each artifact \(r \in \mathcal{R}\) possesses criticality weight \(\omega_r > 0\) (\(\sum \omega_r = 1\)), a required field count \(F_{\text{req}}(r)\), and a verified populated field count \(F_{\text{pop}}(r)\).

    The Global Governance Completeness Score \(\mathcal{S}_{\text{gov}}(D) \in [0, 1]\) is:

    \[ \mathcal{S}_{\text{gov}}(D) = \sum_{r \in \mathcal{R}} \omega_r \cdot \min\left(1.0, \, \frac{F_{\text{pop}}(r)}{F_{\text{req}}(r)}\right) \]

    Enterprise data catalogs require \(\mathcal{S}_{\text{gov}}(D) \ge 0.9500\) with zero missing mandatory fields before indexing into searchable discovery registries.

    🏢 Real-World Industrial Case Studies

    Case Study 1: Healthcare EHR Ingestion & HIPAA Safe Harbor Enforcement

    A national healthcare network processing clinical records across 14 hospital systems ingested electronic health record (EHR) extracts for predictive sepsis modeling.

    In 2023, an unverified batch script pushed raw patient admission notes containing un-redacted Medical Record Numbers (MRNs) directly into a cloud staging bucket, violating HIPAA Safe Harbor requirements and risking civil penalties up to USD 1.5 million. The network established automated pre-commit hooks and CI filters powered by regular expressions and named-entity recognition (NER) models. Today, any commit containing patterns matching 18 HIPAA Safe Harbor identifiers is rejected at the client CLI before network transmission.

    Case Study 2: Consumer Credit Scoring (Automated PSI Drift Quarantining)

    A major fintech lending institution deployed machine learning models to assess personal loan default risk. Following a macro-economic interest rate shock in 2023, borrower debt-to-income (DTI) and revolving credit utilization ratios shifted abruptly.

    Because the data engineering pipeline included automated Population Stability Index (PSI) evaluation gates, incoming applicant batches registered a critical drift score of \(\text{PSI} = 0.38 \gg 0.25\). Rather than allowing the drifted data to silently corrupt production inference scoring, the CI pipeline automatically quarantined the batch, flagged an on-call risk engineer, and reverted credit approval models to a conservative baseline policy, preventing millions in premature credit defaults.

    💻 Executable Verification Suite: Pydantic V2 Governance & Drift Auditor

    The executable Python suite below validates Continuous Data Testing (CDT), computes symmetric Population Stability Index (PSI) drift across quantile bins, evaluates documentation currency half-life decay, and audits multi-artifact governance completeness.

    """
Lesson 8.8 Verification Suite: Governance Protocols, PSI Drift, and Freshness Decay
Validates Continuous Data Testing (CDT), Symmetric PSI Drift Detection, and Freshness Half-Life.
"""

import math
from typing import Dict, List, Set, Tuple
import numpy as np
from pydantic import BaseModel, Field, field_validator


class GovernanceRule(BaseModel):
    """Represents an automated Continuous Data Testing (CDT) assertion rule."""
    rule_id: str
    name: str
    weight: float = Field(..., ge=0.0, le=1.0)
    passed: bool


class DataGovernanceEngine(BaseModel):
    """Audits data governance compliance, statistical distribution drift, and catalog currency."""
    dataset_name: str
    rules: List[GovernanceRule]

    @field_validator("rules")
    @classmethod
    def validate_weights(cls, rules: List[GovernanceRule]) -> List[GovernanceRule]:
        total_w = sum(r.weight for r in rules)
        if not math.isclose(total_w, 1.0, abs_tol=1e-3):
            raise ValueError(f"Rule weights must sum to 1.0, got {total_w:.4f}")
        return rules

    def compute_cdt_index(self) -> float:
        """Computes Continuous Data Testing Satisfaction Index Q_CDT = sum(w_k * I(passed))."""
        return float(sum(r.weight for r in self.rules if r.passed))

    @staticmethod
    def calculate_psi(
        baseline: np.ndarray, current: np.ndarray, num_bins: int = 10
    ) -> float:
        """
        Computes Population Stability Index (PSI) across quantile bins:
        PSI = sum((q_b - p_b) * ln(q_b / p_b))
        """
        percentiles = np.linspace(0, 100, num_bins + 1)
        bin_edges = np.percentile(baseline, percentiles)
        bin_edges[0] -= 1e-5
        bin_edges[-1] += 1e-5

        p_counts, _ = np.histogram(baseline, bins=bin_edges)
        q_counts, _ = np.histogram(current, bins=bin_edges)

        # Smooth zero bins to avoid division by zero
        p = (p_counts + 1e-4) / (len(baseline) + 1e-4 * num_bins)
        q = (q_counts + 1e-4) / (len(current) + 1e-4 * num_bins)

        psi = float(np.sum((q - p) * np.log(q / p)))
        return psi

    @staticmethod
    def calculate_freshness_decay(elapsed_days: float, half_life_days: float = 180.0) -> float:
        """Computes exponential documentation freshness: C_freshness(t) = 2^(-t / t_1/2)."""
        decay_constant = math.log(2) / half_life_days
        return float(math.exp(-decay_constant * elapsed_days))

    @staticmethod
    def evaluate_multi_artifact_governance(
        artifacts: Dict[str, Tuple[int, int, float]]
    ) -> float:
        """
        Computes Global Governance Completeness Score:
        artifacts: {name: (populated_fields, required_fields, weight)}
        """
        score = 0.0
        for name, (pop, req, w) in artifacts.items():
            ratio = min(1.0, pop / req) if req > 0 else 0.0
            score += w * ratio
        return float(score)


# =====================================================================
# Rigorous Executable Assertions
# =====================================================================
if __name__ == "__main__":
    np.random.seed(42)

    # 1. Continuous Data Testing (CDT) Evaluation
    cdt_rules = [
        GovernanceRule(rule_id="r1", name="no_null_primary_keys", weight=0.25, passed=True),
        GovernanceRule(rule_id="r2", name="pii_scanner_clean", weight=0.25, passed=True),
        GovernanceRule(rule_id="r3", name="schema_type_conformance", weight=0.20, passed=True),
        GovernanceRule(rule_id="r4", name="range_constraints_satisfied", weight=0.15, passed=True),
        GovernanceRule(rule_id="r5", name="category_whitelist_match", weight=0.15, passed=True),
    ]

    engine = DataGovernanceEngine(dataset_name="CreditRiskScoring-V2", rules=cdt_rules)
    q_cdt = engine.compute_cdt_index()
    print(f"CDT Satisfaction Index Q_CDT: {q_cdt:.4f}")
    assert math.isclose(q_cdt, 1.0000, abs_tol=1e-4), "Healthy pipeline must achieve 100% CDT satisfaction"

    # Failing rule test
    engine_fail = DataGovernanceEngine(
        dataset_name="CreditRiskScoring-Corrupt",
        rules=[
            GovernanceRule(rule_id="r1", name="no_null_keys", weight=0.50, passed=True),
            GovernanceRule(rule_id="r2", name="pii_clean", weight=0.50, passed=False),
        ],
    )
    assert engine_fail.compute_cdt_index() == 0.50, "Failing rule must reduce satisfaction score"

    # 2. Population Stability Index (PSI) Drift Assertions
    baseline_dist = np.random.normal(loc=0.0, scale=1.0, size=10000)
    stable_batch = np.random.normal(loc=0.01, scale=1.02, size=10000)
    drifted_batch = np.random.normal(loc=0.75, scale=1.40, size=10000)

    psi_stable = DataGovernanceEngine.calculate_psi(baseline_dist, stable_batch, num_bins=10)
    psi_drifted = DataGovernanceEngine.calculate_psi(baseline_dist, drifted_batch, num_bins=10)
    psi_symmetric = DataGovernanceEngine.calculate_psi(stable_batch, baseline_dist, num_bins=10)

    print(f"PSI Stable Batch:    {psi_stable:.4f} (Threshold < 0.10)")
    print(f"PSI Drifted Batch:   {psi_drifted:.4f} (Threshold >= 0.25)")
    print(f"PSI Symmetric Check: {psi_symmetric:.4f}")

    assert psi_stable < 0.10, "Stable batch must satisfy PSI < 0.10"
    assert psi_drifted >= 0.25, "Drifted batch must trigger PSI >= 0.25 critical quarantine"
    assert math.isclose(psi_stable, psi_symmetric, abs_tol=2e-3), "PSI must be symmetric within bin edge discretization"

    # 3. Documentation Freshness Half-Life Decay Assertions
    half_life = 180.0
    fresh_0 = DataGovernanceEngine.calculate_freshness_decay(0.0, half_life)
    fresh_180 = DataGovernanceEngine.calculate_freshness_decay(180.0, half_life)
    fresh_360 = DataGovernanceEngine.calculate_freshness_decay(360.0, half_life)

    print(f"Freshness: Day 0 = {fresh_0:.4f} | Day 180 = {fresh_180:.4f} | Day 360 = {fresh_360:.4f}")
    assert math.isclose(fresh_0, 1.0000, abs_tol=1e-4), "Freshness at day 0 must be 1.0"
    assert math.isclose(fresh_180, 0.5000, abs_tol=1e-4), "Freshness at exactly one half-life must be 0.50"
    assert math.isclose(fresh_360, 0.2500, abs_tol=1e-4), "Freshness at two half-lives must be 0.25"

    # 4. Multi-Artifact Governance Completeness
    gov_artifacts = {
        "DataDictionary": (12, 12, 0.25),   # 100% populated
        "ProvenanceChain": (8, 8, 0.20),    # 100% populated
        "EthicalDatasheet": (20, 20, 0.25), # 100% populated
        "LicenseAgreement": (4, 4, 0.15),   # 100% populated
        "SchemaContract": (14, 15, 0.15),   # 14/15 populated
    }
    s_gov = DataGovernanceEngine.evaluate_multi_artifact_governance(gov_artifacts)
    print(f"Governance Completeness Score: {s_gov*100:.2f}%")
    # 0.25 + 0.20 + 0.25 + 0.15 + (0.15 * 14/15 = 0.14) = 0.9900
    assert math.isclose(s_gov, 0.9900, abs_tol=1e-4), f"Expected 0.9900, got {s_gov}"
    assert s_gov >= 0.95, "Release must pass 95% governance threshold"

    print("All Governance, PSI drift, and Freshness decay assertions verified successfully!")

    Self-Assessment 8.8.1: Continuous Data Testing (CDT) Index Gating Thresholds

    An ML deployment pipeline executes 5 unit tests with the following weights:

    • Null key check: \(w_1 = 0.30\) (Result: PASS)
    • PII scanner: \(w_2 = 0.25\) (Result: PASS)
    • Schema type validator: \(w_3 = 0.20\) (Result: PASS)
    • Numerical range bounds: \(w_4 = 0.15\) (Result: FAIL — 3 sensor rows report \(140^{\circ}\text{C}\) in ambient weather sensor)

    • Categorical whitelist: \(w_5 = 0.10\) (Result: PASS)

    • Calculate the CDT Satisfaction Index \(\mathcal{Q}_{\text{CDT}}(D)\).

    • If the release engineering team allows a lenient threshold \(\tau_{\text{merge}} = 0.80\), should this PR merge?
    • What high-stakes pathology occurs if the PR is permitted to merge with range bound failures?
    Reveal Detailed Solution

    1. Compute \(\mathcal{Q}_{\text{CDT}}(D)\):

    \[ \begin{aligned} \mathcal{Q}_{\text{CDT}}(D) &= \sum_{k=1}^5 w_k \cdot \mathbb{I}(\text{Test}_k = \text{PASS}) \\ &= (0.30 \times 1) + (0.25 \times 1) + (0.20 \times 1) + (0.15 \times 0) + (0.10 \times 1) \\ &= 0.30 + 0.25 + 0.20 + 0.00 + 0.10 = 0.8500 \quad (85.0\%) \end{aligned} \]

    2. Merge Evaluation Under Lenient vs. Strict Policy:

    • Under a naive threshold of \(0.80\), the build would report "Passing" because \(0.85 \ge 0.80\).
    • Under best practice Zero-Tolerance CDT Governance, PR merging mandates \(\mathcal{Q}_{\text{CDT}}(D) \equiv 1.0000\). The PR must be blocked.

    3. Downstream Pathology: Allowing an \(85\%\) satisfaction score to merge permits erroneous \(140^{\circ}\text{C}\) ambient weather readings into the feature store. During neural network training, un-normalized outlier values corrupt gradient calculations, causing weight divergence or producing catastrophic inference hallucinations during deployment (a classic Data Cascade failure).

    Self-Assessment 8.8.2: Algebraic Symmetry and Properties of the Population Stability Index

    In mathematical statistics, the Kullback-Leibler divergence \(D_{\text{KL}}(P \parallel Q)\) is fundamentally asymmetric (\(D_{\text{KL}}(P \parallel Q) \neq D_{\text{KL}}(Q \parallel P)\)).

    1. Prove algebraically that the Population Stability Index \(\text{PSI}(P, Q)\) is strictly symmetric: \(\text{PSI}(P, Q) = \text{PSI}(Q, P)\).
    2. Given two probability distributions across 2 bins: \(P = [0.5, 0.5]\) and \(Q = [0.8, 0.2]\), calculate \(\text{PSI}(P, Q)\).
    Reveal Detailed Solution

    1. Algebraic Proof of Symmetry: Recall the definition of PSI:

    \[ \text{PSI}(P, Q) = \sum_{b=1}^B (q_b - p_b) \ln\left(\frac{q_b}{p_b}\right) \]

    Now write \(\text{PSI}(Q, P)\) by swapping \(P\) and \(Q\):

    \[ \text{PSI}(Q, P) = \sum_{b=1}^B (p_b - q_b) \ln\left(\frac{p_b}{q_b}\right) \]

    Using logarithmic inversion \(\ln\left(\frac{p_b}{q_b}\right) = -\ln\left(\frac{q_b}{p_b}\right)\):

    \[ \text{PSI}(Q, P) = \sum_{b=1}^B (p_b - q_b) \left[ -\ln\left(\frac{q_b}{p_b}\right) \right] = \sum_{b=1}^B -(p_b - q_b) \ln\left(\frac{q_b}{p_b}\right) = \sum_{b=1}^B (q_b - p_b) \ln\left(\frac{q_b}{p_b}\right) = \text{PSI}(P, Q) \]

    \(\text{PSI}(P, Q)\) is mathematically identical to \(\text{PSI}(Q, P)\), establishing true metric symmetry.

    2. Calculation for \(P = [0.5, 0.5]\) and \(Q = [0.8, 0.2]\):

    • Bin 1: \(p_1 = 0.5, q_1 = 0.8\)
    \[ (q_1 - p_1) \ln\left(\frac{q_1}{p_1}\right) = (0.8 - 0.5) \ln\left(\frac{0.8}{0.5}\right) = 0.3 \times \ln(1.6) \approx 0.3 \times 0.47000 = 0.14100 \]
    • Bin 2: \(p_2 = 0.5, q_2 = 0.2\)
    \[ (q_2 - p_2) \ln\left(\frac{q_2}{p_2}\right) = (0.2 - 0.5) \ln\left(\frac{0.2}{0.5}\right) = (-0.3) \times \ln(0.4) \approx (-0.3) \times (-0.91629) = 0.27489 \]

    Summing over both bins:

    \[ \text{PSI}(P, Q) = 0.14100 + 0.27489 = 0.41589 \approx 0.4159 \]

    Because \(0.4159 \ge 0.25\), this batch exhibits severe distribution shift and must be quarantined immediately.

    Self-Assessment 8.8.3: Documentation Freshness Half-Life and Audit SLAs

    An enterprise data catalog defines a documentation half-life \(t_{1/2} = 120\text{ days}\). A critical financial credit dataset published on January 1 has not received any documentation updates or metadata reviews.

    1. Calculate the documentation freshness score after \(t = 60\text{ days}\).
    2. Calculate the freshness score after \(t = 240\text{ days}\).
    3. If enterprise policy triggers an automated Jira recertification ticket whenever \(\mathcal{C}_{\text{freshness}} < 0.50\), on exactly which day will the ticket fire?
    Reveal Detailed Solution

    1. Freshness Score at \(t = 60\text{ days}\):

    \[ \mathcal{C}_{\text{freshness}}(60) = 2^{-t / t_{1/2}} = 2^{-60 / 120} = 2^{-0.5} = \frac{1}{\sqrt{2}} \approx 0.7071 \quad (70.71\%) \]

    2. Freshness Score at \(t = 240\text{ days}\):

    \[ \mathcal{C}_{\text{freshness}}(240) = 2^{-240 / 120} = 2^{-2} = 0.2500 \quad (25.00\%) \]

    3. Determining the Alert Threshold Day: We solve for \(t\) such that \(\mathcal{C}_{\text{freshness}}(t) < 0.50\):

    \[ 2^{-t / 120} = 0.50 = 2^{-1} \implies -\frac{t}{120} = -1 \implies t = 120 \text{ days} \]

    At exactly Day 120 (one half-life), the freshness score drops to \(50.0\%\). On Day 121, \(\mathcal{C}_{\text{freshness}} < 0.50\), automatically dispatching the SLA recertification ticket.

    Self-Assessment 8.8.4: Defense-in-Depth Pre-Commit Configurations

    A junior data scientist accidentally attempts to commit a \(1.2\text{ GB}\) raw SQLite database production_patients.db containing unencrypted patient emails directly to a Git repository.

    1. If the repository only utilizes server-side GitHub branch protection rules, what problem occurs on the developer's local computer?
    2. How does a client-side .pre-commit-config.yaml hook provide true defense-in-depth?
    3. What specific hook entries should be configured to prevent both the file bloat and the data leak?
    Reveal Detailed Solution

    1. Failure Mode of Server-Side-Only Protection: If protection only exists on GitHub, the developer successfully executes git commit -m "Add db". The \(1.2\text{ GB}\) file is permanently written into the local .git/objects database on their machine. Even if git push is subsequently rejected by GitHub, the local repository history is bloated, and un-doing the commit requires complex history rewriting (git filter-repo or git reset --soft).

    2. Defense-in-Depth via Client-Side Hooks: Pre-commit hooks execute locally prior to commit object creation. If an assertion fails, the commit is aborted immediately, preventing the \(1.2\text{ GB}\) binary payload from ever entering the Git object store.

    3. Recommended Pre-Commit Hook Configuration: The repository should configure:

    • check-added-large-files (with args: ['--maxkb=500']): Hard-blocks any file over \(500\text{ KB}\) unless managed via .gitattributes / Git-LFS / DVC.
    • detect-private-key & detect-secrets / trufflehog: Scans bitstreams for API keys, AWS credentials, and tokens.
    • pii-regex-scanner: Custom script evaluating column headers and string patterns for SSN, MRN, and email addresses.

    🎯 Pedagogical Rationale & Conceptual Overview

    In contemporary machine learning and artificial intelligence engineering, documentation is frequently mischaracterized as a passive administrative chore performed post hoc. Empirical software studies demonstrate that documentation neglect triggers devastating downstream system pathologies known as Data Cascades (Sambasivan et al., 2021): compounding technical debt where poorly characterized data distributions corrupt model training, invalidate algorithmic fairness audits, and cause catastrophic production failures.

    Effective documentation serves as a rigorous, living sociotechnical interface between raw data curation and downstream automated inference. In formal peer-reviewed literature and industrial production standards, datasets are elevated to primary scientific objects (Makonin et al., 2024):

    1. IEEE Data Descriptions Framework: Structured descriptor articles documenting instrumentation, crawl parameters, schema validation, and controlled fault injection.
    2. Gebru et al. (2021) Datasheets for Datasets: A standardized 7-pillar accountability framework modeled after hardware spec sheets in electronics engineering (Gebru et al., 2021).
    3. Mitchell et al. (2019) Model Cards for Model Reporting: Bidirectional lineage contracts ensuring that downstream predictive architectures do not violate the upstream dataset's intended operating domain (Mitchell et al., 2019).

    📐 Mathematical Formalization of Documentation Rigor

    To eliminate subjective ambiguity in documentation auditing, we formalize documentation thoroughness, semantic balance, demographic parity, and temporal degradation using rigorous mathematical metrics.

    Definition 8.4.1 (Gebru 7-Pillar Documentation Completeness Index)

    Let \(\mathcal{P} = \{1, 2, \dots, 7\}\) represent the set of standardized documentation pillars:

    \[\mathcal{P} = \{\text{Motivation}, \text{Composition}, \text{Collection}, \text{Preprocessing}, \text{Uses}, \text{Distribution}, \text{Maintenance}\}\]

    For each pillar \(j \in \mathcal{P}\), let \(Q_j = \{q_{j,1}, q_{j,2}, \dots, q_{j,K_j}\}\) be the set of \(K_j\) normative audit questions, and let \(w_j > 0\) denote the domain importance weight satisfying the normalization axiom:

    \[ \sum_{j=1}^7 w_j = 1 \]

    The intra-pillar fulfillment ratio \(\rho_j(D) \in [0, 1]\) for dataset \(D\) is defined as:

    \[ \rho_j(D) = \frac{1}{K_j} \sum_{k=1}^{K_j} \mathbb{I}(q_{j,k} \text{ is thoroughly answered and verified}) \]

    where \(\mathbb{I}(\cdot)\) is the indicator function. The global Documentation Completeness Index \(\mathcal{C}_{\text{doc}}(D) \in [0, 1]\) is the weighted affine combination:

    \[ \mathcal{C}_{\text{doc}}(D) = \sum_{j=1}^7 w_j \rho_j(D) = \sum_{j=1}^7 w_j \left( \frac{1}{K_j} \sum_{k=1}^{K_j} \mathbb{I}(q_{j,k}) \right) \]

    A dataset achieves Certified Operational Readiness if and only if \(\mathcal{C}_{\text{doc}}(D) \ge \tau_{\text{audit}}\) (typically \(\tau_{\text{audit}} = 0.85\)) with no single pillar falling below \(\rho_j(D) \ge 0.50\).

    Definition 8.4.2 (Sociotechnical Balance & Shannon Section Entropy)

    Comprehensive documentation must avoid disproportionate technical over-indexing (e.g., thousands of words describing tensor reshaping while ignoring human participant consent, licensing restrictions, or societal harm anti-goals).

    Let \(L_j \in \mathbb{N}\) be the verified word or token count of section \(j \in \mathcal{P}\), with total documentation volume \(L_{\text{total}} = \sum_{j=1}^7 L_j\). The empirical pillar probability mass function is:

    \[ p(j) = \frac{L_j}{L_{\text{total}}} \quad \text{where} \quad \sum_{j=1}^7 p(j) = 1 \]

    The Sociotechnical Documentation Entropy \(H(S)\) measured in bits (shannons) is:

    \[ H(S) = - \sum_{j=1}^7 p(j) \log_2 p(j) \]

    with theoretical maximum achieved under the uniform distribution \(p^*(j) = \frac{1}{7}\):

    \[ H_{\max} = \log_2(7) \approx 2.80735 \text{ bits} \]

    The normalized Documentation Equitability Ratio \(\eta(S) \in [0, 1]\) is:

    \[ \eta(S) = \frac{H(S)}{H_{\max}} = \frac{-\sum_{j=1}^7 p(j) \log_2 p(j)}{\log_2(7)} \]

    When \(\eta(S) < 0.75\), the documentation suffers from structural domain skew, signaling insufficient legal, ethical, or maintenance rigor.

    Definition 8.4.3 (Demographic Representation Parity & Total Variation Distance)

    In sociotechnical datasets containing human-centric attributes (demographics, clinical cohorts, speech accents), the Composition section must document sampling fidelity against reference census or real-world distributions.

    Let \(\mathbf{p}_{\text{sample}} = [p_1, p_2, \dots, p_K]^\top\) denote the empirical proportions across \(K\) demographic subgroups, and \(\mathbf{q}_{\text{ref}} = [q_1, q_2, \dots, q_K]^\top\) denote the ground-truth reference distribution (\(\sum p_k = \sum q_k = 1\)).

    The Total Variation Distance \(\delta_{\text{TVD}}(\mathbf{p}, \mathbf{q}) \in [0, 1]\) between observed and reference distributions is:

    \[ \delta_{\text{TVD}}(\mathbf{p}_{\text{sample}}, \mathbf{q}_{\text{ref}}) = \frac{1}{2} \sum_{k=1}^K |p_k - q_k| = \max_{A \subseteq \{1,\dots,K\}} \left| \sum_{k \in A} p_k - \sum_{k \in A} q_k \right| \]

    The Demographic Representation Parity \(\mathcal{P}_{\text{demo}}(D)\) is the complementary metric:

    \[ \mathcal{P}_{\text{demo}}(D) = 1 - \delta_{\text{TVD}}(\mathbf{p}_{\text{sample}}, \mathbf{q}_{\text{ref}}) \in [0, 1] \]

    Datasheets must report \(\mathcal{P}_{\text{demo}}(D)\) alongside intersectional subpopulation sample sizes \(n_k\) to satisfy regulatory accountability standards (Buolamwini & Gebru, 2018).

    Definition 8.4.4 (Continuous & Discrete Documentation Decay under Code Drift)

    Software pipelines, API schemas, and feature extraction routines evolve rapidly. Without continuous documentation testing, the semantic alignment between published datasheets and live codebase reality degrades exponentially.

    In discrete sprint iterations \(t \in \{0, 1, 2, \dots, T\}\) with average per-sprint code drift factor \(\gamma \in (0, 1)\):

    \[ \mathcal{A}_{\text{doc}}(t) = \mathcal{A}_0 \cdot (1 - \gamma)^t \]

    where \(\mathcal{A}_0\) is initial documentation accuracy at release. The Documentation Half-Life \(t_{1/2}\) represents the number of sprints until documentation accuracy drops by 50%:

    \[ t_{1/2} = \frac{\ln(0.5)}{\ln(1 - \gamma)} = \frac{\ln(2)}{-\ln(1 - \gamma)} \approx \frac{\ln(2)}{\gamma} \quad (\text{for } \gamma \ll 1) \]

    In a continuous-time deployment regime with Poisson schema modification events occurring at rate \(\lambda > 0\), the expected documentation alignment satisfies:

    \[ \mathcal{A}_{\text{doc}}(t) = \mathcal{A}_0 e^{-\lambda t} + \sum_{k: t_k \le t} \Delta \mathcal{A}_k e^{-\lambda(t - t_k)} \]

    where \(\Delta \mathcal{A}_k\) denotes the documentation remediation jump executed at commit timestamp \(t_k\).

    Continuous Integration (CI) test gates enforce automated release validation:

    \[ \text{Gate}(D_t) = \begin{cases} \text{PASS}, & \text{if } \mathcal{C}_{\text{doc}}(D_t) \ge \tau_{\text{audit}} \ \land \ \eta(S_t) \ge \eta_{\min} \ \land \ \mathcal{A}_{\text{doc}}(t) \ge \alpha_{\text{crit}} \\ \text{FAIL (Block Build)}, & \text{otherwise} \end{cases} \]

    🏢 Real-World Industrial Case Studies

    Case Study 1: The Hugging Face Hub Dataset Cards & Benchmark Contamination Crisis

    In open-source foundation model engineering, the Hugging Face Hub hosts over \(150,000\) community datasets powering large language model (LLM) instruction tuning. In 2023–2024, uncontrolled web scraping led to widespread benchmark contamination: evaluation test sets from MMLU, GSM8K, and HumanEval were inadvertently blended into training corpora, producing artificially inflated model benchmark scores.

    To restore epistemic integrity, Hugging Face mandated Standardized YAML Dataset Cards based on Gebru et al. datasheets (Mitchell et al., 2019). Cards require machine-readable fields specifying dataset languages, licenses, task categories, demographic annotations, and contamination audit scripts. Automated linters reject submissions that fail to specify language_creators, annotations_creators, and explicitly verified benchmark isolation hashes.

    Case Study 2: Medical AI & FDA Pre-Market Submissions (Gender Shades & Dermatology)

    Buolamwini and Gebru (2018) exposed severe intersectional error rate disparities in commercial facial analysis systems: darker-skinned females suffered error rates up to \(34.7\%\), while lighter-skinned males had error rates under \(0.8\%\). The root cause was an uncharacterized training dataset where over \(75\%\) of instances were light-skinned subjects.

    When the FDA established SaMD (Software as a Medical Device) guidelines for clinical machine learning algorithms, they codified Gebru-style Datasheets into pre-market regulatory approval packages. AI diagnostic tools must submit exhaustive documentation detailing participant demographic parity \(\mathcal{P}_{\text{demo}}\), clinical acquisition hardware calibration, exclusion criteria, and ongoing post-market drift surveillance plans.

    💻 Executable Verification Suite: Pydantic V2 Datasheet Auditor

    The executable suite below models the 7 Gebru pillars, computes the Documentation Completeness Index \(\mathcal{C}_{\text{doc}}\), measures Shannon documentation entropy \(H(S)\) and balance \(\eta(S)\), evaluates Total Variation Distance \(\delta_{\text{TVD}}\), and verifies CI/CD build gating.

    """
Lesson 8.4 Verification Suite: Gebru Datasheet Completeness & Documentation Auditor
Validates 7-Pillar Completeness Index, Section Entropy, and Demographic Parity TVD.
"""

import math
from typing import Dict, List, Tuple
import numpy as np
from pydantic import BaseModel, Field, field_validator


class PillarAudit(BaseModel):
    """Represents an audited Gebru Datasheet pillar with weight and verification checks."""
    pillar_id: str
    name: str
    weight: float = Field(..., ge=0.0, le=1.0)
    questions_total: int = Field(..., ge=1)
    questions_verified: int = Field(..., ge=0)

    @property
    def fulfillment_ratio(self) -> float:
        """Computes rho_j = verified / total."""
        return min(1.0, self.questions_verified / self.questions_total)


class DatasheetAuditReport(BaseModel):
    """Audits comprehensive Gebru Datasheet specifications and enforces mathematical bounds."""
    dataset_id: str
    version: str
    pillars: List[PillarAudit]
    word_counts: Dict[str, int]

    @field_validator("pillars")
    @classmethod
    def validate_pillar_weights(cls, pillars: List[PillarAudit]) -> List[PillarAudit]:
        """Ensures the 7 pillar weights sum to 1.0 within numerical tolerance."""
        total_weight = sum(p.weight for p in pillars)
        if not math.isclose(total_weight, 1.0, abs_tol=1e-3):
            raise ValueError(f"Pillar weights must sum to 1.0; current sum = {total_weight:.4f}")
        return pillars

    def compute_completeness_index(self) -> float:
        """Computes global Completeness Index C_doc = sum(w_j * rho_j)."""
        return float(sum(p.weight * p.fulfillment_ratio for p in self.pillars))

    def compute_section_entropy(self) -> Tuple[float, float]:
        """
        Calculates Shannon Section Entropy H(S) and Normalized Equitability Ratio eta(S).
        Returns: (H_bits, eta_ratio).
        """
        counts = [self.word_counts.get(p.pillar_id, 0) for p in self.pillars]
        total_words = sum(counts)
        if total_words == 0:
            return 0.0, 0.0

        p = np.array([c / total_words for c in counts], dtype=float)
        p_nonzero = p[p > 0]
        h_bits = float(-np.sum(p_nonzero * np.log2(p_nonzero)))
        h_max = math.log2(len(self.pillars))
        eta = float(h_bits / h_max) if h_max > 0 else 0.0
        return h_bits, eta

    @staticmethod
    def compute_demographic_parity(
        sample_counts: np.ndarray, reference_distribution: np.ndarray
    ) -> Tuple[float, float]:
        """
        Calculates Total Variation Distance (TVD) and Demographic Representation Parity.
        Returns: (TVD, Parity).
        """
        sample_props = sample_counts / np.sum(sample_counts)
        tvd = float(0.5 * np.sum(np.abs(sample_props - reference_distribution)))
        parity = float(1.0 - tvd)
        return tvd, parity

    @staticmethod
    def simulate_documentation_decay(
        initial_acc: float, drift_rate: float, sprints: int
    ) -> List[float]:
        """Simulates discrete epistemic decay A_doc(t) = A_0 * (1 - gamma)^t."""
        return [float(initial_acc * ((1.0 - drift_rate) ** t)) for t in range(sprints + 1)]

    def evaluate_ci_cd_gate(
        self,
        tau_completeness: float = 0.85,
        min_equitability: float = 0.80,
        current_decay_acc: float = 0.80,
        crit_decay_threshold: float = 0.70,
    ) -> Tuple[bool, Dict[str, bool]]:
        """Evaluates CI/CD deployment gating conditions."""
        c_doc = self.compute_completeness_index()
        _, eta = self.compute_section_entropy()

        checks = {
            "completeness_pass": c_doc >= tau_completeness,
            "equitability_pass": eta >= min_equitability,
            "decay_pass": current_decay_acc >= crit_decay_threshold,
            "no_empty_pillars": all(p.fulfillment_ratio >= 0.50 for p in self.pillars),
        }
        gate_passed = all(checks.values())
        return gate_passed, checks


# =====================================================================
# Rigorous Executable Assertions
# =====================================================================
if __name__ == "__main__":
    # Standard Gebru 7-pillar weighting schema
    pillars_sample = [
        PillarAudit(pillar_id="p1", name="Motivation", weight=0.15, questions_total=5, questions_verified=5),
        PillarAudit(pillar_id="p2", name="Composition", weight=0.20, questions_total=8, questions_verified=8),
        PillarAudit(pillar_id="p3", name="Collection", weight=0.15, questions_total=6, questions_verified=5),
        PillarAudit(pillar_id="p4", name="Preprocessing", weight=0.15, questions_total=6, questions_verified=6),
        PillarAudit(pillar_id="p5", name="Uses", weight=0.15, questions_total=5, questions_verified=5),
        PillarAudit(pillar_id="p6", name="Distribution", weight=0.10, questions_total=4, questions_verified=4),
        PillarAudit(pillar_id="p7", name="Maintenance", weight=0.10, questions_total=4, questions_verified=3),
    ]

    word_counts_sample = {
        "p1": 380, "p2": 450, "p3": 410, "p4": 390,
        "p5": 360, "p6": 320, "p7": 310
    }

    report = DatasheetAuditReport(
        dataset_id="MIMIC-IV-EHR-Subcohort",
        version="2.2.0",
        pillars=pillars_sample,
        word_counts=word_counts_sample,
    )

    # Assertion 1: Completeness Index
    c_doc = report.compute_completeness_index()
    print(f"Documentation Completeness Index C_doc: {c_doc:.4f}")
    # Pillar 3: 5/6, Pillar 7: 3/4. Sum = 0.15*(1)+0.20*(1)+0.15*(5/6)+0.15*(1)+0.15*(1)+0.10*(1)+0.10*(3/4) = 0.9500
    assert math.isclose(c_doc, 0.9500, abs_tol=1e-3), f"Expected 0.9500, got {c_doc}"

    # Assertion 2: Shannon Documentation Entropy & Equitability
    h_bits, eta = report.compute_section_entropy()
    h_max = math.log2(7)  # ~2.80735 bits
    print(f"Section Entropy H(S): {h_bits:.4f} bits (Max: {h_max:.4f} bits), Equitability eta: {eta:.4f}")
    assert h_bits > 2.75, "Balanced datasheet must exhibit near-maximal entropy"
    assert eta > 0.98, f"Equitability ratio must exceed 98%, got {eta:.4f}"

    # Assertion 3: Demographic Parity & Total Variation Distance
    # Census target across 4 cohorts: 25% each
    census_target = np.array([0.25, 0.25, 0.25, 0.25])
    sample_distribution = np.array([250, 250, 240, 260])  # N=1000, props: 0.25, 0.25, 0.24, 0.26
    tvd, parity = report.compute_demographic_parity(sample_distribution, census_target)
    print(f"Demographic TVD: {tvd:.4f}, Parity: {parity:.4f}")
    # TVD = 0.5 * (|0| + |0| + |-0.01| + |0.01|) = 0.0100
    assert math.isclose(tvd, 0.0100, abs_tol=1e-4), f"Expected TVD 0.0100, got {tvd}"
    assert math.isclose(parity, 0.9900, abs_tol=1e-4), f"Expected Parity 0.9900, got {parity}"

    # Assertion 4: Discrete Decay Simulation
    drift_rate = 0.05  # 5% drift per sprint
    decay_curve = report.simulate_documentation_decay(1.0, drift_rate, 12)
    half_life_sprints = math.log(0.5) / math.log(1.0 - drift_rate)
    print(f"Decay after 12 sprints: {decay_curve[12]:.4f}, Half-life: {half_life_sprints:.2f} sprints")
    assert math.isclose(decay_curve[12], (0.95 ** 12), abs_tol=1e-4)
    assert 13.0 < half_life_sprints < 14.0

    # Assertion 5: CI/CD Gating
    passed, checks = report.evaluate_ci_cd_gate(
        tau_completeness=0.85,
        min_equitability=0.80,
        current_decay_acc=decay_curve[4],  # sprint 4 (~0.8145)
        crit_decay_threshold=0.70,
    )
    print("CI/CD Gating Result:", "PASS" if passed else "FAIL", checks)
    assert passed is True, "Healthy documentation audit must pass CI/CD release gate"
    print("All Pydantic V2 Gebru Datasheet mathematical assertions passed successfully!")

    Self-Assessment 8.4.1: Optimizing the Gebru Documentation Completeness Index

    An ML infrastructure team is preparing an open-source instruction-tuning speech corpus. Their audit yields the following fulfillment ratios across the 7 Gebru pillars:

    • Motivation: \(\rho_1 = 1.0\) (\(w_1 = 0.15\))
    • Composition: \(\rho_2 = 0.50\) (\(w_2 = 0.20\))
    • Collection: \(\rho_3 = 0.80\) (\(w_3 = 0.15\))
    • Preprocessing: \(\rho_4 = 1.0\) (\(w_4 = 0.15\))
    • Uses & Anti-Goals: \(\rho_5 = 1.0\) (\(w_5 = 0.15\))
    • Distribution: \(\rho_6 = 1.0\) (\(w_6 = 0.10\))
    • Maintenance: \(\rho_7 = 0.60\) (\(w_7 = 0.10\))

    Calculate the global Documentation Completeness Index \(\mathcal{C}_{\text{doc}}(D)\). If certification requires \(\mathcal{C}_{\text{doc}} \ge 0.85\), does this dataset qualify? How much will completeness increase if they raise Composition fulfillment \(\rho_2\) from \(0.50\) to \(0.90\)?

    Reveal Detailed Solution

    1. Compute Current Completeness Index \(\mathcal{C}_{\text{doc}}(D)\):

    \[ \begin{aligned} \mathcal{C}_{\text{doc}}(D) &= \sum_{j=1}^7 w_j \rho_j \\ &= (0.15 \times 1.0) + (0.20 \times 0.50) + (0.15 \times 0.80) + (0.15 \times 1.0) \\ &\quad + (0.15 \times 1.0) + (0.10 \times 1.0) + (0.10 \times 0.60) \\ &= 0.150 + 0.100 + 0.120 + 0.150 + 0.150 + 0.100 + 0.060 \\ &= 0.8300 \quad (83.00\%) \end{aligned} \]

    Certification Status: Since \(0.8300 < 0.8500\), the dataset fails operational certification by \(2.00\) percentage points.

    2. Remediation Impact on Composition: Because Composition carries weight \(w_2 = 0.20\), an increase \(\Delta \rho_2 = 0.90 - 0.50 = 0.40\) yields:

    \[ \Delta \mathcal{C}_{\text{doc}} = w_2 \cdot \Delta \rho_2 = 0.20 \times 0.40 = +0.0800 \quad (+8.0\%) \]

    The new score becomes:

    \[ \mathcal{C}_{\text{doc}}^{\text{new}} = 0.8300 + 0.0800 = 0.9100 \quad (91.0\%) \]

    This comfortably surpasses the \(85\%\) audit hurdle, demonstrating that remediating heavily weighted structural pillars (Composition \(w_2 = 0.20\)) produces the highest marginal compliance return.

    Self-Assessment 8.4.2: Quantifying Sociotechnical Imbalance via Shannon Entropy

    Suppose Dataset A divides its 2,100 documentation words equally across all 7 Gebru sections (\(300\) words per section). Dataset B devotes \(1,800\) words exclusively to Preprocessing algorithms, with only \(50\) words for each of the other 6 sections (\(1,800 + 6 \times 50 = 2,100\) words total).

    Calculate the Shannon Documentation Entropy \(H(S)\) and Equitability Ratio \(\eta(S)\) for both datasets. What failure mode does Dataset B exhibit?

    Reveal Detailed Solution

    1. Dataset A (Uniform Allocation): Each pillar has proportion \(p_j = \frac{300}{2100} = \frac{1}{7}\).

    \[ H(S_A) = - \sum_{j=1}^7 \frac{1}{7} \log_2\left(\frac{1}{7}\right) = \log_2(7) \approx 2.8074 \text{ bits} \]

    The Equitability Ratio is:

    \[ \eta(S_A) = \frac{H(S_A)}{\log_2(7)} = \frac{2.8074}{2.8074} = 1.0000 \quad (100.0\%) \]

    2. Dataset B (Skewed Technical Over-Indexing):

    • Preprocessing: \(p_{\text{pre}} = \frac{1800}{2100} \approx 0.8571\)
    • Remaining 6 sections: \(p_{\text{other}} = \frac{50}{2100} \approx 0.02381\)
    \[ \begin{aligned} H(S_B) &= - \left[ 0.8571 \log_2(0.8571) + 6 \times \left( 0.02381 \log_2(0.02381) \right) \right] \\ &= - \left[ 0.8571 \times (-0.2224) + 6 \times (0.02381 \times -5.3934) \right] \\ &= - \left[ -0.1906 - 0.7705 \right] = 0.9611 \text{ bits} \end{aligned} \]

    The Equitability Ratio is:

    \[ \eta(S_B) = \frac{0.9611}{2.8074} \approx 0.3423 \quad (34.23\%) \]

    Diagnostic Conclusion: Dataset B exhibits severe technocentric myopia. Despite possessing identical total word count, over \(85\%\) of the text discusses engineering pipelines while legal consent, licensing, demographic sampling, and maintenance sunset clauses receive near-zero attention. Automated CI linters flag this with \(\eta(S_B) = 34.23\% \ll 75\%\).

    Self-Assessment 8.4.3: Total Variation Distance and Demographic Representation Parity

    A medical imaging training set consists of \(N = 4,000\) patient chest X-rays categorized across 4 age demographics:

    • Age Group 1 (18–35): 1,600 samples
    • Age Group 2 (36–50): 1,200 samples
    • Age Group 3 (51–65): 800 samples
    • Age Group 4 (66+): 400 samples

    The regional epidemiological census reveals that clinical hospitalizations in this disease category are uniformly distributed across the 4 age groups (\(25\%\) each).

    1. Compute the empirical sample distribution \(\mathbf{p}_{\text{sample}}\).
    2. Calculate the Total Variation Distance \(\delta_{\text{TVD}}(\mathbf{p}, \mathbf{q})\).
    3. Determine the Demographic Representation Parity \(\mathcal{P}_{\text{demo}}(D)\).
    Reveal Detailed Solution

    1. Empirical Sample Proportions:

    \[ \begin{aligned} p_1 &= \frac{1600}{4000} = 0.40, \quad p_2 = \frac{1200}{4000} = 0.30 \\ p_3 &= \frac{800}{4000} = 0.20, \quad p_4 = \frac{400}{4000} = 0.10 \end{aligned} \]

    Reference target: \(\mathbf{q} = [0.25, 0.25, 0.25, 0.25]^\top\).

    2. Total Variation Distance \(\delta_{\text{TVD}}\):

    \[ \begin{aligned} \delta_{\text{TVD}}(\mathbf{p}, \mathbf{q}) &= \frac{1}{2} \sum_{k=1}^4 |p_k - q_k| \\ &= \frac{1}{2} \left( |0.40 - 0.25| + |0.30 - 0.25| + |0.20 - 0.25| + |0.10 - 0.25| \right) \\ &= \frac{1}{2} \left( 0.15 + 0.05 + 0.05 + 0.15 \right) \\ &= \frac{1}{2} (0.40) = 0.2000 \end{aligned} \]

    3. Demographic Representation Parity \(\mathcal{P}_{\text{demo}}(D)\):

    \[ \mathcal{P}_{\text{demo}}(D) = 1 - \delta_{\text{TVD}}(\mathbf{p}, \mathbf{q}) = 1 - 0.2000 = 0.8000 \quad (80.0\%) \]

    Clinical Consequence: The dataset underrepresents elderly patients (\(66+\), having only \(10\%\) vs. the required \(25\%\)). A model trained on this dataset risks severe diagnostic disparity when deployed in geriatric clinics. The Composition section of the datasheet must record \(\mathcal{P}_{\text{demo}} = 0.8000\) and specify an explicit out-of-scope warning for elderly populations until re-sampling occurs.

    Self-Assessment 8.4.4: Documentation Decay Dynamics and CI/CD Build Gating

    A data science team deploys a dynamic production dataset whose feature extraction schema undergoes continuous updates. Code audits show a per-sprint drift factor \(\gamma = 0.06\) (\(6\%\) per sprint).

    1. Calculate the documentation half-life \(t_{1/2}\) in sprints.
    2. If initial documentation accuracy is \(\mathcal{A}_0 = 0.98\), what will the accuracy be after \(T = 6\) sprints without documentation updates?
    3. If the CI/CD pipeline enforces an automated release block whenever \(\mathcal{A}_{\text{doc}}(t) < 0.75\), during which sprint will the build first fail?
    Reveal Detailed Solution

    1. Documentation Half-Life \(t_{1/2}\):

    \[ t_{1/2} = \frac{\ln(2)}{-\ln(1 - \gamma)} = \frac{\ln(2)}{-\ln(1 - 0.06)} = \frac{0.69315}{-\ln(0.94)} = \frac{0.69315}{0.061875} \approx 11.20 \text{ sprints} \]

    2. Accuracy After \(T = 6\) Sprints:

    \[ \mathcal{A}_{\text{doc}}(6) = \mathcal{A}_0 \cdot (1 - \gamma)^6 = 0.98 \times (0.94)^6 \approx 0.98 \times 0.68987 \approx 0.6761 \quad (67.61\%) \]

    3. Determining the Sprint of CI/CD Failure: We solve for \(t\) such that \(\mathcal{A}_{\text{doc}}(t) < 0.75\):

    \[ \begin{aligned} 0.98 \cdot (0.94)^t &< 0.75 \\ (0.94)^t &< \frac{0.75}{0.98} \approx 0.7653 \\ t \ln(0.94) &< \ln(0.7653) \\ t (-0.061875) &< -0.26747 \\ t &> \frac{-0.26747}{-0.061875} \approx 4.32 \text{ sprints} \end{aligned} \]

    Because sprints are discrete integers, at Sprint 4 the accuracy is \(0.98 \times (0.94)^4 \approx 0.7650 \ge 0.75\) (passing). At Sprint 5, accuracy drops to \(0.98 \times (0.94)^5 \approx 0.7191 < 0.75\).

    Therefore, the automated CI/CD pipeline will first fail and block the release at Sprint 5, forcing engineers to reconcile changed schemas and update the datasheet before merging.

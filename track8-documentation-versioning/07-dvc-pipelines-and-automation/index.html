    🎯 Pedagogical Rationale & Conceptual Overview

    In empirical machine learning and modern data engineering, reproducibility is frequently obstructed by manual, ad-hoc execution scripts (e.g., executing arbitrary shell scripts, unversioned notebooks, or manual database export routines) which incur catastrophic pipeline glue code debt (Sculley et al., 2015). When an engineer tweaks a downstream model hyperparameter, running the entire monolithic pipeline from scratch wastes massive computational energy and introduces non-deterministic execution drift (Peng, 2011; Pacheco et al., 2024).

    To establish industrial-grade reproducibility, scientific computing pioneered declarative workflow engines such as Snakemake (Köster & Rahmann, 2012) and Nextflow (Di Tommaso et al., 2017), coupled with containerized runtimes (Boettiger, 2015) and ML lifecycle platforms (Zaharia et al., 2018). Data Version Control (DVC) translates these declarative principles into Git-native machine learning workflows formalized in dvc.yaml:

    1. Explicit Dependency Graphs: Every computational stage defines explicit inputs (deps: source code, raw data hashes, configuration parameters) and explicit outputs (outs: processed parquet partitions, model weights, evaluation metrics).
    2. Content-Addressed Stage Memoization: By computing a cryptographic stage fingerprint over all inputs and commands, the execution engine bypasses unmodified upstream stages with zero redundant compute.
    3. Automated CI/CD Verification Gates: Pull requests trigger automated dvc repro runs in continuous integration, mathematically verifying whether new data batches degrade model precision or violate schema constraints before merging to main.

    📐 Mathematical Formalization of Pipeline Execution & DAG Memoization

    We formalize cryptographic stage fingerprints, the memoization bypass predicate, Amdahl's pipeline acceleration factor, and critical path makespan scheduling.

    Definition 8.7.1 (Cryptographic Stage Key & Deterministic Fingerprint)

    Let a pipeline DAG be denoted as \(G = (\mathcal{S}, \mathcal{E})\), where vertices \(\mathcal{S} = \{s_1, s_2, \dots, s_n\}\) represent computational stages and directed edges \((s_i, s_j) \in \mathcal{E}\) enforce data dependency ordering.

    For any stage \(s \in \mathcal{S}\), let:

    • \(\text{cmd}(s)\) be the command-line execution string (e.g., python src/train.py --epochs 50),
    • \(\mathcal{C}(s)\) be the cryptographic digest of all source code files invoked by \(s\),
    • \(\boldsymbol{\theta}(s)\) be the serialized hyperparameters specified in params.yaml,
    • \(\mathcal{D}(s) = \{d_1, d_2, \dots, d_m\}\) be the set of input data dependency digests (either raw files or outputs from ancestor stages).

    The Cryptographic Stage Key \(\mathcal{K}_{\text{stage}}(s) \in \{0, 1\}^{256}\) is defined as:

    \[ \mathcal{K}_{\text{stage}}(s) = \text{SHA-256}\left( \text{cmd}(s) \parallel \mathcal{C}(s) \parallel \boldsymbol{\theta}(s) \parallel \bigparallel_{k=1}^m \mathcal{H}(d_k) \right) \]

    where dependencies are sorted deterministically prior to concatenation (\(\parallel\)).

    Definition 8.7.2 (Memoization Bypass Predicate & Cache Lookup)

    Let \(\mathcal{C}_{\text{dvc}}\) denote the set of stage keys previously recorded in the local or remote content-addressable storage cache (dvc.lock).

    When an engineer or automated CI runner invokes dvc repro, the pipeline execution engine evaluates the Memoization Bypass Predicate \(\mathcal{B}(s) \in \{\text{True}, \text{False}\}\):

    \[ \mathcal{B}(s) = \begin{cases} \text{True (Bypass Stage)}, & \text{if } \mathcal{K}_{\text{stage}}(s) \in \mathcal{C}_{\text{dvc}} \ \land \ \forall \, o \in \text{outs}(s) : \mathcal{H}(o) = \mathcal{H}_{\text{expected}}(o) \\ \text{False (Execute Stage)}, & \text{otherwise} \end{cases} \]

    If \(\mathcal{B}(s) = \text{True}\), stage \(s\) consumes \(\mathcal{O}(1)\) time by restoring its cached outputs directly via reflink or hardlink without executing a single instruction of Python code. If \(\mathcal{B}(s) = \text{False}\), stage \(s\) executes, and its new output digests automatically invalidate all downstream descendant stages:

    \[ \mathcal{B}(s) = \text{False} \implies \forall \, s' \in \text{Descendants}(s), \quad \mathcal{B}(s') = \text{False} \]

    Definition 8.7.3 (Amdahl's Pipeline Acceleration Factor)

    Let a pipeline consist of \(n\) stages with baseline execution runtimes \(\tau_1, \tau_2, \dots, \tau_n\), requiring total un-memoized cold-start duration \(T_{\text{cold}} = \sum_{i=1}^n \tau_i\).

    Suppose an incremental code or parameter edit affects only a subset of stages \(\mathcal{S}_{\text{exec}} \subset \mathcal{S}\), while the remaining stages \(\mathcal{S}_{\text{cached}} = \mathcal{S} \setminus \mathcal{S}_{\text{exec}}\) satisfy \(\mathcal{B}(s) = \text{True}\). The cached fraction of computation is:

    \[ f_{\text{cached}} = \frac{\sum_{s \in \mathcal{S}_{\text{cached}}} \tau(s)}{T_{\text{cold}}} \in [0, 1) \]

    The Pipeline Speedup Factor \(\mathcal{S}_{\text{speedup}}\) governed by Amdahl's Law (Amdahl, 1967) is:

    \[ \mathcal{S}_{\text{speedup}} = \frac{T_{\text{cold}}}{T_{\text{memoized}}} = \frac{T_{\text{cold}}}{(1 - f_{\text{cached}})T_{\text{cold}} + \epsilon_{\text{lookup}}} \approx \frac{1}{1 - f_{\text{cached}}} \]

    where \(\epsilon_{\text{lookup}} \approx 0.05\text{s}\) is the negligible hash lookup overhead.

    If heavy raw data ingestion and feature extraction consume \(95\%\) of total pipeline time (\(f_{\text{cached}} = 0.95\)), hyperparameter fine-tuning on the final stage yields an asymptotic speedup of:

    \[ \mathcal{S}_{\text{speedup}} \approx \frac{1}{1 - 0.95} = 20\times \quad (\text{a } 95\%\text{ wall-clock reduction}) \]

    Definition 8.7.4 (DAG Critical Path & Parallel Makespan Scheduling)

    For a pipeline graph \(G = (\mathcal{S}, \mathcal{E})\) scheduled across \(P\) parallel worker nodes, let \(\mathcal{P}\) denote the set of all directed paths from root source nodes to terminal sink nodes:

    \[ \mathcal{P} = \left\{ p = (s_{i_1}, s_{i_2}, \dots, s_{i_k}) \mid (s_{i_j}, s_{i_{j+1}}) \in \mathcal{E} \right\} \]

    The Critical Path Makespan \(T_{\text{crit}}\) is the maximum cumulative execution duration along any path in \(\mathcal{P}\):

    \[ T_{\text{crit}} = \max_{p \in \mathcal{P}} \sum_{s \in p} \tau(s) \]

    Under unbounded parallel compute resources (\(P \to \infty\)), no scheduling algorithm can complete the pipeline faster than the critical path:

    \[ T_{\text{makespan}}(P) \ge T_{\text{crit}} \]

    DVC pipelines maximize concurrency by scheduling independent sibling branches (e.g., parallel feature extractions across disparate modalities) simultaneously on separate worker cores.

    🏢 Real-World Industrial Case Studies

    Case Study 1: Planet Labs Daily Global Satellite Imagery Pipeline

    Planet Labs operates a constellation of over 200 low-Earth orbit satellites imaging the entire global landmass daily, capturing over \(25\text{ Terabytes}\) of multi-spectral orthorectified imagery every 24 hours.

    Retraining agricultural crop stress detection models previously required executing expensive atmospheric surface reflectance calibrations over petabytes of imagery before training deep convolutional neural networks. Planet engineers restructured the pipeline into DVC stages backed by Google Cloud Storage. Because atmospheric calibration outputs are content-addressed, DVC caches the corrected reflectance arrays immutably. When data scientists test novel segmentation architectures, all upstream geospatial calibration stages are bypassed, slashing cloud GPU cluster compute bills by \(68\%\) (> USD 450,000 annual savings).

    Case Study 2: Autonomous Delivery Robot Fleet (Continuous Integration Deployment)

    Nuro operates autonomous delivery bots equipped with radar, LiDAR, and camera vision. ML engineers continuously update pedestrian motion forecasting algorithms.

    To prevent regressions, their GitHub Actions continuous integration suite runs a DVC pipeline upon every pull request. A lightweight test split is processed through dvc repro. If dvc metrics diff detects an increase in average displacement error (\(\Delta \text{ADE} > 0.02\text{m}\)) or if an uncommitted data mutation invalidates dvc.lock, the CI build is hard-blocked. This prevents un-reproducible model weights from contaminating onboard vehicle software releases.

    💻 Executable Verification Suite: Pydantic V2 DVC Pipeline Engine

    The executable Python suite below models declarative DVC stages, computes recursive content-addressed fingerprints, enforces memoization bypass logic, and verifies Amdahl speedup assertions.

    """
Lesson 8.7 Verification Suite: DVC Pipeline DAG & Content-Addressed Execution Engine
Validates Stage Key Hashing, Recursive Dependency Cascades, Memoization Bypass, and Speedups.
"""

import hashlib
from typing import Dict, List, Set, Tuple
from pydantic import BaseModel, Field


class PipelineStage(BaseModel):
    """Represents a single declarative stage in dvc.yaml with inputs, command, and duration."""
    name: str
    cmd: str
    code_hash: str
    params_hash: str
    duration_sec: float = Field(..., ge=0.0)
    deps: List[str] = Field(default_factory=list)


class DVCPipelineEngine(BaseModel):
    """Executes DAG pipelines with content-addressed memoization and stage caching."""
    stages: Dict[str, PipelineStage] = {}
    stage_cache: Set[str] = Field(default_factory=set)

    def register_stage(self, stage: PipelineStage):
        """Adds a pipeline stage to the DAG."""
        self.stages[stage.name] = stage

    def compute_stage_key(self, stage_name: str, external_hashes: Dict[str, str]) -> str:
        """
        Recursively calculates cryptographic stage fingerprint:
        K_stage = SHA-256(cmd || code_hash || params_hash || sorted_ancestor_keys)
        """
        if stage_name not in self.stages:
            raise KeyError(f"Unknown pipeline stage: {stage_name}")

        stage = self.stages[stage_name]
        dep_keys: List[str] = []

        for dep in stage.deps:
            if dep in external_hashes:
                dep_keys.append(f"ext:{dep}={external_hashes[dep]}")
            elif dep in self.stages:
                # Recursively resolve upstream stage fingerprint
                ancestor_key = self.compute_stage_key(dep, external_hashes)
                dep_keys.append(f"stage:{dep}={ancestor_key}")
            else:
                raise ValueError(f"Unresolved dependency '{dep}' for stage '{stage_name}'")

        sorted_deps_str = ";".join(sorted(dep_keys))
        raw_manifest = (
            f"cmd={stage.cmd}|code={stage.code_hash}|params={stage.params_hash}|deps={sorted_deps_str}"
        )
        return hashlib.sha256(raw_manifest.encode("utf-8")).hexdigest()

    def run_repro(self, external_hashes: Dict[str, str]) -> Tuple[float, int, int]:
        """
        Executes dvc repro logic across the DAG.
        Returns: (elapsed_seconds, stages_executed_count, stages_bypassed_count).
        """
        total_elapsed = 0.0
        executed_count = 0
        bypassed_count = 0

        for name, stage in self.stages.items():
            key = self.compute_stage_key(name, external_hashes)
            if key in self.stage_cache:
                # Memoization hit: Bypass execution
                bypassed_count += 1
            else:
                # Memoization miss: Execute stage
                total_elapsed += stage.duration_sec
                executed_count += 1
                self.stage_cache.add(key)

        return total_elapsed, executed_count, bypassed_count

    def compute_critical_path_makespan(self) -> float:
        """Computes sequential critical path makespan across all stages."""
        return sum(s.duration_sec for s in self.stages.values())

# Rigorous Executable Assertions
# =====================================================================
if __name__ == "__main__":
    engine = DVCPipelineEngine()

    # Define standard 4-stage ML pipeline
    engine.register_stage(
        PipelineStage(
            name="ingest",
            cmd="python src/ingest.py",
            code_hash="code_ingest_v1",
            params_hash="p_common_v1",
            duration_sec=25.0,
            deps=["raw_api_source"],
        )
    )
    engine.register_stage(
        PipelineStage(
            name="features",
            cmd="python src/features.py",
            code_hash="code_features_v1",
            params_hash="p_scaler_v1",
            duration_sec=140.0,
            deps=["ingest"],
        )
    )
    engine.register_stage(
        PipelineStage(
            name="train",
            cmd="python src/train.py",
            code_hash="code_train_v1",
            params_hash="p_hyper_v1",
            duration_sec=60.0,
            deps=["features"],
        )
    )
    engine.register_stage(
        PipelineStage(
            name="eval",
            cmd="python src/eval.py",
            code_hash="code_eval_v1",
            params_hash="p_hyper_v1",
            duration_sec=15.0,
            deps=["train", "features"],
        )
    )

    external_data = {"raw_api_source": "hash_s3_raw_2026_q1"}

    # Test Run 1: Cold start (0% cached)
    t1, exec1, byp1 = engine.run_repro(external_data)
    print(f"Run 1 (Cold Start): Elapsed={t1:.1f}s | Executed={exec1} | Bypassed={bypp1 if 'bypp1' in locals() else byp1}")
    assert t1 == 240.0, f"Expected 240.0s (25+140+60+15), got {t1}"
    assert exec1 == 4 and byp1 == 0, "Cold start must execute all 4 stages"

    # Test Run 2: Unchanged rerun (100% memoized bypass)
    t2, exec2, byp2 = engine.run_repro(external_data)
    print(f"Run 2 (Memoized):   Elapsed={t2:.1f}s | Executed={exec2} | Bypassed={byp2}")
    assert t2 == 0.0, "Unchanged run must consume 0.0s compute time"
    assert exec2 == 0 and byp2 == 4, "Unchanged run must bypass all 4 stages"

    # Test Run 3: Modify hyperparameter on 'train' and 'eval' (lr=0.001)
    engine.stages["train"].params_hash = "p_hyper_v2_tuned"
    engine.stages["eval"].params_hash = "p_hyper_v2_tuned"
    t3, exec3, byp3 = engine.run_repro(external_data)
    print(f"Run 3 (Param Tune): Elapsed={t3:.1f}s | Executed={exec3} | Bypassed={byp3}")
    # Ingest (25s) and Features (140s) must be bypassed! Only Train (60s) + Eval (15s) execute = 75s
    assert t3 == 75.0, f"Expected 75.0s, got {t3}"
    assert exec3 == 2 and byp3 == 2, "Stages 1 and 2 must bypass; stages 3 and 4 must execute"

    # Test Run 4: Amdahl speedup factor calculation
    speedup = 240.0 / t3
    print(f"Amdahl Speedup Factor: {speedup:.2f}x (Time saved: {(1 - t3/240.0)*100:.1f}%)")
    assert abs(speedup - 3.20) < 0.01, f"Expected 3.20x speedup, got {speedup}"

    # Test Run 5: Mutate raw data dependency (triggers full cascade)
    external_data["raw_api_source"] = "hash_s3_raw_2026_q2_new_data"
    t5, exec5, byp5 = engine.run_repro(external_data)
    print(f"Run 5 (Data Drift): Elapsed={t5:.1f}s | Executed={exec5} | Bypassed={byp5}")
    assert t5 == 240.0, "Raw data modification must cascade and re-run all 4 stages"
    assert exec5 == 4 and byp5 == 0

    print("All DVC Pipeline and DAG memoization verification assertions verified successfully!")

Self-Assessment 8.7.1: Cryptographic Stage Fingerprints and Memoization Bypass

    In a DVC pipeline, Stage 2 (feature_prep) has dependencies:
    

      

    • Code: src/features.py (\(h_{\text{code}} = \text{3a1f...}\))
      • 

    • Config: params.yaml (\(h_{\text{param}} = \text{b8c2...}\))
      • 

    • Input Data: data/raw.parquet (\(h_{\text{data}} = \text{e491...}\))
      • 

    

    During a team hackathon, an engineer adds an inline comment # Clean outlier bounds to src/features.py without altering any logic or parameters.
    

      

    1. Does \(h_{\text{code}}\) change?
      2. 

    2. Does the cryptographic stage fingerprint \(\mathcal{K}_{\text{stage}}(\text{feature\_prep})\) change?
      3. 

    3. What does dvc repro do when invoked?
      4. 

    4. How can the team prevent innocuous whitespace or comment updates from invalidating heavy stages?
      5. 

    

    
Reveal Detailed Solution

    1. Code Hash Mutation:
Yes. Cryptographic hash functions (SHA-256) evaluate raw file bitstreams. Adding any character (including whitespace or comments) mutates \(h_{\text{code}}\) completely due to the cryptographic avalanche effect.
    

    2. Stage Fingerprint Impact:
Because \(\mathcal{K}_{\text{stage}}\) directly concatenates \(\mathcal{H}(\text{code})\), the stage fingerprint mutates to a new 256-bit hash \(\mathcal{K}' \neq \mathcal{K}\).
    

    3. Execution Behavior:
When dvc repro runs, it queries the local cache dvc.lock. Since \(\mathcal{K}' \notin \mathcal{C}_{\text{dvc}}\), the memoization bypass predicate fails (\(\mathcal{B} = \text{False}\)). DVC is forced to re-execute Stage 2, which then invalidates all downstream stages (train and eval).
    

    4. Best Practice Prevention:
To prevent non-functional comment edits from triggering multi-hour pipeline reruns:
    

      

    • In pre-commit hooks, run code AST (Abstract Syntax Tree) normalizers or formatters (e.g., black, ruff).
      • 

    • In advanced workflow engines, compute stage keys over the serialized Python bytecode (.pyc) or semantic AST hash rather than raw source text.
      • 

    

    

    

    

    
Self-Assessment 8.7.2: Upstream Dependency Cascade Dynamics

    Consider a 4-stage pipeline DAG:
    

    \[\text{Ingestion (30s)} \longrightarrow \text{Preprocessing (180s)} \longrightarrow \text{Training (300s)} \longrightarrow \text{Evaluation (20s)}\]
    

    Total cold-start duration is \(30 + 180 + 300 + 20 = 530\text{ seconds}\).
    

      

    1. If the engineer modifies only the hyperparameter batch_size consumed exclusively by Training, which stages are bypassed and which stages execute? What is the execution time?
      2. 

    2. If a night crawler detects 5 corrupted sensor rows and patches Ingestion, which stages execute? What is the execution time?
      3. 

    

    
Reveal Detailed Solution

    1. Case 1: Hyperparameter Change on Training:
    

      

    • Ingestion: Dependencies unchanged \(\to\) Bypassed (0s).
      • 

    • Preprocessing: Ingestion output unchanged \(\to\) Bypassed (0s).
      • 

    • Training: Parameter hash mutated \(\to\) Executed (300s).
      • 

    • Evaluation: Consumes new model weights from Training \(\to\) Executed (20s).
      • 

    

    Total execution time:
    

    \[
T = 0\text{s} + 0\text{s} + 300\text{s} + 20\text{s} = 320 \text{ seconds}
\]
    

    Time saved: \(530\text{s} - 320\text{s} = 210\text{s}\) (\(39.6\%\) speedup).
    

    2. Case 2: Patch on Ingestion:
    

      

    • Ingestion: Data changed \(\to\) Executed (30s).
      • 

    • Output raw.parquet hash changes, cascading to Preprocessing \(\to\) Executed (180s).
      • 

    • Output features.parquet hash changes, cascading to Training \(\to\) Executed (300s).
      • 

    • Output model changes, cascading to Evaluation \(\to\) Executed (20s).
      • 

    

    Total execution time:
    

    \[
T = 30\text{s} + 180\text{s} + 300\text{s} + 20\text{s} = 530 \text{ seconds} \quad (100\%\text{ full re-run})
\]
    

    Upstream mutations cascade strictly downstream, re-verifying end-to-end data integrity.
    

    

    

    

    
Self-Assessment 8.7.3: Quantifying Amdahl's Acceleration and Developer Iteration Velocity

    A computer vision team trains self-driving object detectors. Their monolithic pipeline takes \(T_{\text{cold}} = 4.0\text{ hours}\) (\(240\text{ minutes}\)):
    

      

    • Video Frame Extraction & Lens Undistortion: 140 minutes
      • 

    • Ground-Truth Bounding Box Alignment & Augmentation: 76 minutes
      • 

    • Neural Network Fine-Tuning: 20 minutes
      • 

    • Mean Average Precision (mAP) Evaluation: 4 minutes
      • 

    

    During hyperparameter optimization, engineers modify only the learning rate and weight decay in the fine-tuning stage.
    

      

    1. Calculate the cached fraction \(f_{\text{cached}}\).
      2. 

    2. Calculate the Amdahl speedup factor \(\mathcal{S}_{\text{speedup}}\).
      3. 

    3. How many experimental iterations can an engineer complete in an 8-hour workday using DVC memoization compared to the naive baseline?
      4. 

    

    
Reveal Detailed Solution

    1. Cached Fraction \(f_{\text{cached}}\):
The bypassed stages are Video Extraction (\(140\text{m}\)) and Augmentation (\(76\text{m}\)):
    

    \[
T_{\text{cached}} = 140 + 76 = 216 \text{ minutes}
\]
    

    \[
f_{\text{cached}} = \frac{216}{240} = 0.90 \quad (90.0\%)
\]
    

    2. Amdahl Speedup Factor:
    

    \[
\mathcal{S}_{\text{speedup}} = \frac{1}{1 - f_{\text{cached}}} = \frac{1}{1 - 0.90} = \frac{1}{0.10} = 10.0\times
\]
    

    Execution time per run drops from \(240\text{ minutes}\) to \(20 + 4 = 24\text{ minutes}\).
    

    3. Workday Iteration Throughput:
    

      

    • Naive Baseline:
      • 

    

    \[
\text{Iterations} = \frac{8 \times 60 \text{ minutes}}{240 \text{ minutes/run}} = 2 \text{ experiments per day}
\]
    

      

    • With DVC Stage Memoization:
First run is cold (\(4.0\text{h}\) or \(240\text{m}\)), leaving \(4.0\text{ hours}\) (\(240\text{m}\)) for iteration:
      • 

    

    \[
\text{Subsequent Runs} = \frac{240 \text{ minutes}}{24 \text{ minutes/run}} = 10 \text{ runs}
\]
    

    Total experiments: \(1 + 10 = 11\) experiments per day.
    

    Conclusion: DVC memoization increases developer experimentation velocity from 2 to 11 iterations per day—a \(5.5\times\) net productivity surge.
    

    

    

    

    
Self-Assessment 8.7.4: Critical Path Makespan Under Parallel Scheduling

    A genomic pipeline DAG has the following stage runtimes and dependencies:
    

      

    • Stage A (Base Ingestion): \(\tau(A) = 10\text{m}\) (no dependencies)
      • 

    • Stage B (Exome Variant Calling): \(\tau(B) = 45\text{m}\) (depends on A)
      • 

    • Stage C (RNA Expression Alignment): \(\tau(C) = 60\text{m}\) (depends on A)
      • 

    • Stage D (Epigenetic Methylation Profiling): \(\tau(D) = 35\text{m}\) (depends on A)
      • 

    • 

      Stage E (Multi-Omic Graph Fusion): \(\tau(E) = 25\text{m}\) (depends on B, C, and D)
      

      • 

    • 

      Enumerate all directed paths from source Stage A to terminal Stage E.
      

      • 

    • Determine the Critical Path and calculate the minimum parallel makespan \(T_{\text{crit}}\).
      • 

    • What is the maximum speedup achievable by provisioning 10 parallel cloud worker cores instead of running sequentially on 1 core?
      • 

    

    
Reveal Detailed Solution

    1. Directed Paths:
    

      

    • Path 1: \(A \to B \to E\)
      • 

    • Path 2: \(A \to C \to E\)
      • 

    • Path 3: \(A \to D \to E\)
      • 

    

    2. Path Durations and Critical Path:
    

    \[
\begin{aligned}
T(P_1) &= \tau(A) + \tau(B) + \tau(E) = 10 + 45 + 25 = 80 \text{ minutes} \\
T(P_2) &= \tau(A) + \tau(C) + \tau(E) = 10 + 60 + 25 = 95 \text{ minutes} \\
T(P_3) &= \tau(A) + \tau(D) + \tau(E) = 10 + 35 + 25 = 70 \text{ minutes}
\end{aligned}
\]
    

    The Critical Path is Path 2 (\(A \to C \to E\)).
    

    \[
T_{\text{crit}} = \max(80, 95, 70) = 95 \text{ minutes}
\]
    

    3. Parallel Speedup Factor:
Sequential execution duration on 1 core:
    

    \[
T_{\text{seq}} = \tau(A) + \tau(B) + \tau(C) + \tau(D) + \tau(E) = 10 + 45 + 60 + 35 + 25 = 175 \text{ minutes}
\]
    

    Under parallel execution, Stages B, C, and D execute concurrently once Stage A finishes. The makespan is bounded below by \(T_{\text{crit}} = 95\text{ minutes}\).
    

    \[
\mathcal{S}_{\text{parallel}} = \frac{T_{\text{seq}}}{T_{\text{crit}}} = \frac{175}{95} \approx 1.842\times \quad (\text{saving } 80 \text{ minutes})
\]
    

    Even with unlimited cores, the pipeline cannot execute faster than 95 minutes due to the irreducible sequential dependency of Stage C.

    🎯 Conceptual Overview & Derivation

    The Silent Failure Mode of Code-Only CI in Data-Centric Machine Learning

    In classical software engineering, Continuous Integration (CI) guarantees system stability by automatically executing unit and regression test suites against every code commit or pull request. The governing paradigm asserts:

    \[\text{If } \forall \text{ tests } \tau_k, \quad \tau_k(\text{code}) \equiv \text{PASS} \implies \text{System is Healthy}\]

    However, in machine learning and data engineering pipelines, code-only continuous integration is fundamentally insufficient (Sculley et al., 2015; Polyzotis et al., 2017). Unlike traditional deterministic software where functional logic is fixed in source files, machine learning behavior is learned from empirical datasets. Consequently, ML systems experience silent degradation: 1. Zero Runtime Exceptions: A pipeline ingesting corrupted data (e.g., negative physical sensor values, swapped coordinate axes, or unit conversion bugs) executes cleanly from beginning to end without throwing Python exceptions or segfaults. 2. Compounding Data Cascades: Sambasivan et al. (2021) showed that unvalidated upstream dataset anomalies trigger compounding cascades across downstream feature pipelines, causing catastrophic inference failures in production (Sambasivan et al., 2021). 3. Training-Serving Skew & Covariate Shift: Small distributional drifts between historical training partitions and newly ingested live batches degrade neural network accuracy while all unit tests report 100% pass rates (Breck et al., 2019; Kreuzberger et al., 2023).

    To address these vulnerabilities, modern MLOps architectures shift data validation left by coupling Continuous Data Integration (CDI), Continuous Data Testing (CDT), and Continuous Machine Learning (CML) into automated GitHub Actions and GitLab CI workflows (Schelter et al., 2018; Makonin, 2024).

    +---------------------------------------------------------------------------------------------------+
|                        CLASSICAL CODE CI VS. CONTINUOUS DATA INTEGRATION (CDI)                    |
+---------------------------------------------------------------------------------------------------+
| DIMENSION               | CLASSICAL CODE CI (e.g., pytest)     | CONTINUOUS DATA INTEGRATION (CDI)|
+-------------------------+--------------------------------------+----------------------------------+
| Primary Artifact        | Python / Rust / C++ Source Code      | Raw & Transformed Parquet Tables |
| Failure Signature       | Stack traces, non-zero exit codes    | Silent accuracy drop, metric drift|
| Invariant Verified      | Syntactical & functional correctness | Schema contracts & distribution  |
| Core Algorithms         | Mock assertions, regression tests    | Two-Sample KS, PSI, Deequ matrix |
| Merge Gate Target       | Code compilation & code coverage     | Distributional delta & CML F1    |
+---------------------------------------------------------------------------------------------------+

    Mathematical Formulations of Continuous Data Validation and Drift Gates

    To establish rigorous engineering foundations for automated data validation, we formalize four mathematical definitions governing schema contracts, statistical distribution shift metrics, automated CML metric gates, and multi-dimensional quality matrices.

    Definition 13.8.1: Continuous Data Integration (CDI) Pipeline & Schema Contract Invariant

    Let an incoming dataset batch be represented as a finite matrix \(\mathcal{D} = \{\mathbf{x}_1, \mathbf{x}_2, \dots, \mathbf{x}_N\} \subset \mathbb{R}^M\), where each record \(\mathbf{x}_i\) comprises \(M\) named attributes \(\{f_1, f_2, \dots, f_M\}\).

    A Formal Schema Contract \(\Sigma_{\text{contract}}\) is a tuple:

    \[\Sigma_{\text{contract}} = \left\{ \left( f_j, \tau_j, \Omega_j, \epsilon_j^{\text{null}}, \mathcal{U}_j \right) \right\}_{j=1}^M\]

    where: - \(\tau_j\) denotes the strictly enforced data type (e.g., Float64, Int32, Categorical[K]). - \(\Omega_j \subseteq \mathbb{R}\) represents the admissible physical domain (e.g., age \(\in [0, 130]\), probability \(\in [0, 1]\)). - \(\epsilon_j^{\text{null}} \in [0, 1]\) defines the maximum allowable missingness rate (null fraction). - \(\mathcal{U}_j \in \{0, 1\}\) specifies whether attribute \(f_j\) must satisfy strict primary key uniqueness (\(\mathcal{U}_j = 1 \implies \text{cardinality}(\text{Distinct}(f_j)) = N\)).

    The Schema Contract Indicator Operator \(\mathcal{S}_{\text{contract}}(\mathcal{D})\) evaluates whether batch \(\mathcal{D}\) satisfies all structural predicates:

    \[\mathcal{S}_{\text{contract}}(\mathcal{D}) = \prod_{j=1}^M \left[ \mathbb{I}\left( \text{Type}(f_j) = \tau_j \right) \cdot \mathbb{I}\left( \frac{1}{N}\sum_{i=1}^N \mathbb{I}\left( x_{ij} \in \text{Null} \right) \le \epsilon_j^{\text{null}} \right) \cdot \mathbb{I}\left( \forall i, \; x_{ij} \in \Omega_j \right) \cdot \mathbb{I}\left( \mathcal{U}_j \implies \text{IsUnique}(f_j) \right) \right]\]
    The Invariant:

    An automated CDI gate strictly halts execution and rejects any pull request or pipeline run if:

    \[\mathcal{S}_{\text{contract}}(\mathcal{D}) \neq 1\]

    guaranteeing that invalid schemas and malformed types never propagate into model training pipelines (Schelter et al., 2018; Breck et al., 2019).

    Definition 13.8.2: Statistical Distribution Shift Distance Metrics

    Even if a batch strictly satisfies its schema contract (\(\mathcal{S}_{\text{contract}} = 1\)), the underlying statistical distribution can diverge from historical baseline data. We define two complementary mathematical drift metrics:

    1. Two-Sample Kolmogorov-Smirnov (KS) Test:

    Let \(B_{\text{ref}} = \{x_1, \dots, x_n\}\) denote the verified baseline reference distribution, and \(B_{\text{new}} = \{y_1, \dots, y_m\}\) denote the incoming candidate batch for a continuous numerical feature \(f_j\).

    Let \(F_{\text{ref}, n}(t) = \frac{1}{n} \sum_{i=1}^n \mathbb{I}(x_i \le t)\) and \(F_{\text{new}, m}(t) = \frac{1}{m} \sum_{j=1}^m \mathbb{I}(y_j \le t)\) represent the respective empirical cumulative distribution functions (ECDFs). The two-sample KS test statistic \(D_{n, m}\) is defined as the supremum distance:

    \[D_{n, m} = \sup_{t \in \mathbb{R}} \left| F_{\text{ref}, n}(t) - F_{\text{new}, m}(t) \right|\]

    At significance level \(\alpha\) (typically \(\alpha = 0.01\)), the null hypothesis of distributional equivalence \(H_0: F_{\text{ref}} = F_{\text{new}}\) is rejected if \(D_{n, m} > D_{\text{crit}}(\alpha)\), where the asymptotic critical boundary is:

    \[D_{\text{crit}}(\alpha) = c(\alpha) \cdot \sqrt{\frac{n + m}{n \cdot m}}, \quad \text{with } c(0.01) \approx 1.628, \quad c(0.05) \approx 1.358\]
    2. Population Stability Index (PSI):

    To quantify covariate shift across continuous or binned categorical features, the population is partitioned into \(B\) reference quantile bins (typically deciles, \(B = 10\)). Let \(P_b\) and \(Q_b\) denote the fraction of samples in bin \(b\) for the baseline reference and incoming candidate batches, respectively:

    \[P_b = \frac{1}{n} \sum_{i=1}^n \mathbb{I}(x_i \in \text{Bin}_b), \quad Q_b = \frac{1}{m} \sum_{j=1}^m \mathbb{I}(y_j \in \text{Bin}_b)\]

    The Population Stability Index \(\text{PSI}\) is formalized as the symmetric Kullback-Leibler divergence:

    \[\text{PSI}(P, Q) = \sum_{b=1}^B \left( P_b - Q_b \right) \cdot \ln\left( \frac{P_b + \varepsilon}{Q_b + \varepsilon} \right)\]

    where \(\varepsilon > 0\) is a small smoothing constant (e.g., \(10^{-4}\)) preventing division by zero.

    The Industrial Drift Gate Thresholds:
    \[\text{DriftStatus}(\text{PSI}) = \begin{cases} \mathbf{STABLE} \quad (\text{Merge Allowed}), & \text{PSI} < 0.10 \\ \mathbf{MONITOR} \quad (\text{Warning / Canary Deploy}), & 0.10 \le \text{PSI} < 0.25 \\ \mathbf{ACTION\_REQUIRED} \quad (\text{Pipeline Blocked}), & \text{PSI} \ge 0.25 \end{cases}\]

    Definition 13.8.3: CML Automated Metric Gate & Pull Request Reporting Invariant

    Continuous Machine Learning (CML) shifts downstream model validation into the Git version control lifecycle.

    Let \(\mathcal{M}\) be a model training and evaluation procedure that produces a validation metric vector:

    \[\mathbf{v}(\mathcal{D}) = \left( \text{F1}(\mathcal{D}), \; \text{Recall}(\mathcal{D}), \; \text{InferenceLatencyMs}(\mathcal{D}) \right) \in \mathbb{R}^3\]

    When a developer opens a pull request altering feature engineering code or proposing an updated dataset snapshot \(\mathcal{D}_{\text{new}}\), the headless CI runner evaluates the CML Gate Indicator Function \(\text{Gate}_{\text{CML}}(\text{PR})\):

    \[\text{Gate}_{\text{CML}}(\text{PR}) = \mathbb{I}\left( \text{F1}(\mathcal{D}_{\text{new}}) - \text{F1}(\mathcal{D}_{\text{ref}}) \ge -\delta_{\text{tol}} \right) \cdot \mathbb{I}\left( \text{Latency}(\mathcal{D}_{\text{new}}) \le \tau_{\text{latency}} \right) \cdot \mathbb{I}\left( \text{PSI}(\mathcal{D}_{\text{ref}}, \mathcal{D}_{\text{new}}) < 0.25 \right)\]

    where \(\delta_{\text{tol}} \ge 0\) is the allowable regression tolerance (e.g., \(0.005\)).

    Pull Request Comment Invariant:

    Under CML, the runner is required to construct and post a deterministic Markdown report \(\mathcal{R}_{\text{CML}}\) containing comparative metrics diffs, visual ROC/PR curves, and drift attribution tables directly into the pull request conversation thread prior to merging (Kreuzberger et al., 2023).

    Definition 13.8.4: Deequ / Great Expectations Multi-Dimensional Quality Constraint Matrix

    Following the foundational data quality framework of Wang & Strong (1996) and its modern distributed realization in Amazon Deequ (Schelter et al., 2018), dataset quality is evaluated across \(K\) orthogonal dimensions: 1. Completeness (\(Q_{\text{comp}}\)): \(1 - \text{NullFraction}\) across non-nullable fields. 2. Uniqueness (\(Q_{\text{uniq}}\)): Ratio of unique primary keys to total cardinality: \(\frac{|\text{Distinct}(\text{PK})|}{N}\). 3. Range Validity (\(Q_{\text{valid}}\)): Fraction of numerical values within admissible physiological or physical bounds. 4. Freshness (\(Q_{\text{fresh}}\)): Exponential recency score: \(Q_{\text{fresh}} = \exp\left( -\lambda \cdot \max(0, \Delta t - t_{\text{expected}}) \right)\).

    We define the Non-Compensatory Harmonic Quality Index \(\mathcal{Q}_{\text{harmonic}}(\mathcal{D})\):

    \[\mathcal{Q}_{\text{harmonic}}(\mathcal{D}) = \frac{K}{\sum_{k=1}^K \frac{1}{Q_k(\mathcal{D}) + \varepsilon}}\]
    Non-Compensatory Axiom:

    Unlike an arithmetic mean where a 100% score in uniqueness compensates for a 0% score in completeness, the harmonic formulation ensures that if any single quality dimension collapses towards zero (\(Q_k \to 0\)), the overall dataset score collapses:

    \[\lim_{Q_k \to 0} \mathcal{Q}_{\text{harmonic}}(\mathcal{D}) = 0\]

    guaranteeing that datasets with critical single-pillar vulnerabilities fail automated CI integration immediately (Wang & Strong, 1996; Schelter et al., 2018).

    💻 Runnable Executable Python Implementation

    The following production-grade implementation, ContinuousDataIntegrationEngine, provides complete mathematical validation for schema contract enforcement, two-sample Kolmogorov-Smirnov drift testing, Population Stability Index (PSI) calculation, and automated CML pull request Markdown report generation.

    """
ContinuousDataIntegrationEngine: Production-grade validation and mathematical testing
for schema contracts, two-sample Kolmogorov-Smirnov tests, Population Stability Index (PSI),
and CML automated pull request gating.
"""

from __future__ import annotations
import math
from typing import Dict, List, Optional, Tuple, Any
from enum import Enum
from pydantic import BaseModel, Field, field_validator


class GateStatus(str, Enum):
    PASSED = "PASSED"
    WARNING = "WARNING"
    FAILED = "FAILED"


class ColumnSchema(BaseModel):
    name: str = Field(..., min_length=1)
    expected_type: str = Field(..., description="e.g. float, int, str")
    min_value: Optional[float] = None
    max_value: Optional[float] = None
    max_null_fraction: float = Field(default=0.0, ge=0.0, le=1.0)
    must_be_unique: bool = False


class DatasetBatch(BaseModel):
    batch_id: str
    records: List[Dict[str, Any]]

    @property
    def row_count(self) -> int:
        return len(self.records)


class QualityScores(BaseModel):
    completeness: float = Field(..., ge=0.0, le=1.0)
    uniqueness: float = Field(..., ge=0.0, le=1.0)
    validity: float = Field(..., ge=0.0, le=1.0)
    freshness: float = Field(..., ge=0.0, le=1.0)
    harmonic_mean: float = Field(..., ge=0.0, le=1.0)


class DriftReport(BaseModel):
    feature_name: str
    ks_statistic: float
    ks_critical_value: float
    ks_p_value_approx: float
    psi_score: float
    psi_status: str
    is_drift_detected: bool


class CMLGateReport(BaseModel):
    batch_id: str
    schema_passed: bool
    quality_scores: QualityScores
    drift_reports: List[DriftReport]
    baseline_f1: float
    candidate_f1: float
    f1_delta: float
    overall_gate_status: GateStatus
    markdown_pr_comment: str


class ContinuousDataIntegrationEngine:
    """
    Mathematical engine implementing Definitions 13.8.1 through 13.8.4.
    """

    def __init__(self, schemas: List[ColumnSchema], significance_alpha: float = 0.01):
        self.schemas = {s.name: s for s in schemas}
        self.alpha = significance_alpha

    def validate_schema(self, batch: DatasetBatch) -> Tuple[bool, List[str]]:
        """
        Validates Definition 13.8.1: Schema Contract Invariant S_contract(D) == 1.
        """
        errors: List[str] = []
        n = batch.row_count
        if n == 0:
            return False, ["Batch is empty."]

        for col_name, schema in self.schemas.items():
            vals = [r.get(col_name) for r in batch.records]

            # Check null rate
            null_count = sum(1 for v in vals if v is None)
            null_rate = null_count / n
            if null_rate > schema.max_null_fraction:
                errors.append(f"Column '{col_name}' null fraction {null_rate:.3f} > allowed {schema.max_null_fraction:.3f}")

            # Check non-null values
            non_null_vals = [v for v in vals if v is not None]

            # Check types & bounds
            for idx, v in enumerate(non_null_vals):
                if schema.expected_type in ("float", "int"):
                    if not isinstance(v, (int, float)):
                        errors.append(f"Column '{col_name}' row {idx} invalid type: expected {schema.expected_type}, got {type(v).__name__}")
                        break
                    if schema.min_value is not None and v < schema.min_value:
                        errors.append(f"Column '{col_name}' value {v} < min bound {schema.min_value}")
                        break
                    if schema.max_value is not None and v > schema.max_value:
                        errors.append(f"Column '{col_name}' value {v} > max bound {schema.max_value}")
                        break

            # Check uniqueness
            if schema.must_be_unique:
                if len(set(non_null_vals)) != len(non_null_vals):
                    errors.append(f"Column '{col_name}' violates uniqueness constraint.")

        return len(errors) == 0, errors

    def compute_quality_matrix(self, batch: DatasetBatch) -> QualityScores:
        """
        Computes Definition 13.8.4: Multi-Dimensional Quality Constraint Matrix.
        """
        n = batch.row_count
        if n == 0:
            return QualityScores(completeness=0, uniqueness=0, validity=0, freshness=0, harmonic_mean=0)

        # 1. Completeness: average across columns
        comp_scores = []
        for col_name in self.schemas:
            vals = [r.get(col_name) for r in batch.records]
            comp_scores.append(1.0 - (sum(1 for v in vals if v is None) / n))
        q_comp = sum(comp_scores) / len(comp_scores) if comp_scores else 1.0

        # 2. Uniqueness of primary key (assuming first schema with must_be_unique)
        pk_cols = [c for c, s in self.schemas.items() if s.must_be_unique]
        if pk_cols:
            pk = pk_cols[0]
            vals = [r.get(pk) for r in batch.records if r.get(pk) is not None]
            q_uniq = len(set(vals)) / max(1, len(vals))
        else:
            q_uniq = 1.0

        # 3. Validity: in-bound rate across numerical columns
        valid_counts = 0
        total_checks = 0
        for col_name, schema in self.schemas.items():
            if schema.min_value is not None or schema.max_value is not None:
                for r in batch.records:
                    v = r.get(col_name)
                    if isinstance(v, (int, float)):
                        total_checks += 1
                        in_min = (schema.min_value is None or v >= schema.min_value)
                        in_max = (schema.max_value is None or v <= schema.max_value)
                        if in_min and in_max:
                            valid_counts += 1
        q_valid = (valid_counts / total_checks) if total_checks > 0 else 1.0

        # 4. Freshness: mock perfect freshness
        q_fresh = 0.98

        # Harmonic Mean Formulation (Non-compensatory)
        k = 4.0
        eps = 1e-4
        inv_sum = (1.0 / (q_comp + eps)) + (1.0 / (q_uniq + eps)) + (1.0 / (q_valid + eps)) + (1.0 / (q_fresh + eps))
        q_harmonic = k / inv_sum

        return QualityScores(
            completeness=round(q_comp, 4),
            uniqueness=round(q_uniq, 4),
            validity=round(q_valid, 4),
            freshness=round(q_fresh, 4),
            harmonic_mean=round(q_harmonic, 4)
        )

    @staticmethod
    def compute_two_sample_ks(ref_vals: List[float], new_vals: List[float], alpha: float = 0.01) -> Tuple[float, float, float]:
        """
        Computes Definition 13.8.2: Two-Sample Kolmogorov-Smirnov supremum distance D_nm and critical boundary.
        """
        n = len(ref_vals)
        m = len(new_vals)
        if n == 0 or m == 0:
            return 0.0, 1.0, 1.0

        sorted_ref = sorted(ref_vals)
        sorted_new = sorted(new_vals)

        # Merge unique points to evaluate supremum distance
        all_points = sorted(list(set(sorted_ref + sorted_new)))

        d_max = 0.0
        i, j = 0, 0
        for pt in all_points:
            while i < n and sorted_ref[i] <= pt:
                i += 1
            while j < m and sorted_new[j] <= pt:
                j += 1

            ecdf_ref = i / n
            ecdf_new = j / m
            diff = abs(ecdf_ref - ecdf_new)
            if diff > d_max:
                d_max = diff

        # Critical value boundary at alpha=0.01 (c=1.628) or alpha=0.05 (c=1.358)
        c_alpha = 1.628 if alpha <= 0.01 else 1.358
        d_crit = c_alpha * math.sqrt((n + m) / (n * m))

        # Asymptotic p-value approximation via Kolmogorov distribution
        lambda_val = math.sqrt((n * m) / (n + m)) * d_max
        if lambda_val <= 0:
            p_val = 1.0
        else:
            p_val = 2.0 * math.exp(-2.0 * (lambda_val ** 2))
            p_val = min(1.0, max(0.0, p_val))

        return round(d_max, 4), round(d_crit, 4), round(p_val, 4)

    @staticmethod
    def compute_psi(ref_vals: List[float], new_vals: List[float], num_bins: int = 10) -> Tuple[float, str]:
        """
        Computes Definition 13.8.2: Population Stability Index over quantile bins.
        """
        n = len(ref_vals)
        m = len(new_vals)
        if n == 0 or m == 0:
            return 0.0, "STABLE"

        sorted_ref = sorted(ref_vals)

        # Determine quantile thresholds from reference distribution
        quantiles = [sorted_ref[int(i * n / num_bins)] for i in range(1, num_bins)]

        # Bin frequencies
        def get_bin_counts(vals: List[float], thresholds: List[float]) -> List[int]:
            counts = [0] * (len(thresholds) + 1)
            for v in vals:
                placed = False
                for idx, t in enumerate(thresholds):
                    if v <= t:
                        counts[idx] += 1
                        placed = True
                        break
                if not placed:
                    counts[-1] += 1
            return counts

        ref_counts = get_bin_counts(ref_vals, quantiles)
        new_counts = get_bin_counts(new_vals, quantiles)

        psi = 0.0
        eps = 1e-4
        for r_c, n_c in zip(ref_counts, new_counts):
            p_b = max(eps, r_c / n)
            q_b = max(eps, n_c / m)
            psi += (p_b - q_b) * math.log(p_b / q_b)

        psi = round(psi, 4)
        if psi < 0.10:
            status = "STABLE"
        elif psi < 0.25:
            status = "MONITOR"
        else:
            status = "ACTION_REQUIRED"

        return psi, status

    def evaluate_cml_pull_request(
        self,
        ref_batch: DatasetBatch,
        candidate_batch: DatasetBatch,
        feature_name: str,
        baseline_f1: float,
        candidate_f1: float
    ) -> CMLGateReport:
        """
        Evaluates full end-to-end CDI + CML gate for an incoming Pull Request.
        """
        # 1. Schema check
        schema_ok, errors = self.validate_schema(candidate_batch)

        # 2. Quality matrix
        quality = self.compute_quality_matrix(candidate_batch)

        # 3. Drift analysis on numerical feature
        ref_nums = [float(r[feature_name]) for r in ref_batch.records if r.get(feature_name) is not None]
        cand_nums = [float(r[feature_name]) for r in candidate_batch.records if r.get(feature_name) is not None]

        ks_stat, ks_crit, ks_p = self.compute_two_sample_ks(ref_nums, cand_nums, alpha=self.alpha)
        psi, psi_status = self.compute_psi(ref_nums, cand_nums, num_bins=10)

        is_drift = (ks_stat > ks_crit) or (psi >= 0.25)

        # 4. Model delta
        f1_delta = candidate_f1 - baseline_f1

        # 5. Determine overall gate
        if not schema_ok or quality.harmonic_mean < 0.80 or psi_status == "ACTION_REQUIRED" or f1_delta < -0.01:
            overall = GateStatus.FAILED
        elif psi_status == "MONITOR" or f1_delta < 0.0:
            overall = GateStatus.WARNING
        else:
            overall = GateStatus.PASSED

        # 6. Generate Markdown PR comment
        icon = "✅" if overall == GateStatus.PASSED else ("⚠️" if overall == GateStatus.WARNING else "❌")
        md_comment = f"""### {icon} CML Automated Data & Model Integration Report

**Pull Request Validation Gate: `{overall.value}`**

| Check Category | Metric Evaluated | Observed Value | Threshold Bound | Status |
| :--- | :--- | :--- | :--- | :--- |
| **Schema Contract** | Indicator $S_{{\\text{{contract}}}}$ | {1 if schema_ok else 0} | $\\equiv 1$ | {'PASS' if schema_ok else 'FAIL'} |
| **Quality Matrix** | Harmonic Mean $\\mathcal{{Q}}$ | {quality.harmonic_mean:.3f} | $\\ge 0.850$ | {'PASS' if quality.harmonic_mean >= 0.85 else 'WARN'} |
| **Statistical Drift** | Two-Sample KS $D_{{n,m}}$ | {ks_stat:.4f} (p={ks_p:.4f}) | $D_{{crit}}={ks_crit:.4f}$ | {'PASS' if ks_stat <= ks_crit else 'DRIFT'} |
| **Covariate Shift** | Population Stability Index | {psi:.4f} | $\\text{{PSI}} < 0.100$ | {psi_status} |
| **Downstream Model** | F1-Score Differential | {f1_delta:+.4f} | $\\ge -0.005$ | {'PASS' if f1_delta >= -0.005 else 'REGRESSION'} |

*Automated validation dispatched via Continuous Data Integration (CDI) runner.*
"""
        return CMLGateReport(
            batch_id=candidate_batch.batch_id,
            schema_passed=schema_ok,
            quality_scores=quality,
            drift_reports=[DriftReport(
                feature_name=feature_name,

                ks_p_value_approx=ks_p,
                psi_score=psi,
                psi_status=psi_status,
                is_drift_detected=is_drift
            )],
            baseline_f1=baseline_f1,
            candidate_f1=candidate_f1,
            f1_delta=round(f1_delta, 4),
            overall_gate_status=overall,
            markdown_pr_comment=md_comment
        )

    Exercise 1: Computing Population Stability Index (PSI) Across 5 Decile Bins

    A machine learning feature store monitors an income prediction pipeline. The baseline reference training partition and a newly ingested candidate batch have the following sample distribution percentages across 5 quantile buckets:

    Bucket (\(b\)) Reference Fraction (\(P_b\)) Candidate Fraction (\(Q_b\))
    Bucket 1 0.20 0.10
    Bucket 2 0.20 0.15
    Bucket 3 0.20 0.20
    Bucket 4 0.20 0.25
    Bucket 5 0.20 0.30
    1. Calculate the individual PSI contribution \(\Delta \text{PSI}_b = (P_b - Q_b) \cdot \ln\left(\frac{P_b}{Q_b}\right)\) for each bucket.
    2. Sum the contributions to find the total \(\text{PSI}(P, Q)\).
    3. Using Definition 13.8.2, determine the automated CI traffic-light gate status (STABLE, MONITOR, or ACTION_REQUIRED).
    Reveal Complete Step-by-Step Solution

    Step 1: Calculating Individual Bucket PSI Contributions

    Recall the formulation for each bucket \(b\):

    \[\Delta \text{PSI}_b = (P_b - Q_b) \cdot \ln\left( \frac{P_b}{Q_b} \right)\]

    Let us evaluate each bucket systematically:

    • Bucket 1: \(P_1 - Q_1 = 0.20 - 0.10 = 0.10\), \(\ln\left( \frac{0.20}{0.10} \right) = \ln(2.0) \approx 0.6931 \implies \Delta \text{PSI}_1 = 0.10 \cdot 0.6931 \approx 0.0693\)
    • Bucket 2: \(P_2 - Q_2 = 0.20 - 0.15 = 0.05\), \(\ln\left( \frac{0.20}{0.15} \right) = \ln(1.3333) \approx 0.2877 \implies \Delta \text{PSI}_2 = 0.05 \cdot 0.2877 \approx 0.0144\)
    • Bucket 3: \(P_3 - Q_3 = 0.20 - 0.20 = 0.00\), \(\ln\left( \frac{0.20}{0.20} \right) = \ln(1.0) = 0.0000 \implies \Delta \text{PSI}_3 = 0.00 \cdot 0.0000 = 0.0000\)
    • Bucket 4: \(P_4 - Q_4 = 0.20 - 0.25 = -0.05\), \(\ln\left( \frac{0.20}{0.25} \right) = \ln(0.80) \approx -0.2231 \implies \Delta \text{PSI}_4 = (-0.05) \cdot (-0.2231) \approx 0.0112\)
    • Bucket 5: \(P_5 - Q_5 = 0.20 - 0.30 = -0.10\), \(\ln\left( \frac{0.20}{0.30} \right) = \ln(0.6667) \approx -0.4055 \implies \Delta \text{PSI}_5 = (-0.10) \cdot (-0.4055) \approx 0.0406\)

    Notice that every non-zero contribution \((P_b - Q_b) \cdot \ln(P_b / Q_b)\) is strictly non-negative because \((P_b - Q_b)\) and \(\ln(P_b / Q_b)\) always have the identical algebraic sign!

    Step 2: Summing Total PSI

    \[\text{PSI}(P, Q) = \sum_{b=1}^5 \Delta \text{PSI}_b = 0.0693 + 0.0144 + 0.0000 + 0.0112 + 0.0406 = 0.1355\]

    The total Population Stability Index is 0.1355.

    Step 3: Determining Automated CI Gate Status

    Under the industrial drift thresholds in Definition 13.8.2: - \(\text{PSI} < 0.10 \implies\) STABLE - \(0.10 \le \text{PSI} < 0.25 \implies\) MONITOR (Amber Warning) - \(\text{PSI} \ge 0.25 \implies\) ACTION_REQUIRED (Halt Merge)

    Because \(\text{PSI} = 0.1355\), the automated CDI runner sets status to MONITOR (Amber): the pipeline generates a warning notification and flags the pull request for canary evaluation before wide deployment.

    Exercise 2: Evaluating Two-Sample KS Statistic and Critical Values for an Ingestion Gate

    A streaming pipeline ingests a batch of \(m = 800\) sensor readings to compare against a baseline validation dataset of \(n = 1,200\) samples.

    During evaluation of the empirical cumulative distribution functions: 1. The maximum absolute vertical divergence across all values is observed at \(t = 42.5\text{ PSI}\), where \(F_{\text{ref}}(42.5) = 0.620\) and \(F_{\text{new}}(42.5) = 0.715\). 2. Compute the Two-Sample Kolmogorov-Smirnov test statistic \(D_{n, m}\). 3. Calculate the critical boundary \(D_{\text{crit}}\) at significance level \(\alpha = 0.01\) (using \(c(0.01) = 1.628\)). 4. Decide whether the automated CDI gate should pass or fail this ingestion pull request.

    Reveal Complete Step-by-Step Solution

    Step 1: Calculating the Two-Sample KS Statistic \(D_{n, m}\)

    Under Definition 13.8.2, the KS test statistic is the supremum difference:

    \[D_{n, m} = \sup_{t} |F_{\text{ref}, n}(t) - F_{\text{new}, m}(t)|\]

    At the point of maximal divergence \(t = 42.5\):

    \[D_{n, m} = |0.620 - 0.715| = |-0.095| = 0.0950\]

    Step 2: Calculating the Asymptotic Critical Value \(D_{\text{crit}}\)

    The critical value threshold at \(\alpha = 0.01\) with \(n = 1,200\) and \(m = 800\) is given by:

    \[D_{\text{crit}}(\alpha) = c(\alpha) \cdot \sqrt{\frac{n + m}{n \cdot m}}\]

    Substituting the values:

    \[\frac{n + m}{n \cdot m} = \frac{1,200 + 800}{1,200 \cdot 800} = \frac{2,000}{960,000} = \frac{1}{480} \approx 0.0020833\]
    \[\sqrt{\frac{n + m}{n \cdot m}} = \sqrt{0.0020833} \approx 0.04564\]
    \[D_{\text{crit}}(0.01) = 1.628 \cdot 0.04564 \approx 0.0743\]

    Step 3: Automated Decision and Hypothesis Test

    Comparing the observed test statistic to the critical value:

    \[D_{n, m} = 0.0950 > D_{\text{crit}} = 0.0743\]

    Because the observed supremum distance \(D_{n, m}\) exceeds the critical threshold at the 99% confidence level (\(\alpha = 0.01\)), we strictly reject the null hypothesis of identical distributions (\(H_0\)).

    Decision: The automated CDI gate FAILS the pull request (Exit Code 1), blocking the batch from being merged into the master feature store and alerting the engineering team of significant distributional drift.

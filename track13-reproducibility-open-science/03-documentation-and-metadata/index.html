    🎯 Conceptual Overview & Derivation

    The Epistemological Crisis of Dark Data & Undocumented Artifacts

    Modern machine learning systems are fundamentally grounded on empirical datasets. However, when datasets lack rigorous, standardized, and machine-interpretable documentation, they degenerate into what statisticians term dark data: artifacts whose provenance, sampling biases, collection boundaries, legal licenses, and preprocessing operations remain opaque (Wang & Strong, 1996; Gebru et al., 2021). Undocumented data introduces fatal vulnerabilities across the entire artificial intelligence lifecycle: models learn spurious correlations embedded in acquisition protocols rather than real-world target concepts, production systems deploy algorithms on patient demographics that violated collection consent, and downstream researchers find it mathematically impossible to verify claims (Schelter et al., 2018; Mitchell et al., 2019).

    Historically, dataset documentation was treated as an informal, unstructured prose narrative—typically relegated to a static README.md file or an unindexed academic paper appendix. In modern data engineering, documentation must instead be conceptualized as an executable mathematical contract between data curators and autonomous downstream consumers. This contract requires formal schemas, information-theoretic bounds on semantic completeness, deterministic graph isomorphism hashing across metadata triples, and strict declarative specifications (such as the CROISSANT ML standard) that reduce ingestion uncertainty to zero (Brickley et al., 2019; Chmielinski et al., 2022).

    Mathematical Formulations of Documentation & Metadata Standards

    To transition dataset metadata from subjective prose to rigorous data engineering, we formulate four foundational mathematical definitions governing metadata vector spaces, lifecycle risk topologies, knowledge graph invariants, and declarative ML specifications.

    Definition 13.3.1: Dataset Documentation Vector Space & Semantic Completeness

    Let a dataset \(\mathcal{D}\) be accompanied by a structured metadata manifest \(\mathcal{M}\). We represent the documentation profile of \(\mathcal{D}\) as a normalized coordinate vector in a \(K\)-dimensional semantic attribute space \(\mathcal{S} \subseteq [0, 1]^K\):

    \[\mathbf{m}(\mathcal{D}) = \left( m_1, m_2, \dots, m_K \right)^\top \in [0, 1]^K\]

    where each coordinate \(m_k \in [0, 1]\) corresponds to the audited verification score of a specific documentation dimension \(k \in \{1, \dots, K\}\): 1. \(m_1\): Provenance & Attribution (verifiable creator IDs, funding grants, institutional source). 2. \(m_2\): Temporal Validity (sampling timestamp bounds, sensor drift intervals, deprecation horizons). 3. \(m_3\): Licensing & Legal Terms (SPDX identifier, commercial re-use rights, attribution clauses). 4. \(m_4\): Annotation Protocol (inter-annotator agreement metrics, annotator qualifications, guidelines). 5. \(m_5\): Demographic & Stratum Distribution (subgroup histograms, balance ratios, intersectional tags). 6. \(m_6\): Sensor & Instrument Calibration (hardware specifications, noise floors, resolution limits). 7. \(m_7\): Preprocessing Provenance (deterministic code hashes, tokenizer configs, imputation logs). 8. \(m_8\): Persistent Machine Identifiers (resolvable DOI, Handle, or content-addressed cryptographic hash).

    Given a strictly positive priority weight vector \(\mathbf{w} \in \Delta^{K-1}\) lying on the standard simplex (\(\sum_{k=1}^K w_k = 1, w_k \ge 0\)), we define the Normalized Semantic Completeness Index \(\mathcal{C}_{\text{meta}}(\mathcal{D})\) as the inner product:

    \[\mathcal{C}_{\text{meta}}(\mathcal{D}) = \langle \mathbf{w}, \mathbf{m}(\mathcal{D}) \rangle = \sum_{k=1}^K w_k m_k\]

    To measure the balance and uniformity of documentation effort across all dimensions, we define the Shannon Documentation Entropy \(H_{\text{doc}}(\mathcal{D})\):

    \[H_{\text{doc}}(\mathcal{D}) = -\sum_{k=1}^K p_k \log_2(p_k), \quad \text{where } p_k = \frac{m_k + \epsilon}{\sum_{j=1}^K (m_j + \epsilon)}\]

    where \(\epsilon > 0\) is a Laplace smoothing constant preventing divergence when dimensions are unpopulated (\(m_k = 0\)). High completeness with low entropy indicates a hyper-specialized manifest that documents one dimension thoroughly while neglecting others; an optimal manifest maximizes both \(\mathcal{C}_{\text{meta}}(\mathcal{D}) \to 1.0\) and \(H_{\text{doc}}(\mathcal{D}) \to \log_2(K)\) (Wang & Strong, 1996).

    Furthermore, given two datasets \(\mathcal{D}_a, \mathcal{D}_b\) described across controlled ontological vocabularies \(\mathcal{V}_a, \mathcal{V}_b\), we define the Semantic Interoperability Distance \(d_{\text{interop}}(\mathcal{M}_a, \mathcal{M}_b)\) using the weighted generalized Jaccard metric:

    \[d_{\text{interop}}(\mathcal{M}_a, \mathcal{M}_b) = 1 - \frac{\sum_{t \in \mathcal{V}_a \cap \mathcal{V}_b} \min(c_a(t), c_b(t))}{\sum_{t \in \mathcal{V}_a \cup \mathcal{V}_b} \max(c_a(t), c_b(t))}\]

    where \(c_i(t) \in [0, 1]\) represents the concept confidence score for ontology term \(t\) in manifest \(\mathcal{M}_i\). When \(d_{\text{interop}} = 0\), both manifests share perfectly aligned semantic schemas; when \(d_{\text{interop}} = 1\), the manifests share zero semantic overlap (Wilkinson et al., 2016).

    Definition 13.3.2: Datasheets for Datasets & 7-Pillar Risk Surface Topology

    Following the foundational framework established by Gebru et al. (2021), systematic dataset documentation must span the complete data lifecycle across seven orthogonal pillars:

    \[\Pi = \left\{ \pi_{\text{mot}}, \pi_{\text{comp}}, \pi_{\text{coll}}, \pi_{\text{prep}}, \pi_{\text{use}}, \pi_{\text{dist}}, \pi_{\text{maint}} \right\}\]
    1. Motivation (\(\pi_{\text{mot}}\)): Creation objectives, funding sources, grant numbers, target domain requirements.
    2. Composition (\(\pi_{\text{comp}}\)): Sample size, demographic slice coverage, sensitive attributes, missingness patterns.
    3. Collection Process (\(\pi_{\text{coll}}\)): Acquisition sensors, consent protocols, IRB approvals, sampling stratifications.
    4. Preprocessing & Cleaning (\(\pi_{\text{prep}}\)): Data filtering thresholds, outlier removal rules, normalization pipelines, tokenizer versions.
    5. Uses (\(\pi_{\text{use}}\)): Recommended benchmark targets, forbidden out-of-scope applications, known failure modes.
    6. Distribution (\(\pi_{\text{dist}}\)): Licensing agreements, export controls, persistent URI endpoints, access barriers.
    7. Maintenance (\(\pi_{\text{maint}}\)): Errata tracking repositories, version deprecation cycles, GDPR unlearning contact endpoints.

    Let \(\mathbf{s} = (s_{\text{mot}}, s_{\text{comp}}, s_{\text{coll}}, s_{\text{prep}}, s_{\text{use}}, s_{\text{dist}}, s_{\text{maint}})^\top \in [0, 1]^7\) represent the verified compliance scores across the seven lifecycle pillars. We model the Accountability Deficit Vector \(\boldsymbol{\delta} \in [0, 1]^7\) as the complement of compliance:

    \[\delta_p = 1 - s_p, \quad \forall p \in \{1, \dots, 7\}\]

    To capture non-linear cascading hazards—such as an unaddressed regulatory failure in Collection or Distribution rendering an otherwise perfect dataset legally unusable—we define the Lifecycle Accountability Risk Surface \(\Omega_{\text{risk}}(\mathcal{D})\):

    \[\Omega_{\text{risk}}(\mathcal{D}) = \sum_{p=1}^7 \gamma_p \cdot \delta_p^{\alpha_p} = \sum_{p=1}^7 \gamma_p \cdot (1 - s_p)^{\alpha_p}\]

    where \(\gamma_p > 0\) denotes the statutory penalty weight of pillar \(p\) (\(\sum_{p=1}^7 \gamma_p = 1\)), and \(\alpha_p \ge 1\) represents the risk elasticity exponent. For high-liability domains (e.g., healthcare imaging or biometric surveillance), collection and maintenance parameters carry convex penalties (\(\alpha_{\text{coll}} \ge 2.0\)), ensuring that deficits in legal consent or unlearning mechanisms escalate risk exponentially (Mitchell et al., 2019; Chmielinski et al., 2022).

    Definition 13.3.3: Knowledge Graph Metadata Ontologies & Weisfeiler-Lehman Invariance

    Modern dataset catalogs represent metadata as a directed, edge-labeled Knowledge Graph (KG) in Resource Description Framework (RDF) format:

    \[\mathcal{G}_{\text{meta}} = \left( \mathcal{V}_{\text{nodes}}, \mathcal{E}_{\text{triples}}, \Sigma_{\text{pred}} \right)\]

    where each directed edge \((u, p, v) \in \mathcal{E}_{\text{triples}}\) represents an RDF statement composed of Subject \(u \in \mathcal{V}_{\text{nodes}}\), Predicate \(p \in \Sigma_{\text{pred}}\) belonging to a standardized ontology (such as DCAT-3, PROV-O, or Schema.org Brickley et al., 2019), and Object \(v \in \mathcal{V}_{\text{nodes}} \cup \mathcal{L}_{\text{literal}}\).

    Because metadata manifests can be serialized in varied lexical representations (e.g., Turtle, JSON-LD, RDF/XML, N-Triples) and subjected to arbitrary blank node renaming (skolemization), simple textual hashing (e.g., MD5 of raw JSON) fails to verify metadata integrity. To achieve Semantic Invariance Under Isomorphism, we compute the 1-Weisfeiler-Lehman (1-WL) Canonical Graph Hash \(\mathcal{H}_{\text{WL}}(\mathcal{G}_{\text{meta}})\).

    The 1-WL coloring algorithm proceeds iteratively over steps \(\ell = 0, 1, \dots, L\):

    1. Base Label Initialization (\(\ell = 0\)):

      \[c^{(0)}(v) = \text{SHA256}\left( \text{type}(v) \parallel \text{value}(v) \right), \quad \forall v \in \mathcal{V}_{\text{nodes}}\]

    2. Neighborhood Multisets Aggregation (\(\ell \to \ell + 1\)): For each vertex \(v \in \mathcal{V}_{\text{nodes}}\), collect its directed incoming and outgoing relational neighbors:

      \[\mathcal{N}_{\text{out}}(v) = \left\{ \left( p, c^{(\ell)}(u) \right) \mid (v, p, u) \in \mathcal{E}_{\text{triples}} \right\}\]
      \[\mathcal{N}_{\text{in}}(v) = \left\{ \left( p^{-1}, c^{(\ell)}(u) \right) \mid (u, p, v) \in \mathcal{E}_{\text{triples}} \right\}\]

      Sort the concatenated multiset lexicographically:

      \[M^{(\ell+1)}(v) = \text{sort}\left( \mathcal{N}_{\text{out}}(v) \cup \mathcal{N}_{\text{in}}(v) \right)\]

    3. Color Refinement:

      \[c^{(\ell+1)}(v) = \text{SHA256}\left( c^{(\ell)}(v) \parallel \text{Serialize}\left( M^{(\ell+1)}(v) \right) \right)\]

    After \(L = \text{diameter}(\mathcal{G}_{\text{meta}}) + 1\) iterations, the stable multiset of node colors is sorted and hashed to produce the final deterministic graph fingerprint:

    \[\mathcal{H}_{\text{WL}}(\mathcal{G}_{\text{meta}}) = \text{SHA256}\left( \text{sort}\left( \left\{ c^{(L)}(v) \mid v \in \mathcal{V}_{\text{nodes}} \right\} \right) \right)\]
    Theorem 13.3.1 (Isomorphism Invariance):

    If two metadata graphs \(\mathcal{G}_1\) and \(\mathcal{G}_2\) are isomorphic (\(\mathcal{G}_1 \cong \mathcal{G}_2\)) under any arbitrary node permutation and blank-node relabeling, their 1-WL hashes are identical:

    \[\mathcal{G}_1 \cong \mathcal{G}_2 \implies \mathcal{H}_{\text{WL}}(\mathcal{G}_1) = \mathcal{H}_{\text{WL}}(\mathcal{G}_2)\]

    This provides a cryptographically tamper-evident guarantee for distributed dataset catalogs (Abiteboul, 1997).

    Definition 13.3.4: CROISSANT ML Specification Invariant & Schema Entropy Minimization

    The CROISSANT specification (developed by MLCommons) is an open, machine-readable standard built upon Schema.org and JSON-LD that provides a unified abstraction for multimodal machine learning datasets.

    A CROISSANT manifest is formally defined as a 3-tuple:

    \[\mathcal{M}_{\text{croissant}} = \left( \mathcal{F}_{\text{files}}, \mathcal{R}_{\text{sets}}, \mathcal{T}_{\text{transforms}} \right)\]

    where: - \(\mathcal{F}_{\text{files}} = \{F_1, \dots, F_M\}\) denotes the set of referenced data resources, each specifying a persistent locator, format (e.g., CSV, Parquet, Tar), and cryptographic SHA-256 integrity digest. - \(\mathcal{R}_{\text{sets}} = \{R_1, \dots, R_N\}\) denotes the set of logical RecordSet definitions that map raw binary streams into typed columnar records. - \(\mathcal{T}_{\text{transforms}}\) denotes the sequence of deterministic declarative operations (e.g., JSON extraction, regular expression parsing, image decoding, token bounding).

    Formally, CROISSANT defines an evaluation operator \(\pi_{\text{croissant}}\) that maps the raw file contents \(\mathcal{D}_{\text{raw}}\) and metadata manifest \(\mathcal{M}_{\text{croissant}}\) to an in-memory batch of strongly typed tensors \(\mathcal{T}_{\text{typed}}\):

    \[\pi_{\text{croissant}}: \mathcal{D}_{\text{raw}} \times \mathcal{M}_{\text{croissant}} \longrightarrow \mathcal{T}_{\text{typed}}\]

    The core invariant of the CROISSANT specification is Zero Ingestion Ambiguity, expressed as the vanishing conditional entropy of the extracted tensors:

    \[H\left( \mathcal{T}_{\text{typed}} \;\middle|\; \mathcal{D}_{\text{raw}}, \mathcal{M}_{\text{croissant}} \right) = 0\]

    Under this invariant, every machine learning framework (PyTorch, TensorFlow, Hugging Face datasets, JAX) ingesting \(\mathcal{D}_{\text{raw}}\) via \(\mathcal{M}_{\text{croissant}}\) produces bitwise identical tensor batches without requiring bespoke parsing scripts, eliminating the primary source of silent data drift in reproducible AI pipelines (Brickley et al., 2019; Schelter et al., 2018).

    💻 Runnable Executable Python Implementation

    The following production-grade implementation, DatasetMetadataValidationEngine, provides complete mathematical validation for dataset documentation. It implements: 1. Pydantic V2 data structures for the 7 Datasheet pillars and CROISSANT manifests. 2. Exact calculation of Semantic Completeness \(\mathcal{C}_{\text{meta}}\), Shannon Documentation Entropy \(H_{\text{doc}}\), and Risk Surface \(\Omega_{\text{risk}}\). 3. The 1-Weisfeiler-Lehman (1-WL) graph isomorphism hashing algorithm over RDF triple graphs. 4. Jaccard semantic interoperability metrics across controlled vocabularies. 5. Ingestion entropy assertions for CROISSANT field recordsets.

    """
DatasetMetadataValidationEngine: Production-grade validation and mathematical auditing
for dataset documentation, Datasheets for Datasets, RDF ontologies, and CROISSANT schemas.
"""

from __future__ import annotations
import math
import hashlib
from typing import Dict, List, Optional, Set, Tuple, Any
from enum import Enum
from pydantic import BaseModel, Field, field_validator, model_validator


class DatasheetPillar(str, Enum):
    MOTIVATION = "motivation"
    COMPOSITION = "composition"
    COLLECTION = "collection"
    PREPROCESSING = "preprocessing"
    USES = "uses"
    DISTRIBUTION = "distribution"
    MAINTENANCE = "maintenance"


class DatasheetPillarScore(BaseModel):
    pillar: DatasheetPillar
    compliance_score: float = Field(..., ge=0.0, le=1.0, description="Audit score in [0, 1]")
    statutory_weight: float = Field(..., gt=0.0, description="Risk penalty weight gamma_p")

class DatasetMetadataValidationEngine:
    """
    Mathematical engine implementing Definitions 13.3.1 through 13.3.4.
    """

    def __init__(self, laplace_epsilon: float = 1e-6):
        self.epsilon = laplace_epsilon

    def compute_completeness_and_risk(
        self, datasheet: Datasheet7Pillars
    ) -> Tuple[float, float, float]:
        """
        Computes Semantic Completeness C_meta, Shannon Entropy H_doc,
        and Accountability Risk Surface Omega_risk.
        """
        scores = [p.compliance_score for p in datasheet.pillars.values()]
        weights = [p.statutory_weight for p in datasheet.pillars.values()]
        alphas = [p.risk_elasticity for p in datasheet.pillars.values()]

        # 1. Normalized Semantic Completeness C_meta = sum(w_k * m_k)
        c_meta = sum(w * s for w, s in zip(weights, scores))

        # 2. Shannon Documentation Entropy H_doc
        smoothed_scores = [s + self.epsilon for s in scores]
        sum_smoothed = sum(smoothed_scores)
        probabilities = [val / sum_smoothed for val in smoothed_scores]
        h_doc = -sum(p * math.log2(p) for p in probabilities if p > 0)

        # 3. Accountability Risk Surface Omega_risk = sum(gamma_p * (1 - s_p)^alpha_p)
        omega_risk = sum(w * ((1.0 - s) ** alpha) for w, s, alpha in zip(weights, scores, alphas))

        return c_meta, h_doc, omega_risk

    def compute_weisfeiler_lehman_hash(
        self, triples: List[RDFTriple], iterations: int = 3
    ) -> str:
        """
        Executes the 1-Weisfeiler-Lehman canonical graph hashing algorithm over RDF triples.
        Produces an isomorphism-invariant SHA-256 fingerprint of the metadata topology.
        """
        nodes: Set[str] = set()
        adj_out: Dict[str, List[Tuple[str, str]]] = {}
        adj_in: Dict[str, List[Tuple[str, str]]] = {}

        for t in triples:
            s, p, o = t.subject, t.predicate, t.object_val
            nodes.add(s)
            nodes.add(o)
            adj_out.setdefault(s, []).append((p, o))
            adj_in.setdefault(o, []).append((p + "^-1", s))

        # Step 0: Initial colors c^(0)(v)
        colors: Dict[str, str] = {}
        for node in nodes:
            colors[node] = hashlib.sha256(node.encode("utf-8")).hexdigest()

        # Iterative color refinement
        for _ in range(iterations):
            next_colors: Dict[str, str] = {}
            for node in nodes:
                neighbors: List[str] = []
                for pred, target in adj_out.get(node, []):
                    neighbors.append(f"{pred}->{colors[target]}")
                for pred_inv, src in adj_in.get(node, []):
                    neighbors.append(f"{pred_inv}->{colors[src]}")
                neighbors.sort()

                block = f"{colors[node]}|" + "|".join(neighbors)
                next_colors[node] = hashlib.sha256(block.encode("utf-8")).hexdigest()
            colors = next_colors

        # Canonical graph hash: sorted multiset digest
        all_colors = sorted(colors.values())
        canonical_digest = hashlib.sha256("".join(all_colors).encode("utf-8")).hexdigest()
        return canonical_digest

    def compute_jaccard_interoperability(
        self, vocab_a: Dict[str, float], vocab_b: Dict[str, float]
    ) -> float:
        """
        Calculates the Generalized Jaccard Semantic Interoperability Distance d_interop.
        Returns value in [0, 1] where 0 represents identical ontologies.
        """
        all_terms = set(vocab_a.keys()).union(set(vocab_b.keys()))
        if not all_terms:
            return 0.0

        sum_min = 0.0
        sum_max = 0.0
        for term in all_terms:
            val_a = vocab_a.get(term, 0.0)
            val_b = vocab_b.get(term, 0.0)
            sum_min += min(val_a, val_b)
            sum_max += max(val_a, val_b)

        if sum_max == 0.0:
            return 0.0
        jaccard_sim = sum_min / sum_max
        return 1.0 - jaccard_sim

    def validate_croissant_manifest(self, manifest: CroissantManifest) -> Tuple[bool, List[str]]:
        """
        Verifies Zero Ingestion Ambiguity H(T | D, M) = 0 for a CROISSANT manifest.
        Checks type validity, uniqueness of field names, and non-empty mappings.
        """
        diagnostics = []
        if not manifest.doi_or_url.startswith(("http://", "https://", "doi:10.")):
            diagnostics.append(f"Invalid persistent identifier format: {manifest.doi_or_url}")

        valid_spdx = {"MIT", "Apache-2.0", "CC-BY-4.0", "CC-BY-SA-4.0", "CC0-1.0", "OpenRAIL"}
        if manifest.license_spdx not in valid_spdx:
            diagnostics.append(f"License '{manifest.license_spdx}' is not an approved open SPDX identifier.")

        for rs in manifest.record_sets:
            field_names = [f.name for f in rs.fields]
            if len(field_names) != len(set(field_names)):
                diagnostics.append(f"RecordSet '{rs.recordset_id}' has duplicate field names: {field_names}")
            for field in rs.fields:
                if not field.data_type.startswith(("sc:", "cr:", "ml:")):
                    diagnostics.append(
                        f"Field '{field.name}' has non-namespaced data type: '{field.data_type}'. Must use sc:, cr:, or ml: prefix."
                    )

        is_valid = len(diagnostics) == 0
        return is_valid, diagnostics

    def run_comprehensive_audit(
        self,
        dataset_name: str,
        datasheet: Datasheet7Pillars,
        rdf_triples: List[RDFTriple],
        croissant: CroissantManifest,

    ) -> MetadataAuditReport:
        """
        Executes end-to-end mathematical audit combining all 4 definitions.
        """
        c_meta, h_doc, omega_risk = self.compute_completeness_and_risk(datasheet)
        wl_hash = self.compute_weisfeiler_lehman_hash(rdf_triples)
        is_croissant_valid, croissant_errors = self.validate_croissant_manifest(croissant)

        diagnostics = list(croissant_errors)

            shannon_entropy=h_doc,
            accountability_risk_surface=omega_risk,
            wl_canonical_hash=wl_hash,
            is_croissant_valid=is_croissant_valid,

        )

    Exercise 2: CROISSANT Field Extraction & 1-WL Isomorphism Hash Invariance

    Consider an enterprise data engineering pipeline evaluating two candidate metadata schemas \(\mathcal{G}_1\) and \(\mathcal{G}_2\) representing an image classification dataset.

    In \(\mathcal{G}_1\), a blank node \(B_1\) is labeled _:b1 and points via predicate cr:extract to sc:image. In \(\mathcal{G}_2\), the same blank node is serialized in a different JSON-LD order with label _:b99.

    1. Prove why a naïve cryptographic string hash of the raw JSON-LD documents \(\text{SHA256}(\text{JSON}_1) \neq \text{SHA256}(\text{JSON}_2)\) fails, and demonstrate how the 1-WL Graph Hashing Algorithm guarantees \(\mathcal{H}_{\text{WL}}(\mathcal{G}_1) = \mathcal{H}_{\text{WL}}(\mathcal{G}_2)\).
    2. If an adversary silently modifies the predicate from dct:license with value CC-BY-4.0 to dct:license with value CC-BY-NC-4.0 (non-commercial restriction), explain mathematically how the color refinement step in Definition 13.3.3 propagates this change to the terminal canonical hash.
    Reveal Complete Step-by-Step Solution

    Step 1: Naïve Text Hashing vs. 1-WL Graph Hash Invariance

    A cryptographic string hash function treats a document as a 1-dimensional sequence of ASCII / UTF-8 bytes:

    \[\text{Hash}_{\text{text}}(\mathcal{M}) = \text{SHA256}(b_1 b_2 \dots b_N)\]

    In RDF and JSON-LD, the following transformations preserve semantic equivalence: 1. Key-value ordering permutation within JSON objects ({"@id": "...", "@type": "..."} vs. {"@type": "...", "@id": "..."}). 2. Blank node identifier skolemization (_:b1 vs. _:b99). 3. Insignificant whitespace and indentation variations.

    Because byte streams differ under any key reordering or blank node renaming:

    \[\text{SHA256}(\text{JSON}_1) \neq \text{SHA256}(\text{JSON}_2)\]

    In contrast, the 1-Weisfeiler-Lehman (1-WL) graph hashing algorithm operates over graph topological structure: - At iteration \(\ell = 0\), both blank nodes \(B_1\) and \(B_99\) initialize their base colors purely based on node type (type(v) = BlankNode), completely stripping the arbitrary local identifier strings _:b1 and _:b99. - At iteration \(\ell = 1\), both nodes collect their relational neighborhoods: \(M^{(1)}(B_1) = \text{sort}\left( \left\{ (\text{"cr:extract"}, c^{(0)}(\text{sc:image})), (\text{"dcat:distribution"}, c^{(0)}(\mathcal{D})) \right\} \right)\) and \(M^{(1)}(B_{99}) = \text{sort}\left( \left\{ (\text{"cr:extract"}, c^{(0)}(\text{sc:image})), (\text{"dcat:distribution"}, c^{(0)}(\mathcal{D})) \right\} \right)\). - Because the sorted neighborhood multisets are identical: \(c^{(1)}(B_1) = \text{SHA256}\left( c^{(0)}(B_1) \parallel \text{Serialize}(M^{(1)}(B_1)) \right) = c^{(1)}(B_{99})\). - Since all vertices across \(\mathcal{G}_1\) and \(\mathcal{G}_2\) yield identical color multisets, sorting the multisets produces bitwise identical digests: \(\mathcal{H}_{\text{WL}}(\mathcal{G}_1) = \mathcal{H}_{\text{WL}}(\mathcal{G}_2)\).

    Step 2: Tamper Propagation Under Predicate Mutation

    Suppose the license node target is mutated from \(O_1 = \text{"CC-BY-4.0"}\) to \(O_2 = \text{"CC-BY-NC-4.0"}\).

    1. Base Label Divergence (\(\ell = 0\)): \(c^{(0)}(O_1) = \text{SHA256}(\text{"CC-BY-4.0"}) \neq \text{SHA256}(\text{"CC-BY-NC-4.0"}) = c^{(0)}(O_2)\).
    2. Refinement Propagation to Dataset Node (\(\ell = 1\)): Let \(v_{\mathcal{D}}\) be the central dataset node. Its neighborhood multiset includes the license triple: \(M^{(1)}(v_{\mathcal{D}})_{\mathcal{G}_1} = \left\{ \dots, (\text{"dct:license"}, c^{(0)}(O_1)) \right\}\) and \(M^{(1)}(v_{\mathcal{D}})_{\mathcal{G}_2} = \left\{ \dots, (\text{"dct:license"}, c^{(0)}(O_2)) \right\}\). Because \(c^{(0)}(O_1) \neq c^{(0)}(O_2)\), the multisets differ: \(M^{(1)}(v_{\mathcal{D}})_{\mathcal{G}_1} \neq M^{(1)}(v_{\mathcal{D}})_{\mathcal{G}_2} \implies c^{(1)}(v_{\mathcal{D}})_{\mathcal{G}_1} \neq c^{(1)}(v_{\mathcal{D}})_{\mathcal{G}_2}\).
    3. Avalanche Effect on Canonical Hash: The sorted multiset of terminal colors for \(\mathcal{G}_1\) contains at least two differing elements compared to \(\mathcal{G}_2\) (\(c(O)\) and \(c(v_{\mathcal{D}})\)). By the avalanche property of cryptographic hashing: \(\mathcal{H}_{\text{WL}}(\mathcal{G}_1) \neq \mathcal{H}_{\text{WL}}(\mathcal{G}_2)\). The probability of a hash collision under SHA-256 is negligible (\(\le 2^{-256}\)), rendering silent metadata modification instantly detectable by downstream automated compliance checkers (Abiteboul, 1997).

    🎯 Conceptual Overview & Derivation

    The Duality of Openness and Quality in Scientific Machine Learning

    The open science movement has democratized artificial intelligence by providing global access to foundational training corpora, clinical cohorts, and scientific benchmarks. However, open access without rigorous quality verification and cryptographic provenance creates catastrophic systemic vulnerabilities (Wang & Strong, 1996; Schelter et al., 2018). When open datasets circulate across internet mirrors and community repositories, unversioned transformations, silent label corruptions, and missing sensor calibrations propagate downstream undetected (Sculley et al., 2015).

    Provenance tracking is the formal mathematical discipline that reconstructs the causal chain of custody: where did data originate, who collected it, what computational transformations altered it, and what downstream artifacts depend upon it? (Moreau et al., 2011; Missier et al., 2013). Without machine-actionable provenance, modern data systems become vulnerable to cascading data poisoning, irreproducible experimental findings, and legal non-compliance (Baggerly & Coombes, 2009).

    +---------------------------------------------------------------------------------------------------+
|                        THE DUALITY OF OPENNESS AND PROVENANCE GOVERNANCE                          |
+---------------------------------------------------------------------------------------------------+
| UNMANAGED OPEN REPOSITORY         | MANAGED PROVENANCE PIPELINE (W3C PROV-O)                      |
| - Unversioned CSV/Tar drops       | - Directed Acyclic Multigraph of Entities, Activities, Agents |
| - Unknown upstream cleaning code  | - Causal Upstream Ancestry Reachability Cones                 |
| - Silent label corruption spreads | - Quantified Downstream Contamination Blast Radius            |
| - Untracked data leakage & drift  | - Cryptographic Merkle Lineage (H(v) = SHA256(Payload || H(u)))|
| - Off-by-one errors fatal         | - Enforced Temporal Consistency (t_gen <= t_start <= t_end)   |
+---------------------------------------------------------------------------------------------------+

    Mathematical Formulations of Dataset Quality & Provenance

    To model data transformation pipelines rigorously, we formulate four foundational mathematical definitions governing directed acyclic provenance multigraphs, causal error propagation, Merkle lineage immutability, and temporal consistency invariants.

    Definition 13.5.1: The W3C PROV Provenance Directed Acyclic Graph (PROV-DAG) & Causal Reachability Cone

    Formally, a dataset provenance trace is modeled as a directed, edge-labeled bipartite multigraph conforming to the World Wide Web Consortium (W3C) PROV specification (Moreau et al., 2011; Missier et al., 2013):

    \[\mathcal{G}_{\text{prov}} = \left( \mathcal{V}_{\text{nodes}}, \mathcal{E}_{\text{edges}}, \tau \right)\]

    where the vertex set \(\mathcal{V}_{\text{nodes}}\) is partitioned into three disjoint canonical classes:

    \[\mathcal{V}_{\text{nodes}} = \mathcal{E}\text{ntity} \;\dot{\cup}\; \mathcal{A}\text{ctivity} \;\dot{\cup}\; \mathcal{A}\text{gent}\]
    1. Entities (\(\mathcal{E}\text{ntity}\)): Physical or digital data artifacts, file shards, feature tensors, and model weights (e.g., raw_data.csv, normalized_tokens.parquet).
    2. Activities (\(\mathcal{A}\text{ctivity}\)): Dynamic computational processes, data transformation jobs, and model training runs occurring over finite time intervals (e.g., clean_text(), train_resnet()).
    3. Agents (\(\mathcal{A}\text{gent}\)): Autonomous actors, human investigators, or automated CI/CD runners bearing responsibility (e.g., DataCurator_Alice, GitHubActions_Runner).

    The directed edges \(\mathcal{E}_{\text{edges}}\) encode causal dependencies: - \(\text{wasGeneratedBy} \subset \mathcal{E}\text{ntity} \times \mathcal{A}\text{ctivity}\) - \(\text{used} \subset \mathcal{A}\text{ctivity} \times \mathcal{E}\text{ntity}\) - \(\text{wasDerivedFrom} \subset \mathcal{E}\text{ntity} \times \mathcal{E}\text{ntity}\) - \(\text{wasAssociatedWith} \subset \mathcal{A}\text{ctivity} \times \mathcal{A}\text{gent}\) - \(\text{wasAttributedTo} \subset \mathcal{E}\text{ntity} \times \mathcal{A}\text{gent}\)

    For any target entity \(e \in \mathcal{E}\text{ntity}\), we define its Upstream Provenance Ancestry Cone \(\mathcal{A}_{\text{up}}(e)\) as the set of all causal ancestors reachable via backward edge traversal:

    \[\mathcal{A}_{\text{up}}(e) = \left\{ u \in \mathcal{V}_{\text{nodes}} \;\middle|\; u \rightsquigarrow e \text{ in } \mathcal{G}_{\text{prov}} \right\}\]

    Conversely, if an entity \(e\) is discovered to be corrupted, poisoned, or revoked under GDPR consent mandates, its Downstream Contamination Blast Radius \(\mathcal{B}_{\text{down}}(e)\) is the topological transitive closure of all affected descendants:

    \[\mathcal{B}_{\text{down}}(e) = \left\{ v \in \mathcal{V}_{\text{nodes}} \;\middle|\; e \rightsquigarrow v \text{ in } \mathcal{G}_{\text{prov}} \right\}\]

    Computing \(\mathcal{B}_{\text{down}}(e)\) enables targeted, minimal-cost invalidation and retraining, eliminating the catastrophic need to tear down unaffected pipeline partitions (Moreau et al., 2011).

    Definition 13.5.2: Causal Quality Attenuation & Error Propagation Bounds

    Let each entity \(e \in \mathcal{E}\text{ntity}\) possess an audited quality metric \(Q(e) \in [0, 1]\) measuring composite data integrity (e.g., signal-to-noise ratio, label fidelity, or completeness Wang & Strong, 1996).

    When an activity \(a \in \mathcal{A}\text{ctivity}\) consumes input entities \(\{e_1, \dots, e_k\}\) via \(\text{used}\) edges to generate an output entity \(e_{\text{out}}\) via \(\text{wasGeneratedBy}\), the transformation is governed by an intrinsic activity fidelity \(\eta_a \in (0, 1]\) and an additive noise injection parameter \(\xi_a \ge 0\):

    \[Q(e_{\text{out}}) = \eta_a \cdot \min_{i=1,\dots,k} Q(e_i) - \xi_a\]
    Theorem 13.5.1 (Upstream Quality Attenuation Bound):

    Consider a composite data processing pipeline forming a linear causal provenance path \(\pi = (e_0, a_1, e_1, a_2, \dots, a_L, e_L)\) of topological depth \(L\). The terminal entity quality \(Q(e_L)\) is strictly bounded by:

    \[Q(e_L) \le Q(e_0) \cdot \prod_{j=1}^L \eta_{a_j} - \sum_{j=1}^L \xi_{a_j} \prod_{m=j+1}^L \eta_{a_m}\]
    Proof:

    By induction on pipeline depth \(L\). For \(L = 1\), \(Q(e_1) = \eta_{a_1} Q(e_0) - \xi_{a_1}\), matching the theorem. Assuming the hypothesis holds for depth \(L - 1\): $\(Q(e_{L-1}) \le Q(e_0) \prod_{j=1}^{L-1} \eta_{a_j} - \sum_{j=1}^{L-1} \xi_{a_j} \prod_{m=j+1}^{L-1} \eta_{a_m}\)$ Applying activity \(a_L\): $\(Q(e_L) = \eta_{a_L} Q(e_{L-1}) - \xi_{a_L} \le \eta_{a_L} \left( Q(e_0) \prod_{j=1}^{L-1} \eta_{a_j} - \sum_{j=1}^{L-1} \xi_{a_j} \prod_{m=j+1}^{L-1} \eta_{a_m} \right) - \xi_{a_L}\)$ Distributing \(\eta_{a_L}\) yields the terminal expression. \(\blacksquare\)

    Corollary 13.5.1 (Exponential Quality Decay):

    If all pipeline activities have identical fidelity \(\eta \in (0, 1)\) and zero additive noise (\(\xi = 0\)), then as pipeline depth \(L \to \infty\): $\(\lim_{L \to \infty} Q(e_L) = Q(e_0) \cdot \lim_{L \to \infty} \eta^L = 0\)$ This proves that unmonitored multi-step preprocessing pipelines inevitably destroy data fidelity unless intermediate activities incorporate active quality restoration filters (\(\eta \ge 1.0\)) (Wang & Strong, 1996; Schelter et al., 2018).

    Definition 13.5.3: Cryptographic Lineage Merkelization & Git-Tree Invariance

    To guarantee immutability against retroactive tampering or silent bit rot in distributed open science repositories, the provenance DAG is mapped to a Directed Acyclic Merkle Graph (DAMG) (Boettiger, 2015; Stodden et al., 2016).

    Each node \(v \in \mathcal{V}_{\text{nodes}}\) is assigned a cryptographic content identifier \(\mathcal{H}(v)\) recursively defined as:

    \[\mathcal{H}(v) = \text{SHA256}\left( \text{Payload}(v) \parallel \text{sort}\left( \left\{ (p, \mathcal{H}(u)) \;\middle|\; (u, p, v) \in \mathcal{E}_{\text{edges}} \right\} \right) \right)\]

    where \(\text{Payload}(v)\) is the byte content of entity \(v\) (or the serialized deterministic execution environment of activity \(v\)), and the incoming parent hashes are sorted lexicographically to preserve isomorphism invariance.

    Theorem 13.5.2 (Cryptographic Tamper-Evidence):

    Let \(\mathcal{G}_{\text{prov}}\) be a Merkle lineage graph. If any upstream raw dataset \(e_0\) or intermediate processing script \(a_k\) undergoes an unrecorded modification of even a single byte:

    \[\Delta \text{Payload}(e_0) \neq 0 \implies \mathcal{H}(e_L)' \neq \mathcal{H}(e_L) \quad \text{with probability } 1 - 2^{-256}\]

    Under the collision-resistance property of SHA-256, finding two distinct dataset pipelines that produce the same terminal model digest is computationally intractable, providing an unbroken cryptographic chain of custody (Boettiger, 2015).

    Definition 13.5.4: W3C PROV-O Constraint Satisfaction & Temporal Consistency Invariants

    In open science, invalid provenance graphs often introduce subtle temporal paradoxes—such as models training on test data that was collected months later, or activities referencing data before it was generated. Formally, a valid W3C PROV trace must satisfy three first-order logic temporal constraints (Moreau et al., 2011; Missier et al., 2013):

    1. Generation-Usage Ordering Constraint: An activity cannot consume an entity before that entity was physically or digitally generated: $\(\forall a \in \mathcal{A}, e \in \mathcal{E}: (a, \text{used}, e) \in \mathcal{E}_{\text{edges}} \implies t_{\text{gen}}(e) \le t_{\text{start}}(a)\)$

    2. Activity Lifetime Invariant: The start of an activity must precede or equal its completion timestamp: $\(\forall a \in \mathcal{A}: t_{\text{start}}(a) \le t_{\text{end}}(a)\)$

    3. Generation-Invalidation Invariant: An entity must be generated before it is invalidated, and cannot be used after invalidation: $\(\forall e \in \mathcal{E}: t_{\text{gen}}(e) \le t_{\text{inval}}(e) \quad \text{and} \quad \forall (a, \text{used}, e): t_{\text{end}}(a) \le t_{\text{inval}}(e)\)$

    Any provenance graph violating these constraints possesses a Temporal Inconsistency Deficit \(\Omega_{\text{temporal}} > 0\). In machine learning pipelines, temporal violations are the primary symptom of catastrophic look-ahead bias and covariate leakage, invalidating empirical performance claims (Sculley et al., 2015).

    💻 Runnable Executable Python Implementation

    The following production-grade implementation, DatasetQualityProvenanceEngine, provides complete mathematical validation for dataset provenance and quality tracking. It implements: 1. Pydantic V2 models for W3C PROV entities, activities, agents, and causal relations. 2. Exact calculation of Upstream Ancestry Cones \(\mathcal{A}_{\text{up}}\) and Downstream Blast Radii \(\mathcal{B}_{\text{down}}\) using breadth-first search. 3. Causal Quality Attenuation tracking implementing Theorem 13.5.1. 4. Cryptographic Merkle lineage hash cascade generation. 5. First-order logic temporal consistency validation and look-ahead paradox detection.

    """
DatasetQualityProvenanceEngine: Production-grade validation and mathematical auditing
for W3C PROV-O multigraphs, causal blast radius bounds, Merkle lineage hashing,
and temporal consistency invariants.
"""

from __future__ import annotations
import math
import hashlib
from typing import Dict, List, Optional, Set, Tuple, Any
from enum import Enum
from pydantic import BaseModel, Field, field_validator, model_validator


class PROVNodeType(str, Enum):
    ENTITY = "Entity"
    ACTIVITY = "Activity"
    AGENT = "Agent"


class PROVEdgeType(str, Enum):
    WAS_GENERATED_BY = "wasGeneratedBy"  # Entity -> Activity
    USED = "used"                          # Activity -> Entity
    WAS_DERIVED_FROM = "wasDerivedFrom"  # Entity -> Entity
    WAS_ASSOCIATED_WITH = "wasAssociatedWith"  # Activity -> Agent
    WAS_ATTRIBUTED_TO = "wasAttributedTo"  # Entity -> Agent


class PROVNode(BaseModel):
    node_id: str = Field(..., min_length=1)
    node_type: PROVNodeType
    payload_hash: str = Field(..., min_length=8, description="Cryptographic SHA-256 of contents/env")
    quality_score: float = Field(default=1.0, ge=0.0, le=1.0, description="Quality metric Q in [0, 1]")
    t_start: Optional[float] = Field(default=None, description="Start timestamp (epoch seconds)")
    t_end: Optional[float] = Field(default=None, description="End / generation timestamp (epoch seconds)")


class PROVEdge(BaseModel):
    source_id: str = Field(..., min_length=1)
    target_id: str = Field(..., min_length=1)
    edge_type: PROVEdgeType
    activity_fidelity: float = Field(default=1.0, ge=0.0, le=1.0, description="Activity fidelity eta")
    noise_injection: float = Field(default=0.0, ge=0.0, description="Additive noise xi")


class BlastRadiusReport(BaseModel):
    corrupted_entity_id: str
    upstream_ancestry_size: int
    upstream_ancestry_nodes: List[str]
    blast_radius_size: int
    blast_radius_nodes: List[str]
    affected_models: List[str]
    terminal_quality: float


class DatasetQualityProvenanceEngine:
    """
    Mathematical engine implementing Definitions 13.5.1 through 13.5.4.
    """

    def __init__(self):
        self.nodes: Dict[str, PROVNode] = {}
        self.edges_out: Dict[str, List[PROVEdge]] = {}
        self.edges_in: Dict[str, List[PROVEdge]] = {}

    def add_node(self, node: PROVNode) -> None:
        self.nodes[node.node_id] = node
        self.edges_out.setdefault(node.node_id, [])
        self.edges_in.setdefault(node.node_id, [])

    def add_edge(self, edge: PROVEdge) -> None:
        if edge.source_id not in self.nodes or edge.target_id not in self.nodes:
            raise ValueError(f"Edge endpoints ({edge.source_id} -> {edge.target_id}) must exist in graph.")
        self.edges_out[edge.source_id].append(edge)
        self.edges_in[edge.target_id].append(edge)

    def compute_reachability_cones(self, target_id: str) -> Tuple[Set[str], Set[str]]:
        """
        Computes the Upstream Ancestry Cone A_up and Downstream Blast Radius B_down.
        """
        if target_id not in self.nodes:
            raise KeyError(f"Target node '{target_id}' not found.")

        # 1. Upstream Ancestry Cone (traverse edges_in)
        ancestry: Set[str] = set()
        queue = [target_id]
        while queue:
            curr = queue.pop(0)
            for edge in self.edges_in.get(curr, []):
                parent = edge.source_id
                if parent not in ancestry:
                    ancestry.add(parent)
                    queue.append(parent)

        # 2. Downstream Blast Radius (traverse edges_out)
        blast_radius: Set[str] = set()
        queue = [target_id]
        while queue:
            curr = queue.pop(0)
            for edge in self.edges_out.get(curr, []):
                child = edge.target_id
                if child not in blast_radius:
                    blast_radius.add(child)
                    queue.append(child)

        return ancestry, blast_radius

    def compute_quality_propagation(self, path: List[str]) -> float:
        """
        Evaluates Theorem 13.5.1 along a causal sequence of entities and activities.
        path: [e_0, a_1, e_1, a_2, ..., e_L]
        """
        if not path or path[0] not in self.nodes:
            raise ValueError("Invalid path sequence.")

        curr_quality = self.nodes[path[0]].quality_score

        for i in range(1, len(path)):
            prev_node = path[i - 1]
            curr_node = path[i]

            # Find edge
            matching_edges = [
                e for e in self.edges_out.get(prev_node, []) if e.target_id == curr_node
            ]
            if not matching_edges:
                raise ValueError(f"No direct edge found between {prev_node} and {curr_node}")

            edge = matching_edges[0]
            # Q_out = eta * Q_in - xi
            curr_quality = max(0.0, edge.activity_fidelity * curr_quality - edge.noise_injection)

        return curr_quality

    def compute_merkle_lineage_hash(self, target_id: str) -> str:
        """
        Recursively calculates the cryptographic Merkle content digest H(v).
        H(v) = SHA256( Payload(v) || sort( (pred, H(parent)) ) )
        """
        if target_id not in self.nodes:
            raise KeyError(f"Node '{target_id}' not found.")

        visited: Dict[str, str] = {}

        def dfs(node_id: str) -> str:
            if node_id in visited:
                return visited[node_id]

            parent_hashes: List[str] = []
            for edge in self.edges_in.get(node_id, []):
                parent_id = edge.source_id
                h_parent = dfs(parent_id)
                parent_hashes.append(f"{edge.edge_type.value}:{h_parent}")

            parent_hashes.sort()
            node_payload = self.nodes[node_id].payload_hash
            block = node_payload + "|" + "|".join(parent_hashes)
            digest = hashlib.sha256(block.encode("utf-8")).hexdigest()
            visited[node_id] = digest
            return digest

        return dfs(target_id)

    def validate_temporal_consistency(self) -> Tuple[bool, List[str]]:
        """
        Enforces Definition 13.5.4 first-order logic temporal constraints:
        1. Generation-Usage: t_gen(e) <= t_start(a) for (a, used, e)
        2. Activity Lifetime: t_start(a) <= t_end(a)
        """
        violations: List[str] = []

        for node in self.nodes.values():
            if node.node_type == PROVNodeType.ACTIVITY:
                if node.t_start is not None and node.t_end is not None:
                    if node.t_start > node.t_end:
                        violations.append(
                            f"Activity '{node.node_id}' has negative lifetime: start ({node.t_start}) > end ({node.t_end})"
                        )

        for edges in self.edges_out.values():
            for e in edges:
                src = self.nodes[e.source_id]
                tgt = self.nodes[e.target_id]

                # (Activity used Entity): Entity must be generated before Activity starts
                if e.edge_type == PROVEdgeType.USED:
                    # src is Activity, tgt is Entity
                    if tgt.t_end is not None and src.t_start is not None:
                        if tgt.t_end > src.t_start:
                            violations.append(
                                f"Look-ahead violation: Activity '{src.node_id}' used entity '{tgt.node_id}' before generation! (t_gen={tgt.t_end} > t_start={src.t_start})"
                            )

        is_valid = len(violations) == 0
        return is_valid, violations

    def generate_blast_radius_report(self, corrupted_entity_id: str) -> BlastRadiusReport:
        ancestry, blast_radius = self.compute_reachability_cones(corrupted_entity_id)
        affected_models = [
            nid for nid in blast_radius
            if self.nodes[nid].node_type == PROVNodeType.ENTITY and "model" in nid.lower()
        ]

        return BlastRadiusReport(
            corrupted_entity_id=corrupted_entity_id,
            upstream_ancestry_size=len(ancestry),
            upstream_ancestry_nodes=sorted(list(ancestry)),
            blast_radius_size=len(blast_radius),
            blast_radius_nodes=sorted(list(blast_radius)),
            affected_models=affected_models,
            terminal_quality=self.nodes[corrupted_entity_id].quality_score,
        )

    Case Study 1: The Duke University Oncology Clinical Trial Retraction

    In 2006, researchers at Duke University led by Anil Potti published landmark papers in Nature Medicine and the New England Journal of Medicine, claiming that genomic microarray expression profiles could predict patient sensitivity to specific chemotherapy regimens with over 90% accuracy. Based on these findings, Duke launched three major clinical trials assigning cancer patients to toxic chemotherapy drugs.

    Forensic Findings & Provenance Failure (Baggerly & Coombes, 2009):

    1. Unversioned Ad-Hoc Scripts: The Duke laboratory maintained no Git version control, no data hashing, and no recorded pipeline logs. Spreadsheets were manually manipulated and passed between graduate students via email.
    2. The Off-By-One Shift: Baggerly and Coombes discovered that a simple copy-paste error shifted the microarray expression matrix down by one row relative to the patient outcome column. The algorithm was effectively learning noise, and in several drug panels, recommending therapies that were toxic to non-responders.
    3. The Provenance Invariant Solution: Under Definition 13.5.3 (Cryptographic Lineage Merkelization), every transformation script and raw shard produces a deterministic Merkle root. A single row permutation alters the cryptographic hash \(\mathcal{H}(v)\), halting automated CI/CD deployment before clinical trials can begin (Baggerly & Coombes, 2009; Stodden et al., 2016).

    Exercise 2: Detecting Causal Paradoxes in a W3C PROV-O Temporal Log

    An automated pipeline log records the following timestamps (seconds from midnight): - \(t_1 = 100\): Entity_RawSignals generated (\(t_{\text{gen}} = 100\)) - \(t_2 = 120\): Activity_Filtering starts (\(t_{\text{start}} = 120\)) - \(t_3 = 180\): Activity_Filtering ends (\(t_{\text{end}} = 180\)) - \(t_4 = 180\): Entity_FilteredSignals generated (\(t_{\text{gen}} = 180\)) - \(t_5 = 150\): Activity_TrainNeuralNet starts (\(t_{\text{start}} = 150\)) - \(t_6 = 300\): Activity_TrainNeuralNet ends (\(t_{\text{end}} = 300\)) - Edge: (Activity_TrainNeuralNet, used, Entity_FilteredSignals)

    1. Identify the formal temporal violation in this provenance log using Definition 13.5.4.
    2. In machine learning systems, what real-world modeling pathology does this violation correspond to?
    3. Calculate the terminal quality \(Q(e_2)\) of a 2-step pipeline where \(Q(e_0) = 0.95\), \(\eta_1 = 0.90\), \(\xi_1 = 0.02\), \(\eta_2 = 0.85\), and \(\xi_2 = 0.05\) using Theorem 13.5.1.
    Reveal Complete Step-by-Step Solution

    Step 1: Identifying the Formal Temporal Violation

    Under Definition 13.5.4 (Generation-Usage Ordering Constraint):

    \[\forall (a, \text{used}, e): t_{\text{gen}}(e) \le t_{\text{start}}(a)\]

    In the provided log: - Entity_FilteredSignals has generation timestamp \(t_{\text{gen}} = 180\). - Activity_TrainNeuralNet has start timestamp \(t_{\text{start}} = 150\). - Edge: (Activity_TrainNeuralNet, used, Entity_FilteredSignals).

    Evaluating the inequality:

    \[t_{\text{gen}}(\text{Entity\_FilteredSignals}) = 180 > 150 = t_{\text{start}}(\text{Activity\_TrainNeuralNet})\]

    The condition is violated because the training activity started 30 seconds before its input data was generated.

    Step 2: Real-World Modeling Pathology

    This temporal paradox represents Look-Ahead Bias and Data Leakage. In financial time-series forecasting or medical triage models, this occurs when an algorithm uses data from the future (e.g., closing market prices, or lab results obtained 24 hours post-admission) to train predictions on the past. Models exhibiting this bug appear to achieve 99% accuracy in offline testing, but fail completely when deployed in live real-time environments.

    Step 3: Calculating Terminal Quality \(Q(e_2)\) under Theorem 13.5.1

    Given parameters: - \(Q(e_0) = 0.95\) - Step 1: \(\eta_1 = 0.90, \; \xi_1 = 0.02\) - Step 2: \(\eta_2 = 0.85, \; \xi_2 = 0.05\)

    Applying Theorem 13.5.1 for depth \(L = 2\):

    \[Q(e_1) = \eta_1 Q(e_0) - \xi_1 = (0.90 \times 0.95) - 0.02 = 0.855 - 0.02 = 0.835\]
    \[Q(e_2) = \eta_2 Q(e_1) - \xi_2 = (0.85 \times 0.835) - 0.05 = 0.70975 - 0.05 = 0.65975 \approx 0.660\]

    Alternatively, using the direct formula from Theorem 13.5.1:

    \[Q(e_2) = Q(e_0) (\eta_1 \eta_2) - \left[ \xi_1 \eta_2 + \xi_2 \right]\]
    \[Q(e_2) = 0.95 \times (0.90 \times 0.85) - \left[ 0.02 \times 0.85 + 0.05 \right]\]
    \[Q(e_2) = 0.95 \times 0.765 - [0.017 + 0.05] = 0.72675 - 0.067 = 0.65975 \approx 0.660\]

    The two-step pipeline degrades input quality from \(0.950\) to \(0.660\)—a 30.5% loss in data fidelity.
